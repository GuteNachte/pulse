# 资产参数整理作业手册

> 来源：2026-10-17 ~ 2026-10-18 第一个资产（UM690）参数整理全过程复盘。
> 用途：整理第二个及后续资产时直接照此执行；也可作为参数系统继续迭代时的设计检查表。
> 配套：字段目录见 `internal/assetcatalog/asset-parameter-registry.json`，计算设备方案见 `docs/pc-asset-design.md`。

## 一、目标与完成标准

一次资产参数整理，做到以下五条才算完成（来自本轮用户反复纠正后提炼的“五性”）：

1. **完整性**：用户提供的参数一条不漏；识别、分类、写入、展示四段都不能丢。
2. **可见性**：写入了什么、写到了哪里，保存前在弹窗里就能看见，不靠一句提示。
3. **一致性**：同类信息同一形态；所有参数都能排序；中文标签统一，不出现英文键。
4. **可逆性**：删除、隐藏、重开、保存后行为一致；历史数据不因界面调整被静默破坏。
5. **整洁性**：分组顺序、整行/配对、表格列宽与表头分组整齐，无重复信息。

## 二、单个资产的整理顺序

1. **先对齐基本信息**：品牌、型号、产品定位、上市日期、官网。型号内的内部型号用括号写入（如 `UM690（Venus 系列）`），不单列。
2. **按组推进，一次一组**：物理规格 → 处理器(CPU) → 图形核心 → 内存 → 存储支持 → 网络连接 → 显示输出 → 接口与扩展 → 电源与功耗 → 散热设计 → 系统与软件。
3. **让用户给真实参数文本**：以官网/电商/说明书原文为准，不凭印象补参数；用户贴一组就整理一组。
4. **先定数据口径，再调界面**：分清“规范参数（支持什么）”和“实际安装（这台机器装了什么）”，再决定格子与表格怎么分工。
5. **粘贴写入 + 手工兜底**：优先用组弹窗粘贴自动写入；无法识别的按自定义参数留在当前组，绝不丢；特殊值手工补。
6. **保存后回展示页逐条核对**：值、顺序、空组入口、表格行数、整行/配对全部看一遍。
7. **收尾三件事**：追加 `docs/release-notes-next.md`、同步设置页“关于”版本记录、提交（不推送）。

## 三、粘贴识别的固定规则

- 输入格式固定为**一行一个参数**：`参数名 + Tab + 值`。本地确定性解析优先，不依赖 AI 抽行；其他格式才回退 AI 提取。
- 提取与分类两段 AI 各自动重试一次，失败不要求用户再点一次。
- 分类结果必须对照提取清单**补回漏条**（补回项进未识别，再由组弹窗写为自定义参数）。
- **同一字段的多条参数**：后续条目名称与字段标签不同 → 保留为该组自定义参数；同名重复才丢弃。
- **组弹窗里粘贴的内容全部写入当前组**：能对上本组预设字段的落字段；其他分组的预设字段按归属写入并在弹窗内以只读行展示（字段中文名 + 值 + 归属分组）；其余全部进本组自定义参数。
- 预设字段不再以自定义行出现；自定义行恢复时优先中文标签，只有真正的自定义参数才显示键名。
- 数字字段统一归一化：`3.3 GHz → 3.3`、`最高 4.9GHz → 4.9`、`1,024 GB → 1024`；解析不出数字时保留原文，不写丢。

## 四、展示设计规范

- 计算设备固定 **11 类**常驻显示：物理规格 / 处理器(CPU) / 图形核心(GPU/核显) / 内存 / 存储支持 / 网络连接 / 显示输出 / 接口与扩展 / 电源与功耗 / 散热设计 / 系统与软件。空组保留“暂无参数 + 编辑”入口。
- **物理规格置顶整行**；内存、存储、网络三张表相邻且整行；其余短分组两两配对（处理器+图形核心、显示输出+接口与扩展、电源与功耗+散热设计），最后“系统与软件”整行，保证无落单。
- 内存/存储/网络三组同构：**规范参数单独铺格子，表格只放实际安装**。
  - 内存格子：插槽数 / 支持内存类型 / 支持频率 / 内存条形态 / 最大容量 / 通道数 / 是否可扩展 / ECC。
  - 存储格子：插槽数 / 硬盘类型支持 / 接口 / 协议版本 / 每槽最大容量。
  - 网络格子：有线网卡芯片 / 有线速率 / Wi-Fi 协议 / Wi-Fi 模块 / Wi-Fi 速率 / 蓝牙；表格列 = 接口 | 接口类型 | 连接的设备。
- 表格行数由插槽数/盘位数决定；行首状态点保留；网络表格保留“网口属性｜实际接入”分组表头。
- 组内不再显示小分类标题（自定义参数、接口规格等），内容直接平铺；表格内的分组表头保留。

## 五、编辑弹窗规范

- 非表格组：单列布局，粘贴框 → 参数行列表 → “添加参数”；行左侧拖拽手柄排序。
- 表格组：上方规范参数编辑区 + 插槽数/盘位数控制器 + 可拖拽表格；表格下方显示自定义参数行与“添加参数”。
- 所有排序（非表格行、表格行）都支持**拖拽**，顺序分别持久化到 `_param_order`、`_table_row_order`（按组），展示页同步。
- 预设字段可删除并持久隐藏（`_hidden_params`）；自定义参数删除时同步清值与 `_group_params` 登记。
- 其他分组字段保存时直接写入对应字段，本组只保留只读预览行，不生成自定义行。
- 中文优先：字段标签一律走 registry 中文名；提示语、表头、占位符不得暴露英文键。

## 六、数据与保留规则

- registry 是字段与分类的单一事实源，前端直接 import、Go 侧 `go:embed`；改动后必须 `run-hub-dev.ps1 -Restart` 才会生效。
- 预设字段优先于自定义参数；保留键（下划线开头的结构键、网络表格结构键等）不允许被自定义参数占用。
- 界面下线功能时**不删历史数据**：字段值留在 metadata，只是不再展示；需要彻底清理时单独做数据清洗并先备份。
- 历史自定义行恢复时，能对上 registry 字段的按中文标签显示，不把预设字段登记进 `_group_params`。

## 七、验证清单

前端：

```powershell
cd internal/site
npm run typecheck
npm test
```

Go：

```powershell
go build ./...
go vet -tags testing ./internal/...
go test -count=1 ./internal/assetcatalog/

```

本地环境：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "supplemental/scripts/run-hub-dev.ps1" -Restart
```

浏览器实查至少覆盖：

- 分组数量与顺序、空组入口、整行/配对；
- 三张表的规范格子与安装行、表头分组线；
- 组弹窗粘贴 N 行 → 保存 → 展示页 N 条齐全（不是只看提示）；
- 拖拽非表格行与表格行 → 保存 → 重开顺序一致；
- 带单位数字、中文标签、其他分组字段只读行；
- 删除某组全部参数后空组仍显示。

## 八、本轮踩坑与根因（下次直接规避）

| 现象 | 根因 | 规避方式 |
| --- | --- | --- |
| 改了 registry 但界面没变 | registry 被 go:embed，Hub 没重建 | 一律 `-Restart`，不要只跑脚本 |
| 粘贴五行只识别四行 | 免费档模型提取漏行 + 分类漏条 + 同字段去重 | 本地解析固定格式 + 补回漏条 + 同字段多条保留 |
| 提示已写入但弹窗看不到 | 其他分组字段直接写库，本组无展示 | 保存前渲染只读预览行并标注归属分组 |
| 自定义行显示英文键 | 预设字段被误当自定义参数 | 预设字段直接写字段；恢复时优先中文标签 |
| 主频/睿频保存丢失 | number 字段 `Number("3.3 GHz")` 得 NaN | 保存前统一数值归一化 |
| 删除后重开又出现 | 只删了表单行，没清 metadata 与 `_group_params` | 删除时同步清值、清登记、记 `_hidden_params` |
| 分组排版有落单 | 分类数量变化后配对关系没重算 | 分类增删后同时调整 fullRow 与配对 |
| 大段改 TSX/Go 后文件结构损坏 | 脚本切段、引号转义、Edit 锚点不唯一 | JSX/Go 结构改动只用 Read + Edit 整段替换；脚本只做锚点明确的小替换 |
| tsc 报大量 unknown / never | 联合类型收窄后推导失效 | 给行/描述符补显式类型（RowEntry、TableRowDescriptor） |

## 九、协作节奏（对非技术用户）

- 一次只推进一个组或一个问题；每步说清“现在做什么、为什么、怎么算成功”。
- 用户给出真实参数文本后，先复述口径（哪些是规范参数、哪些是实际安装），再动手。
- 用户说“不要我一个一个说”时，要横向扫全部同类路径，而不是修好当前例子。
- 用户指出显示问题时，先修数据源与真实状态，不在 UI 上遮盖。
- 每个阶段结束，用一页以内说明：完成了什么、改了哪里、怎么验证、下次可复用什么。
