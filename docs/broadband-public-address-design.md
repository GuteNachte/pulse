# 宽带动态公网地址设计

> 适用范围：仅 `type = internet` 的宽带资产。其他资产不显示该卡片，也不调用检测接口。

## 目标

- 自动或手动获取当前宽带出口的公网 IPv4 / IPv6。
- 检测失败时说明真实原因；保留上次成功结果并明确标注，不把旧值伪装成最新值。
- 检测端点可替换、可回退，避免单一服务不可用导致长期「尚未获取」。

## 数据（asset.metadata）

- `public_ip_mode`：`auto`（自动检测，缺省）或 `manual`（手动填写）。
- `public_ipv4` / `public_ipv6`：最近一次成功获取或手动维护的地址。
- `public_ipv4_error` / `public_ipv6_error`：最近一次检测失败原因。
- `public_ip_checked_at` / `public_ip_next_check_at`：上次检测时间与下次自动检测时间。
- `public_ip_auto_refresh`（`yes` / `no`）与 `public_ip_refresh_interval_minutes`：自动更新开关与间隔。
- 以上键属于宽带严格模板放行范围；写入失败时保留现场结果，不静默丢弃。

## 检测链路

- IPv4 端点顺序：`ipv4.icanhazip.com` → `checkip.amazonaws.com` → `api4.ipify.org`。
- IPv6 端点顺序：`api6.ipify.org` → `ipv6.icanhazip.com`。
- 环境变量 `PULSE_PUBLIC_IPV4_DETECTOR_URL` / `PULSE_PUBLIC_IPV6_DETECTOR_URL` 可覆盖首选端点，内置端点继续作为回退。
- IPv4 与 IPv6 并行检测；每个端点 4 秒超时；同一协议按顺序回退，任一端点返回合法地址即停止。
- 返回地址必须与协议匹配，并拒绝私网、回环、未指定、链路本地、组播地址。
- 全部端点失败时记录最后一个错误；不清空上次成功地址。

## 模式

- **自动检测（auto，缺省）**：使用下方多端点链路自动获取地址；可配置自动更新开关和间隔，也可立即刷新。
- **手动填写（manual）**：用户在设置弹窗直接填写公网 IPv4 / IPv6；保存时校验为公网单播地址并记录维护时间。
  - 强制关闭自动更新，后台刷新跳过该资产，刷新接口拒绝执行自动检测。
  - 适合 Hub 无法直接探测的线路，例如科技网这类独立线路。
- 每条宽带独立设置模式，互不影响；旧数据没有 `public_ip_mode` 时按 auto 处理。

## 刷新策略

- 手动刷新：详情页「刷新公网地址」按钮，结果用 toast 区分成功、部分成功和失败，并附失败原因。
- 自动刷新：默认开启，可选 15 分钟、30 分钟、1 小时、6 小时、12 小时、24 小时；后台每 15 分钟检查到期资产，只处理 `active` 宽带。
- 每次刷新写 `public_ip_checked_at` 与 `public_ip_next_check_at`；地址变化写入资产变更审计。

## 展示

- 自动模式：宽带右侧「动态公网地址」卡，显示自动更新开关与间隔、刷新按钮、当前公网 IPv4 / IPv6、检测状态、上次更新时间、下次更新时间。
- 手动模式：卡片标题为「公网地址」，显示当前 IPv4 / IPv6、维护方式「手动填写」、上次维护时间、「手动模式，不自动更新」，不显示自动更新控件和刷新按钮。
- 检测失败但保留旧地址：地址照常显示，并增加「检测状态」行，例如「IPv4：检测服务不可达（保留上次结果）」。
- 无地址且无错误：显示「尚未获取」。
- 空值不显示、空分组查看态隐藏的通用规则不变；该卡本身在宽带查看态固定展示。

## 权限与安全

- 只允许管理员或具备资产写权限的账号手动刷新与修改设置；只读账号不可操作。
- 检测接口只接受 `type = internet` 资产；其他类型直接拒绝。
- 检测仅向公网地址服务发起普通 HTTPS GET，不发送资产名称、位置、账号等资料；端点可配置。
- CGNAT / 共享公网 IPv4 的专门标注留待后续；当前显示检测服务实际看到的出口地址。
