# Pulse 家庭资产管理与监控方案

## 核心宗旨

Pulse 的项目定位是家庭资产管理与监控。核心目标不是单纯做监控，而是让用户完全掌握自己家里和个人环境里的所有数码硬件资产。

- 所有电子设备都应该能在 Pulse 里被看见、被分类、被检索、被关联。
- 能自动采集的设备，通过 Agent、SNMP、接口或后续插件采集真实状态。
- 不能自动检测状态的设备，通过资产中心手动维护长期稳定信息。
- 页面默认不伪造监控状态，不用占位数据假装已采集。
- 资产中心是所有硬件信息的主数据源，客户端监控、网络拓扑、网站监控、告警和后续智能家居模块都从资产中心选择对象。

## 产品定位升级

Pulse 后续统一按“家庭资产管理与监控平台”设计和表述。

第一层目标是资产清楚：

- 家里有哪些设备。
- 每个设备是什么类型。
- 每个设备在哪里。
- 每个设备的品牌、型号、序列号、IP、MAC、管理地址、保修、用途是什么。
- 哪些设备已监控，哪些只是手动资产。

第二层目标是状态清楚：

- 在线 / 离线。
- 资源占用。
- 磁盘、网卡、GPU、温度、电池等硬件状态。
- 服务、容器、网站、虚拟机等运行状态。
- 手动资产的维护状态、保修状态、位置和归属。

第三层目标是关系清楚：

- 哪些设备接在哪个路由器、交换机、AP 或宽带入口下。
- 哪台物理机承载哪些虚拟机、容器和网页服务。
- 哪些监控项、告警、通知规则和资产有关。
- 哪些设备属于同一个房间、用途、网络、服务链路或智能家居场景。

第四层目标是操作清楚：

- 能操作的设备提供受控操作。
- 不能操作的设备只展示信息和维护记录。
- 所有操作有审计、有确认、有风险边界。

## 模块边界

### 基础底座

继续保持不可关闭：

- PocketBase 基座。
- Pulse 内核。
- 用户、权限、初始化、模块管理、日志审计。
- 全局设置和关于页。

### 资产中心

资产中心是核心基座，不能关闭。它负责：

- 资产主档。
- 硬件参数。
- 固定 IP / IPv6 / MAC。
- 管理地址。
- 资产接口。
- 资产关系。
- 位置主数据。
- 资产生命周期。
- 手动维护状态。
- 被其他模块引用的统一对象来源。

资产中心不是监控页，不能承担实时指标展示的主要职责。

### 客户端监控

客户端监控只负责“已安装 Agent 或能被 Agent 采集的资产”：

- Windows 主机。
- Linux / NAS / 飞牛 / Unraid 容器 Agent。
- 后续 macOS Agent。
- 宿主机、虚拟机、容器、服务、软件、SMART、GPU 等真实采集数据。

客户端监控新增对象时，必须优先从资产中心选择资产，再安装 Agent 或绑定采集数据。

### 网络拓扑

网络拓扑负责“资产之间的网络关系”：

- 宽带入口。
- 光猫。
- 路由器。
- 交换机。
- AP。
- 有线设备。
- 无线设备。
- 虚拟关系和服务关系的可视化。

拓扑节点来自资产中心。没有资产时拓扑为空。互联网、宽带、路由器、交换机和 AP 都作为资产添加。

### 网站监控

网站监控负责“URL / 服务端点状态”：

- 内网服务。
- 外网服务。
- 管理后台。
- 自定义网页监控。

网页端点也应作为资产中心里的 `web_endpoint` 资产维护，网站监控从资产中心选择要监控的端点。

### 智能家居模块

智能家居可以作为后续大模块，不应混进客户端监控。它负责：

- Home Assistant 接入。
- 米家 / Matter / Zigbee / 蓝牙网关等后续适配。
- 灯、开关、传感器、空调、插座、门锁、摄像头等设备状态。
- 家居设备和实体硬件资产的绑定。

第一版先支持资产中心手动建档，并通过 `/smarthome` 做只读总览；暂不自动发现，也不急着做实时控制。

## 资产分类体系

### 网络与出口

- 互联网接入：宽带线路、运营商、上下行、接入方式、公网地址、入户位置。
- 光猫 / ONT：运营商设备、桥接状态、管理 IP、MAC、位置。
- 路由器 / 网关：管理 IP、LAN 网段、DHCP、DNS、Wi-Fi、端口、固件。
- 交换机：端口数、端口速率、PoE、管理 IP、VLAN 备注。
- 无线 AP：Wi-Fi 标准、SSID、频段、回程方式、位置。
- 防火墙：策略网关、安全设备、管理口。

### 主机与计算

- 物理主机：Windows、Linux、工作站、游戏主机、办公主机。
- NAS：飞牛、Unraid、群晖、TrueNAS。
- 服务器：长期运行的物理服务器。
- 迷你主机：NUC、小主机、软路由主机。
- 虚拟机：宿主机、平台、vCPU、内存、磁盘、固定 IP。
- 容器宿主：由 Agent 自动采集容器和 Compose，但资产归属仍在资产中心。

### 存储与外设

- 硬盘 / SSD：可先通过 SMART 自动归属到主机，后续可提升为独立资产。
- UPS：手动资产优先，后续可做 NUT / SNMP 接入。
- 打印机 / 扫描仪：固定 IP、MAC、耗材、位置。
- 摄像头 / NVR：IP、MAC、协议、位置、供电方式。

### 移动与个人设备

- 手机。
- 平板。
- 笔记本。
- 手表。
- 游戏掌机。
- 电子阅读器。
- 蓝牙 / Wi-Fi 外设。

这类设备第一版以手动资产为主，后续能采集再接入。

### 智能家居

- 灯。
- 开关。
- 插座。
- 传感器。
- 空调。
- 门锁。
- 窗帘。
- 网关。
- 扫地机器人。
- 音箱。

智能家居资产要保留房间、协议、网关、供电、电池、厂商和自动化备注。

### 服务与网页端点

- 内网网页服务。
- 外网网页服务。
- 管理后台。
- API 端点。
- 需要监控的自建服务入口。

服务端点可以绑定到宿主资产，也可以独立存在。

## 数据模型升级

### 资产主表

资产主表继续保存长期稳定信息：

- 名称。
- 类型。
- 状态。
- 厂商。
- 型号。
- 序列号。
- 厂家官网支持页 / 驱动下载页 / 保修支持页；优先填写能直接定位到该型号的支持页面，而不是厂家首页。
- 资产编号。
- 位置。
- 角色 / 用途。
- 管理 IP。
- 备注。
- metadata 类型专属字段。

主机、NAS、服务器和迷你主机还要预留更细的硬件主档字段：

- CPU 厂商 / 型号。
- 主板品牌 / 型号。
- BIOS 厂商 / 版本 / 日期。
- 显卡芯片厂商 / 型号、板卡品牌、显存。
- 内存品牌 / 型号 / 类型 / 频率 / 插槽摘要。
- 硬盘品牌 / 型号 / 介质 / 序列号摘要。
- 有线网卡品牌 / 型号、无线网卡品牌 / 型号。
- 机箱品牌 / 型号、电源品牌 / 型号 / 功率。
- CPU、主板、显卡、内存、存储、有线网卡、无线网卡、机箱和电源的官网支持 / 驱动 / 固件 / 保修页面。
- DMI、PCI、USB、SMART 等专项识别依据摘要，用于后续专用 Agent 做硬件匹配和资料补齐。
- 专项识别匹配备注，用于记录已确认的匹配来源、置信度判断和不能自动覆盖资产主档的原因。

这些字段不要求第一阶段全部手动填满。它们属于长期硬件主档，当前可手动补充；后续通过专项硬件识别 Agent 或外部硬件资料库补齐时，也只能作为“采集建议 / 匹配建议”进入差异提示，不能静默覆盖资产主档。

### 资产接口

资产接口保存可被拓扑复用的连接点：

- WAN。
- LAN。
- Ethernet。
- Wi-Fi。
- Management。
- Virtual。
- Custom。

字段包括：

- 接口名。
- MAC。
- IPv4。
- IPv6。
- 速率。
- 是否连接。
- 是否主接口。
- 来源：manual / agent / snmp / import。

### 资产关系

资产关系保存长期稳定关系：

- connected_to：网络连接。
- hosted_on：虚拟机 / 容器 / 服务运行在某宿主上。
- monitors：监控对象关系。
- depends_on：服务依赖。
- owns：归属关系。
- located_in：后续房间 / 区域关系可扩展。
- powered_by：后续 UPS / PoE / 插座关系可扩展。

### 位置主数据

位置主数据保存长期稳定的家庭空间和硬件摆放点：

- 房间。
- 区域。
- 机架。
- 柜体。
- 桌面。
- 网络 / 家居分区。

资产档案里的 `location` 仍保留为可读文本，方便快速录入和兼容旧数据；常用位置应进入 `asset_locations`，资产表单优先复用位置主数据，清单用“待归档”提示尚未规范化的位置文本。

### 采集结果

采集结果不能覆盖资产主档，只能作为实时状态层叠加：

- Agent 采集结果。
- SMART。
- GPU。
- 网络接口实时状态。
- 容器。
- 服务。
- 网站检测。
- 后续 SNMP / Home Assistant 状态。

### 补全报告

资产中心补全采用“极简建档 -> 采集 / 联网识别报告 -> 人工确认写回”的主数据流程。

- 创建资产时优先填写资产类型、名称、建档 IP / 接入 IP、详细型号线索、位置和备注。
- 建档 IP 用于 Agent 接入、局域网可达性和后续 SNMP / Home Assistant 等采集入口。
- 详细型号用于联网资料匹配，但不能直接覆盖资产主档。
- 本地采集、联网匹配和后续 AI / 专项识别结果都进入 `asset_enrichment_reports` 和 `asset_enrichment_suggestions`。
- 联网资料补全和本地采集是并行来源：没有本地采集时也要尝试联网搜索；能本地采集时仍要联网搜索，并把两边结果同时保留为候选。
- 当本地采集值、联网匹配值和手动主档不一致时，报告只标记冲突和来源证据，不自动判断谁覆盖谁。
- 报告长期留档，字段级建议必须人工确认后才能写入 `assets`、`asset_interfaces` 或其他允许写回的资产子档案。
- 确认写回前必须重新校验资产归属、字段白名单、当前值是否变化、重复 IP / MAC 和主数据约束。
- 网站监控、客户端监控、网络拓扑、智能家居和告警只消费确认后的资产主档，不直接写主档。

补全策略分两类：

- 固定规格型号匹配：手机、平板、路由器、交换机、AP、打印机、UPS、游戏设备、智能家居等通常由厂商详细型号决定主要规格，后续优先通过型号联网匹配厂商、支持页、规格、固件和保修资料。
- 分阶段硬件识别：物理主机、NAS、服务器、迷你主机和虚拟机内部硬件可能被替换或自定义，详细型号只作为整机、机箱或平台线索；CPU、主板、BIOS、内存、网卡、硬盘、显卡等内部硬件以 Agent、DMI、PCI、USB、SMART、WMI、sysfs 和后续专项识别报告为准。

## 页面规划

### 首页

首页目标是一眼掌握家庭数字资产状态：

- 总资产数。
- 已监控资产数。
- 手动资产数。
- 异常资产数。
- 近期离线。
- 需要维护。
- 保修即将到期。
- 拓扑只读小图。
- 关键设备状态。

首页不要堆表格，使用摘要、状态分布、重点问题和拓扑概览。首页里的资产数量、资料缺口、保修关注和位置归档提示必须从资产中心主数据计算，不在首页维护第二套资产状态；这些关注项要能直接跳到资产中心对应筛选结果，形成“发现问题 -> 进入资产中心处理”的闭环。

### 资产中心

资产中心目标是完整盘点：

- 类型选择添加。
- 类型专属字段。
- 搜索。
- 按类型、房间、状态、监控状态筛选。
- 批量编辑。
- 资产详情页。
- 资产关系页。
- 生命周期和维护记录。
- 附件 / 图片 / 发票 / 保修凭证 / 说明书 / 配置备份。

资产详情页要分层：

- 基础档案。
- 资料来源边界：区分手动主档、接入必填、Agent 可采集、专项识别可补。
- 网络接口。
- 硬件规格。
- 关系。
- 监控绑定。
- 维护记录。
- 资产附件。
- 变更历史。

### 客户端监控

客户端监控页改为只显示已接入或待接入 Agent 的资产：

- 从资产中心选择资产安装 Agent。
- 安装后绑定到同一个资产。
- 机器详情展示实时采集。
- 如果 Agent 采集到的信息和资产主档不同，要提示“采集值”和“资产档案值”的差异，不自动覆盖。

### 网络拓扑

网络拓扑完整页负责编辑：

- 从资产中心添加节点。
- 手动连接资产接口。
- 节点布局。
- 节点详情。
- 有线 / 无线 / 宽带 / 虚拟关系不同视觉。
- 链路状态叠加 Agent 或后续 SNMP 数据。

首页拓扑只读，不编辑。

### 智能家居

后续新增 `/smarthome`：

- 房间视图。
- 设备类型视图。
- 网关视图。
- 状态视图。
- 资产详情绑定。

第一阶段先不要自动发现，先支持资产中心手动建档和只读总览；网关归属优先使用资产关系，只有没有真实关系时才使用资产档案里的网关文本备注。

## 采集策略

### 现有 Agent

继续采集：

- CPU、内存、磁盘、网络。
- Docker / Podman。
- SMART。
- GPU。
- Windows 服务。
- 手动软件。
- 虚拟机清单。

采集结果只绑定到资产，不替代资产。

### 后续专项硬件识别 Agent

适合补齐基础 Agent 不稳定或采不到的硬件档案信息：

- CPU 厂商、CPU 型号。
- 主板厂商、主板型号、BIOS 厂商、BIOS / 固件版本和发布日期。
- 内存条厂商、颗粒 / 频率 / 插槽信息。
- 硬盘具体品牌、型号、序列和介质信息。
- 网卡芯片厂商、型号、无线 / 有线能力。
- 显卡板卡品牌、芯片型号和驱动信息。
- 根据硬件 ID、DMI、PCI、USB、SMART、WMI 或 Linux sysfs 数据匹配厂家官网支持页 / 驱动下载页 / 保修支持页。

专项识别 Agent 的结果不能直接改资产主档。正确流程是：采集 -> 标准化 -> 匹配置信度 -> 展示建议 -> 用户确认写入。

资料来源边界必须在资产详情页可见。手动主档和接入必填字段以用户录入为准；Agent 可采集字段只能形成采集建议；专项识别可补字段只能形成匹配建议，特别是厂家支持页、驱动页、保修页和精确硬件型号，不允许后台静默写回。

### 后续 SNMP

适合：

- 交换机端口状态。
- 交换机端口流量。
- 路由器接口流量。
- UPS 状态。
- 打印机状态。

SNMP 应作为独立采集能力，不强依赖第一阶段。

### 后续 Home Assistant

适合：

- 智能家居状态。
- 房间。
- 电池。
- 传感器。
- 开关。
- 灯具。

Pulse 不需要替代 Home Assistant，应该作为资产总览和关键状态展示层。

### 后续导入

支持 CSV / JSON 导入资产：

- 大量手动设备。
- IP / MAC 清单。
- 保修清单。
- 智能家居清单。

导入必须可预览、可回滚、可去重。

## UI/UX 原则

- 克制、清晰、专业，不做花哨装饰。
- 资产卡片固定尺寸，关键文字有限展示。
- 详细信息进详情页或 hover / 弹窗。
- 状态用颜色、图标和短标签表达。
- 真实状态和手动档案必须视觉区分。
- 不显示没有意义的占位字段。
- 不把未采集信息显示成异常。
- 桌面端重点是信息密度和检索效率。
- 移动端重点是只读查看和快速确认。

## 实施路线

### 阶段 1：资产中心主数据成型

目标：先让所有设备都能被录入。

- 完善资产类型体系。
- 完善类型专属字段。
- 新增资产详情页。
- 新增资产接口管理。
- 新增资产关系管理。
- 新增房间 / 位置字段规范，使用 `asset_locations` 维护房间、区域、机柜、桌面和分区等主数据，同时兼容资产档案里的手动位置文本。
- 新增监控绑定状态。
- 新增手动维护状态。

验收：

- 可以录入宽带、路由器、交换机、AP、主机、NAS、Unraid、手机、平板、摄像头、打印机、IoT、网页服务。
- 每类资产都有合理字段。
- 没有监控的资产也能清楚展示。

### 阶段 2：监控模块全部改为从资产中心选择

目标：资产是源头，监控是能力。

- 添加 Agent 前必须可选择资产。
- 网站监控从 `web_endpoint` 或资产详情里创建。
- 网络拓扑从资产选择节点。
- 告警规则绑定资产。
- 通知内容带资产信息。

验收：

- 不再出现“监控里有机器，但资产中心不知道”的情况。
- 不再出现“网站监控和资产没有关系”的情况。

### 阶段 3：资产详情页做成硬件总档案

目标：一台设备的所有信息集中可见。

- 基础档案。
- 网络接口。
- 监控状态。
- 硬件采集。
- 容器 / 服务 / 网站归属。
- 拓扑关系。
- 告警历史。
- 维护记录。

验收：

- 打开任意资产详情，可以知道它是什么、在哪里、怎么连、有没有监控、当前状态如何。

### 阶段 4：家庭网络拓扑完善

目标：所有网络关系清楚。

- 手动连线更顺手。
- 资产接口自动带入 IP / MAC / 速率。
- 支持宽带多入口。
- 支持无线连接。
- 支持虚拟关系和服务承载关系。
- 后续预留 SNMP 端口流量。

验收：

- 家庭网络能完整画出来。
- 宽带、路由器、交换机、AP、主机、NAS、无线设备关系明确。

### 阶段 5：维护和生命周期

目标：不仅能看，还能管理。

- 保修到期提醒。
- 购买日期。
- 维护记录。
- 配件 / 硬盘更换记录。
- 设备退役。
- 资产变更历史。

验收：

- 可以知道设备什么时候买的、什么时候上线、什么时候换过硬件、是否该维护。

### 阶段 6：智能家居资产接入

目标：把智能家居纳入统一资产视图。

- 先手动资产类型。
- 再接 Home Assistant。
- 再按房间、设备类型和状态展示。
- 智能家居设备和网络资产、网关资产建立关系。

验收：

- 灯、插座、传感器、空调、门锁、扫地机器人等能纳入 Pulse 资产视图。

## 优先级建议

近期最合理顺序：

1. 资产详情页。
2. 资产接口管理。
3. 资产关系管理。
4. 客户端监控从资产选择。
5. 网络拓扑从资产详情和接口复用数据。
6. 网站监控绑定网页端点资产。
7. 维护记录和保修提醒。
8. 智能家居手动资产类型。
9. SNMP / Home Assistant 自动采集。

## 不做或暂缓

暂缓自动发现：

- 自动发现会引入误识别、权限、扫描、重复资产和维护成本。
- 当前家庭设备不多，手动建档更准确。

暂缓机器到机器真实流量：

- 没有 NetFlow / sFlow / IPFIX 或连接级 Agent 数据前，不声明真实机器间流量。

暂缓完整智能家居控制：

- Pulse 先做资产和状态总览，不急着替代 Home Assistant 做自动化控制。

暂缓复杂 CMDB：

- 不做企业级审批、采购、库存、成本核算。
- 重点是家庭和个人数码资产掌控。

## 后续判断标准

后续每加一个功能，先问：

- 它属于资产主数据，还是采集状态？
- 它能不能绑定到资产？
- 它关闭后是否影响其他模块？
- 它是否需要单独大模块？
- 它是否让“所有电子设备一目了然”更接近？
- 它有没有伪造不可采集的数据？
