# Windows 安装器替换后失败恢复设计

状态：设计与隔离验证准备中。用户已同意本阶段设计和隔离验证；未授权真实覆盖、回退或卸载测试。

## 范围

仅针对原安装目录中的双程序覆盖升级，恢复 pulse-agent.exe 和 agent-config.exe。首次安装、安装位置迁移、配置格式迁移、断电和安装器被强制结束不纳入本阶段自动恢复承诺。连接凭据和监控数据不随程序回退。

## 已核对依据

2026-09-06 核对 Inno 官方文档：

 - https://jrsoftware.org/ishelp/topic_installorder.htm
 - https://jrsoftware.org/ishelp/topic_scriptevents.htm

安装顺序为文件、快捷方式、注册表、卸载登记与卸载文件保存，然后执行 Run。卸载文件保存完成后不能取消，后续错误不会自动撤销已安装内容。DeinitializeSetup 在退出前调用，包括未开始安装即退出的情况。

这两页没有完整保证每种失败下内部清理与自定义文件恢复的先后关系；不能仅凭退出回调就认定恢复时机安全。必须使用无服务、无真实配置的独立安装试验确认。当前网页更新脚本仅处理单个 Agent 程序，不能直接作为双程序安装器回退实现。

## 分阶段处理

1. 准备阶段：核对安装目录、服务程序路径与现有安装登记相符。旧程序缺失、路径指向其他位置、重解析点或并发更新时拒绝覆盖，不推断为可回退安装。
2. 备份阶段：停止服务并确认状态后，将两份旧程序复制到所选根目录 data/rollback 下的唯一事务目录。记录大小与 SHA-256，并再次核对源文件；任一备份失败就禁止替换。重试不能用部分新程序覆盖原备份。
3. 替换阶段：记录事务阶段；出现失败先让安装器完成自身清理。必须先证明清理顺序，再决定恢复回调位置，不与 Inno 同时写同一目标。
4. 恢复阶段：确认服务已停止，核对备份和目标路径，恢复两份程序，再逐份校验。只有全部一致且原服务原本运行，才请求启动并复用真实运行状态检查。原服务原本停止则保持停止。
5. 登记完成后的失败：单独处理服务设置、卸载登记、卸载文件和快捷方式的一致性。未验证这些状态前，不把仅恢复两个程序称为完整回退，不自动启用这条回退路径。
6. 任一恢复步骤失败：保留事务目录和日志，返回失败，不启动混合版本、不循环重试、不自动删除最后一份有效备份。

## 备份与安全

备份目录只能由系统和管理员写入，防止恢复时将被篡改程序作为服务启动。目录与所有父路径必须检查重解析点和实际归属，路径检查不只做字符串前缀匹配。备份清单不保存令牌、配对码或配置内容。空间检查包含新程序、旧程序与临时文件；空间不足在替换前拒绝。

第一版保留失败事务，不自动清理；成功事务的保留和清理策略需在实现前明确，禁止无限堆积，也禁止删除唯一有效恢复点。服务自动恢复、网页更新和安装器之间的互斥必须纳入验证。

## 隔离验证计划

先使用独立 AppId、普通用户权限、项目 build 下的唯一测试目录，以及两个无执行能力的文本文件模拟新旧程序；不注册或操作服务，不访问 D:\Pulse Agent，不运行项目卸载逻辑。测试只能修改自身创建的文件。

第一组验证 Inno 生命周期：第一文件替换后失败、第二文件替换后失败、登记完成后的失败。记录事件顺序及退出前后文件哈希，保留日志与目录；不将模拟实验当真实升级验收。

第二组验证共用恢复逻辑：完整备份、第二份备份失败、备份损坏、部分替换、第二份恢复失败、重复恢复、原服务停止、路径不合法。检查失败时禁止启动和备份保留。

第三组核对登记一致性：独立测试 AppId 的旧版与新版登记、卸载文件和快捷方式。该组会创建测试登记，执行前另行说明并确认，未通过前不接入真实安装。

## 验收与接入门槛

隔离实验必须保留实际日志、文件校验和明确失败断言。源码契约检查只作辅助。所有登记与清理顺序已验证、恢复失败可安全停止后，再接入正式安装器并编译。真实服务中断及覆盖回退测试另行申请确认，需重新备份并验证恢复后版本、配置不变和新增采集数据。
