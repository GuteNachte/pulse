# Pulse 开发环境一键启动设计

## 目标

为 Windows 开发环境提供一个真正可双击使用的启动入口。用户从项目根目录或桌面快捷方式启动后，Pulse 自动启动或复用 Hub 与 Vite，确认服务可用后打开 Web 页面，继续使用项目内既有 `pulse_data`，避免只看到浏览器页面外壳却没有资产数据。

## 方案选择

采用“根目录启动器 + 可重复生成的桌面快捷方式”：

- 项目根目录提供 `Start-Pulse-Dev.cmd`，作为唯一面向用户的一键入口。
- 启动器调用既有 `supplemental\scripts\run-hub-dev.ps1`，不复制 Hub、Vite、数据目录或局域网地址判断逻辑。
- 仓库提供独立的桌面快捷方式安装脚本；该脚本根据当前仓库绝对路径生成快捷方式，不把本机路径提交进仓库。

不采用 Windows 登录自启。开发服务只在需要时运行，避免长期占用 `5173`、`8090` 端口。也不只创建一次性的手工快捷方式，因为项目移动后无法复用和修复。

## 启动行为

1. 启动器先将工作目录切换到自身所在的项目根目录。
2. 优先使用已安装的 PowerShell 7 (`pwsh.exe`) 调用标准开发脚本；没有 PowerShell 7 时回退到 Windows PowerShell 5.1 (`powershell.exe`)。默认不传 `-Restart`：服务未运行时启动，已经运行时直接复用。
3. 标准脚本继续固定使用项目根目录下的 `pulse_data`，并等待 Hub 健康检查通过。
4. 启动成功后打开 `http://localhost:5173`。
5. 启动失败时保留控制台窗口，显示错误并等待按键，避免窗口闪退后无法判断原因。

`run-hub-dev.ps1 -Restart` 与 `-Stop` 继续作为维护入口，不塞进日常双击流程。

## 桌面快捷方式

- 新增 `supplemental\scripts\install-dev-shortcut.ps1`，通过 Windows Shell 创建桌面快捷方式。
- 快捷方式名称使用“Pulse 开发环境”，目标指向当前仓库的 `Start-Pulse-Dev.cmd`，工作目录指向仓库根目录。
- 安装脚本可以重复执行，重复执行时更新同名快捷方式，不创建多个副本。
- 本次实施完成时实际运行安装脚本，在当前用户桌面创建快捷方式。

## 错误处理

- 缺少标准 PowerShell 启动脚本时，启动器明确报错并退出。
- Hub、Vite、Go、Node 或依赖启动失败时，保留标准脚本的真实错误和日志路径，不吞掉错误。
- 只有标准脚本成功返回后才打开浏览器，避免再次出现“页面打开了，但后端没有资源”的假成功。

## 验证

- 先增加静态契约测试，确认根目录启动器调用标准脚本、成功后打开固定 Web 地址、失败时不会打开浏览器。
- 增加桌面快捷方式安装脚本契约测试，确认快捷方式目标和工作目录来自当前仓库，且支持覆盖更新。
- 验证首次启动能够监听 `5173`、`8090`，Hub 健康检查返回 `200`。
- 验证服务已运行时再次启动不会强制杀进程或切换数据目录。
- 运行快捷方式安装脚本并检查桌面 `.lnk` 的目标、参数和工作目录。
- 同步开发运行手册、开发启动清单、README、`1.0.6` 开发记录和设置页关于版本记录。
