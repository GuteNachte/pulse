# 互联网接入公网地址 DDNS 简化设计

## 背景

当前宽带资产支持把公网 IPv4 / IPv6 标记为“手动确认”。当自动检测发现变化时，系统保留旧值并生成待确认候选。白老板已经使用 DDNS 和域名访问服务，不会直接依赖某个固定公网 IP，因此这套人工保护流程增加了理解和操作成本，没有实际收益。

## 已确认目标

公网地址改为纯自动状态：Hub 检测到有效地址后直接更新正式值；IPv4 与 IPv6 继续独立成功或失败；失败时保留各自上一次成功地址；只有正式地址真实变化时才写入资产变更记录。

编辑工作台只显示当前公网 IPv4、IPv6、最近检测时间、协议错误和“刷新公网地址”。不再显示“手动确认”“确认新地址”“标记为已确认”或待确认候选。

## 模块与边界

本功能继续属于必需模块 `asset-center`，不新增模块、集合、设置项或 Agent 能力。检测仍由 Hub 在启动时、每 30 分钟定时任务和用户手动刷新时执行；前端只负责展示和触发刷新。

## 数据流

1. Hub 分别请求 IPv4 与 IPv6 检测服务。
2. 某协议成功时，直接写入 `public_ipv4` 或 `public_ipv6`，并清除该协议旧错误。
3. 某协议失败时，保留旧成功值并更新该协议错误。
4. 每次检测写入 `public_ip_checked_at`。
5. 地址从一个非空值变为另一个非空值时，写一条“公网地址已变化”记录；首次获得地址不制造变化记录。
6. 每次刷新清理历史 `*_source`、`*_candidate` 和 `*_candidate_checked_at` 字段，不新增数据库迁移，也不影响旧数据读取。

## API 与界面

- 保留 `POST /api/pulse/assets/{id}/internet-addresses/refresh`。
- 删除 `POST /api/pulse/assets/{id}/internet-addresses/confirm`。
- 刷新响应只返回当前检测结果和协议错误，不再返回候选地址。
- 编辑工作台保留只读公网地址字段与刷新按钮，在字段上方显示紧凑的“自动检测 / 最近检测”状态；仅在协议失败时显示对应错误。

## 验证

- Go 单元测试覆盖人工历史值被新检测值直接替换、候选字段被清理、单协议失败保留旧值、真实变化记录与定时范围。
- 前端直接测试覆盖刷新成功、部分失败、全部失败和无人工确认状态。
- 浏览器验收桌面与窄屏编辑工作台：确认无人工确认按钮、当前地址可见、刷新操作可用、无横向溢出和控制台错误。
