# 互联网接入公网地址 DDNS 简化设计

## 背景

当前宽带资产支持把公网 IPv4 / IPv6 标记为“手动确认”。当自动检测发现变化时，系统保留旧值并生成待确认候选。白老板已经使用 DDNS 和域名访问服务，不会直接依赖某个固定公网 IP，因此这套人工保护流程增加了理解和操作成本，没有实际收益。

## 已确认目标

公网地址改为纯自动状态：Hub 检测到有效地址后直接更新正式值；IPv4 与 IPv6 继续独立成功或失败；失败时保留各自上一次成功地址；只有正式地址真实变化时才写入资产变更记录。

详情卡片和编辑工作台都显示当前更新后的公网 IPv4、IPv6、上次更新时间和预计下次更新时间；两处都提供自动更新开关、固定更新时间选择和“刷新公网地址”，并共用同一设置、刷新链路和加载状态。编辑工作台另外显示协议错误。不再显示“手动确认”“确认新地址”“标记为已确认”或待确认候选。

自动更新默认开启，默认间隔 30 分钟。间隔只允许选择 15 分钟、30 分钟、1 小时、6 小时、12 小时或 24 小时，不提供自定义数字。关闭自动更新后仍可手动刷新；重新开启或更改间隔时立即刷新一次并重新计算下次更新时间。

## 模块与边界

本功能继续属于必需模块 `asset-center`，不新增模块、集合、设置项或 Agent 能力。检测仍由 Hub 在启动时、每 30 分钟定时任务和用户手动刷新时执行；前端只负责展示和触发刷新。

## 数据流

1. Hub 分别请求 IPv4 与 IPv6 检测服务。
2. 某协议成功时，直接写入 `public_ipv4` 或 `public_ipv6`，并清除该协议旧错误。
3. 某协议失败时，保留旧成功值并更新该协议错误。
4. 每次检测写入 `public_ip_checked_at`；使用中且开启自动更新的宽带按所选间隔写入 `public_ip_next_check_at`，关闭自动更新或非使用中宽带清空下次更新时间。
5. 地址从一个非空值变为另一个非空值时，写一条“公网地址已变化”记录；首次获得地址不制造变化记录。
6. 每次刷新清理历史 `*_source`、`*_candidate` 和 `*_candidate_checked_at` 字段，不新增数据库迁移，也不影响旧数据读取。
7. 后台任务每 15 分钟扫描一次使用中的宽带，只刷新已开启自动更新且 `public_ip_next_check_at` 已到期的记录；历史记录没有设置时按“开启、30 分钟”处理。

## API 与界面

- 保留 `POST /api/pulse/assets/{id}/internet-addresses/refresh`。
- 删除 `POST /api/pulse/assets/{id}/internet-addresses/confirm`。
- 新增 `POST /api/pulse/assets/{id}/internet-addresses/settings`，只接受开关和固定间隔；关闭时清空下次时间，开启或改间隔时保存设置并立即刷新。
- 刷新响应只返回当前检测结果和协议错误，不再返回候选地址。
- 详情卡片把地址标签明确为“当前公网 IPv4 / IPv6”，增加“上次更新时间 / 下次更新时间”，并在卡片右上角显示自动更新开关、间隔选择和“刷新公网地址”。
- 编辑工作台保留只读公网地址字段，在字段上方显示相同的开关、间隔选择和刷新按钮，以及紧凑的上次/下次更新状态；仅在协议失败时显示对应错误。

## 验证

- Go 单元测试覆盖人工历史值被新检测值直接替换、候选字段被清理、单协议失败保留旧值、真实变化记录、固定间隔、开关、到期判断和下次更新时间。
- 前端直接测试覆盖刷新成功、部分失败、全部失败、更新时间展示和无人工确认状态。
- 浏览器验收桌面与窄屏详情及编辑工作台：确认当前地址、上次更新时间、下次更新时间可见，两处开关、间隔与刷新操作同步，无人工确认按钮、横向溢出或控制台错误。
