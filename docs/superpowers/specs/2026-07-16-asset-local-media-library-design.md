# 资产本地媒体库设计

## 目标

在不新增独立页面、不中转第三方对象存储的前提下，把资产图片能力升级为完整的本地媒体库：用户在“编辑资产”工作台内完成找图、上传、入库、编辑、版本管理、封面和详情图库配置；编辑后必须生成真实文件并保存到可配置的本地对象存储目录。

## 已确认约束

- 图片管理只存在于每个资产的编辑工作台，不新增“图片管理”路由。
- 存储固定为 Hub 所在机器的本地对象存储目录；不接入 MinIO、S3、迁移工具或远程存储。
- 设置页提供目录配置、可写检查、用量、对象数量与安全清理；配置不会删除或移动已有文件。
- 资产中心是唯一模块归属，继续使用 `asset-center` manifest 和模块开关。
- 原图不可破坏；每次保存编辑生成可追溯的独立版本文件。
- 详情展示、编辑预览和缩略图使用同一套展示规格，消除裁剪结果与实际详情页不一致的问题。

## 架构

Hub 新增 `asset_media`（逻辑媒体）、`asset_media_versions`（原图与渲染版本）、`asset_media_placements`（封面/图库展示位置）三个集合，并把现有 `asset_visuals` 作为历史候选来源兼容读取。媒体字节存放在配置目录，PocketBase 只保存对象键、完整性哈希、文件属性、来源、编辑配方、版本关系和展示位置。

图像处理放在 Hub 的资产媒体服务内：使用 Go 的 `imaging` 与 `x/image` 完成方向修正、裁剪、旋转、缩放、背景合成、JPEG/PNG 编码和缩略图生成。浏览器用 Canvas 与现有 React 指针交互即时预览；保存请求提交标准化编辑配方，Hub 使用同一配方生成最终文件，前后端不共享“仅用于展示的裁剪状态”。第一版不包含滤镜、文字、拼图、AI 抠图或生图。

## 本地对象存储

系统设置保存一个绝对目录；未配置时使用 Hub 数据目录下的默认 `asset_media`。Hub 启动和每次保存设置时验证目录可创建、可读写，拒绝相对路径、目录文件化和不可写路径。

```text
<media-root>/
  originals/<asset-id>/<media-id>/<version-id>.<ext>
  renders/<asset-id>/<media-id>/<version-id>.jpg
  thumbnails/<asset-id>/<media-id>/<version-id>-{sm,md,lg}.jpg
  temporary/<request-id>/
```

对象键只由 Hub 生成；路径解析必须验证最终路径仍在根目录内。删除版本前检查是否被封面或图库位置引用；删除媒体前保留原图直到用户明确永久删除。安全清理仅删除过期临时目录与数据库中已无引用的渲染/缩略图，不处理原图。

## 数据模型与状态

### `asset_media`

- `asset`：所属资产。
- `source_kind`：`search`、`upload`、`url_import`、`legacy_visual`。
- `source_url`、`source_title`、`source_provider`：来源可追溯信息。
- `content_hash`：原图 SHA-256，用于同资产去重。
- `state`：`candidate`、`library`、`archived`、`deleted`。
- `active_version`：当前在图片库中打开的版本。

### `asset_media_versions`

- `media`、`parent_version`：版本链；原图没有父版本。
- `kind`：`original`、`render`。
- `object_key`、`thumbnail_keys`、`mime_type`、`width`、`height`、`bytes`。
- `recipe`：裁剪区域、旋转、翻转、输出比例、背景模式、背景色、主体对齐。
- `created_by`、`created_at`、`label`。

### `asset_media_placements`

- `asset`、`media`、`version`。
- `role`：`cover` 或 `gallery`。
- `sort_order`、`visible`。

每个资产至多一个可见封面；图库可有多张且排序稳定。一个版本可同时是封面与图库项。候选图片必须先“加入图片库”才允许编辑、展示或生成衍生版本。

## API

所有接口位于 `/api/pulse/assets/:assetId/media`，受现有 `asset-center` 模块检查和编辑权限保护：

- `GET /`：媒体、版本摘要、展示位置和本地文件 URL。
- `POST /search`：复用图片搜索 Agent，把结果写入候选媒体。
- `POST /upload`：上传本地原图，归档、去重并生成缩略图。
- `POST /import-url`：下载用户明确提供的 URL，归档、去重并生成缩略图。
- `POST /:mediaId/adopt`：候选进入图片库。
- `POST /:mediaId/versions`：由编辑配方创建真实渲染版本。
- `POST /:mediaId/placements`：设封面、加入图库、显示/隐藏、排序。
- `POST /:mediaId/restore/:versionId`：将历史版本设为活动版本或展示版本。
- `DELETE /:mediaId/versions/:versionId`、`DELETE /:mediaId`：执行引用校验和二次确认所需的删除动作。

原始文件、渲染文件和缩略图均通过受鉴权的 Hub 媒体读取端点返回，不能直接暴露操作系统绝对路径。

## 编辑工作台交互

资产编辑右侧保留为单个图片区，但按任务状态分层而不是新建页：

1. 顶部操作：获取图片、上传、粘贴链接；显示找图进度与失败原因。
2. 预览区：展示当前封面或选中图库版本，提供与资产详情相同的卡片预览。
3. 编辑态：覆盖预览区，提供拖拽裁剪框、缩放、旋转、翻转、比例预设、背景模式、重置、取消、保存为新版本。
4. 图片库：三列缩略图网格，显示封面、图库、候选和归档状态；支持多选和拖拽图库排序。
5. 版本历史：选择库内图片后显示原图及其渲染版本；可预览、比较、恢复和删除未引用版本。

候选区与图片库分开显示：候选仅有“加入库/丢弃/来源”；库内图片才有“编辑/设封面/加入图库/归档”。详情页读取 `cover` 与 `gallery` placement，不再自己推断单个 `primary` 图片。

## 设置页

资产中心设置新增“本地媒体对象存储”卡：目录输入、恢复默认目录、测试目录、健康状态、对象数、总用量、上次清理时间、清理临时文件、清理无引用派生文件。目录变更只影响后续新写入对象；页面必须明确提示旧对象继续从原保存位置读取，不能承诺自动迁移。

## 质量、安全与验收

- 图片下载/上传最大体积、允许 MIME、最小像素和解码像素总量受限，避免畸形图片与内存耗尽。
- 导入时剥离 EXIF/GPS，所有浏览器输出使用安全文件响应头。
- 原图与版本编辑采用 SHA-256 与对象存在性校验；文件写入先进入临时目录，再原子移动。
- 缩略图按小、中、大三档生成；列表禁止加载原始图。
- 核心自动测试覆盖：目录校验与路径逃逸、对象原子写入、去重、编辑配方归一化、版本生成、封面唯一性、图库排序、删除引用保护、清理边界和旧 `asset_visuals` 候选兼容。
- UI 测试覆盖：候选入库、保存为新版本、设封面、加入图库、恢复历史版本和“编辑预览=详情预览”。

## 非目标

- 不建立独立图片管理页面。
- 不引入对象存储服务、远程同步、目录迁移或第三方 CDN。
- 不实现文字、水印、拼图、滤镜、AI 抠图或生图。
- 不自动把搜索候选直接设为封面；所有展示变更由用户确认。
