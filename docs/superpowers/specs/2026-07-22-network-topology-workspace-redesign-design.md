# 网络拓扑工作台重设计

## 目标

把 `/network` 从现有自由画布彻底重做为“网络分层矩阵”。现有页面只提供真实资产、网口、链路和维护能力清单，不作为布局、视觉或交互参考。

用户打开页面后应立即看清：

- 当前有哪几个独立网络域
- 每个网络域的上游入口、网关 / 路由、交换 / 接入设备和终端
- 网线、无线和光纤分别如何连接
- 哪些设备未接入、缺少端口或形成异常关系

本功能属于现有 `network-topology` 模块，继续消费资产中心的 `assets`、`asset_interfaces`、`asset_relations`，并使用 `network_layouts` 保存列内排序和当前视图。不新增数据库集合，不复制资产主档，不改变 Agent 采集边界。

## 范围

本轮重做完整网络拓扑页 `/network`，保留以下业务能力：

- 刷新拓扑数据
- 新增设备、网口和链路
- 查看与编辑节点、链路
- 调整并保存设备顺序
- 从资产或关系 URL 参数定位节点 / 链路
- 展示 Agent 机器在线状态、网卡和流量
- 深色、浅色主题

首页只读拓扑继续读取相同图数据，但使用紧凑只读模式，不渲染完整页的维护工具、网络域矩阵标题或详情抽屉。

本轮只针对桌面客户端浏览器自适应，不单独设计手机页面。

## 页面骨架

页面不使用大 Card 包裹整个工作区，直接由顶部控制栏、网络域筛选、矩阵画布和按需详情抽屉组成。

### 顶部控制栏

顶部保持一条固定高度的紧凑控制栏：

1. 网络拓扑标题
2. 外网、设备、机器、端口、链路、无线六项统计
3. `全部 / 家庭网络 / 科技网`网络域筛选
4. `新增`、`刷新`、`调整布局`操作

`新增`使用现有 DropdownMenu，包含“设备、网口、链路”。默认布局锁定；进入调整模式后显示“保存顺序”和“取消调整”。

### 分层矩阵

矩阵固定为四列：

1. 上游网络
2. 网关 / 路由
3. 交换 / 接入
4. 终端

家庭网络与科技网分别占一条横向网络带。每条网络带包含域标题、状态摘要和四列节点区域，高度根据最拥挤列中的节点数量自然增长。所有网络带共享相同列宽和列标题，设备横向位置稳定，页面不会因节点内容变化产生结构跳动。

`全部`视图纵向展示所有网络带；选择单个网络域后只展示该网络带并适配视口。孤立节点统一进入底部“未接入”网络带，不伪造上联。

### 详情抽屉

页面不长期保留空白侧栏。点击节点或链路后，从右侧打开约 360px 的 Sheet：

- 节点详情：设备摘要、上联、下联、网口状态和编辑入口
- 链路详情：两端设备、两端接口、连接介质、方向、速率和编辑入口

关闭抽屉后矩阵恢复全宽，当前网络域和选中对象仍保留。

## 网络域与层级

新增纯函数模型 `buildTopologyMatrix()`，把基础图转换为网络域、矩阵列、诊断和列内顺序。

```ts
type TopologyMatrix = {
  domains: TopologyMatrixDomain[]
  unlinked: TopologyMatrixNode[]
}

type TopologyMatrixDomain = {
  id: string
  label: string
  rootNodeIds: string[]
  columns: Record<TopologyMatrixColumn, TopologyMatrixNode[]>
  edgeIds: string[]
  diagnostics: TopologyDiagnostic[]
  summary: TopologyDomainSummary
}

type TopologyMatrixColumn = "upstream" | "gateway" | "access" | "endpoint"
```

分域规则：

1. 真实链路构成的连通分量就是网络域。
2. 优先选择 `internet` 资产作为域根；没有 `internet` 时选择无上联节点。
3. 包含家庭宽带入口的域显示“家庭网络”；其他域优先使用根资产名称，例如“科技网”。
4. 无链路节点进入“未接入”。
5. 环路保留真实链路并标记“存在环路”，计算不能递归卡死。
6. 缺少任一端资产或接口时保留关系并标记“端点待确认”。

列归属规则：

- `upstream`：互联网接入、外部网络和域根上游
- `gateway`：光猫、ONT、网关、路由器、防火墙
- `access`：交换机、无线 AP、网络接入设备
- `endpoint`：NAS、服务器、主机、手机、摄像头、插座和其他终端

同列默认按真实上下联深度、设备类型、名称和稳定 ID 排序。用户调整布局时只能修改同列的纵向顺序，不能把终端拖入网关列，也不能通过拖动改变真实关系。

## 节点体系

节点不沿用当前大卡片样式，改为两种固定尺寸：

- 基础设施节点：网关、路由器、交换机、AP，约 184 × 64px
- 终端节点：NAS、主机、手机、IoT，约 168 × 48px

节点只显示：

- 设备名
- 类型图标和短类型
- 状态点
- 主 IPv4（存在时）
- 基础设施节点的已连接接口 / 真实接口总数

节点使用中性底色、清晰边框和小面积状态色。设备类型靠 Lucide 图标和文字区分，不使用大面积彩色卡片。选中节点增强边框；直接上联、下联保持正常，其余节点降低对比度。

## 三类链路

三类链路不继承原有视觉，必须同时通过路径形状、线型、端点和文字语义区分，不能只靠颜色。

### 网线

- 使用横平竖直的直角实线
- 两端显示方形 RJ45 / 网口端点
- 悬停显示本端网口、对端网口和协商速率
- 颜色使用克制的冷灰蓝

### 无线

- 使用平滑弧形短虚线
- 不显示物理插头，链路中部显示 Wi-Fi 图标
- 多个无线终端从接入点扇出，避免与有线直角线重叠
- 颜色使用克制的青绿色

### 光纤

- 使用双层平行线
- 两端显示圆形光口端点
- 链路中部显示“光纤”或 PON / 光口名称
- 颜色使用克制的琥珀色

默认不播放持续流动动画。选中链路时增强描边和方向箭头；其余链路降低对比度。路径交叉不可避免时使用桥接或错层偏移，避免两条线视觉黏连。

## 网络带与异常

每条网络带左侧显示域名称和摘要，右侧矩阵区域使用轻微列底色和细分隔线，不用大色块或嵌套卡片。

异常显示规则：

- 缺少接口：域标题显示“接口待确认”，相关链路使用警示端点
- 关系缺少资产：保留占位端点并显示“设备待建档”
- 环路：域标题显示“存在环路”，回边绕网络带上缘或下缘绘制
- 无上游：显示“上游待确认”，不把任意设备伪装成公网入口
- 无异常：显示中性“连接关系完整”

## 操作规则

- 默认矩阵锁定，避免误拖动。
- `调整布局`只允许同列节点上下重排。
- `保存顺序`写入 `network_layouts.layout.order` 和当前网络域。
- `取消调整`恢复进入调整模式前的顺序。
- 刷新时保留网络域、选中对象和未保存顺序；对象已删除时关闭抽屉并退回域视图。
- URL 参数进入时先显示目标所属域，再选中节点 / 链路并打开详情抽屉。
- 只读用户不显示新增、调整、保存和编辑入口。

## 数据与组件边界

现有 `loadTopologyData()` 继续读取必要字段，`buildTopologyGraph()` 继续生成真实节点和边。新增模块负责：

- `topology-matrix.ts`：网络域、四列归属、顺序和诊断
- `topology-selection.ts`：域筛选、URL 定位和上下联强调
- `topology-inspector-model.ts`：节点、链路详情
- `topology-matrix-layout.ts`：把矩阵模型转换为 React Flow 坐标和网络带尺寸
- `components/topology-workspace-toolbar.tsx`：控制栏与域筛选
- `components/topology-matrix-node.tsx`：两类节点
- `components/topology-matrix-edge.tsx`：网线、无线、光纤三类链路
- `components/topology-inspector-sheet.tsx`：详情抽屉

`home-network-topology.tsx` 只负责读取、页面状态、React Flow 组合、保存和现有维护弹窗，不继续承载矩阵领域判断和大段节点 JSX。

## 加载、空态与错误

- 首次加载保持工作台骨架稳定，只在矩阵区域显示加载状态。
- 没有资产时引导前往资产中心添加真实主档。
- 有资产但没有关系时全部进入“未接入”网络带。
- 刷新失败保留最后一次成功数据，在控制栏下显示简短错误和重试入口。
- 未知资产类型进入终端列并标记原始类型，不导致渲染失败。
- 未保存顺序与远端刷新冲突时保留本地顺序并提示保存或取消。

## 视觉规则

- 不复用当前页面卡片结构、节点造型、固定侧栏或持续动画。
- 继续使用项目全局字体、语义颜色变量和成熟 shadcn / Radix 组件，确保与 Pulse 其他页面仍属于同一产品。
- 不使用渐变、发光、玻璃拟态、装饰图形或大面积类型色块。
- 控制栏、列标题、节点、端点和按钮使用固定尺寸。
- 文字溢出时截断，并通过 Tooltip 查看完整内容。
- 深色和浅色主题均保证链路线型、端点和状态可辨认。

## 测试与验收

自动化测试覆盖：

- 家庭网络和科技网分成独立网络带
- 节点进入正确的四列
- 孤立节点进入“未接入”
- 环路和缺失端点产生诊断但不阻断渲染
- 同一输入产生稳定顺序和坐标
- 调整模式只能改变同列顺序
- 节点与链路选择只强调直接上下联
- 节点和链路详情不伪造缺失接口
- URL 参数定位目标所属网络域
- 首页只读总览不出现完整页维护工具

浏览器验收覆盖：

- 深色和浅色主题
- 三类链路仅凭形状和端点也能区分
- `全部 / 家庭网络 / 科技网`筛选
- 节点、链路选择和详情抽屉
- 新增、刷新、调整、保存和取消
- 控制台无错误，文字、端点和链路不遮挡

## 非目标

- 不自动发现局域网设备
- 不通过拖动修改资产类型或真实关系
- 不新增实时 SNMP、LLDP 或交换机端口采集
- 不做手机端专门适配
- 不重做资产详情页或首页其他区域
- 不改变模块开关、Hub API 或数据库集合
- 不把推测关系显示为已确认关系
