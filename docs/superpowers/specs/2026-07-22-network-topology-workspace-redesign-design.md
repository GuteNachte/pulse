# 网络拓扑工作台重设计

## 目标

把 `/network` 从自由摆放、需要人工追线的拓扑画布，重设计为“先看清网络关系，再做维护”的桌面工作台。用户打开页面后应能立即区分家庭网络与科技网，并按上游入口、网关 / 路由、交换设备和终端的顺序阅读真实连接。

本功能属于现有 `network-topology` 模块，继续消费资产中心确认后的 `assets`、`asset_interfaces`、`asset_relations`，并使用 `network_layouts` 保存用户布局和视图配置。不新增数据库集合，不复制资产主档，不改变 Agent 采集边界。

## 范围

本轮重设计完整网络拓扑页 `/network`，保留以下现有能力：

- 刷新拓扑数据
- 新增设备、网口和链路
- 查看并编辑节点详情
- 拖动节点和保存布局
- 从资产或关系 URL 参数定位节点 / 链路
- 展示 Agent 机器在线状态、网卡和流量
- 深色、浅色主题

首页家庭网络拓扑仍为只读总览，继续复用同一份图数据和基础节点组件，但不增加维护工具栏、固定详情栏或网络域筛选。完整页重设计不能破坏首页总览的自适应高度与完整构图。

本轮只针对桌面客户端浏览器自适应，不单独设计手机页面。较窄桌面窗口允许把固定详情栏切换为抽屉，保证画布仍可操作。

## 页面骨架

页面由顶部工具栏、网络域导航、拓扑画布和固定详情栏组成。

### 顶部工具栏

顶部保持单行紧凑布局：

1. 网络拓扑图标与标题
2. 外网、设备、机器、端口、链路、无线六项紧凑统计
3. `新增`、`刷新`、`自动整理`、`保存布局`操作

`新增`使用现有 DropdownMenu，包含“设备、网口、链路”三个命令，替代右侧三个长期占位按钮。刷新、自动整理和保存布局保留直接入口。按钮沿用现有 Button 和 Lucide 图标，不增加新的装饰样式。

### 工作区

桌面主体使用 `minmax(0, 1fr) + 20rem` 两列结构：

- 左侧拓扑画布使用浏览器剩余高度，保留可操作的最小高度。
- 右侧详情栏固定约 320px，并固定在顶部导航下方独立滚动。
- 桌面宽度不足以同时保证画布和详情栏时，详情栏改为 Sheet 抽屉；画布不压缩到无法阅读。
- 页面使用自然滚动，不在画布外再套多层浮动卡片。

画布左上角提供 `全部 / 家庭网络 / 科技网` 紧凑分段导航。网络域数量变化时根据计算结果生成选项，不在代码中写死名称。选择某个网络域后，只聚焦该域的节点和链路；`全部`恢复完整视图。

## 网络域模型

新增纯函数展示模型，负责把现有拓扑图转换为网络域和层级，不把领域判断继续堆进页面组件。

```ts
type TopologyDomain = {
  id: string
  label: string
  rootNodeIds: string[]
  nodeIds: string[]
  edgeIds: string[]
  levels: TopologyDomainLevel[]
  summary: TopologyDomainSummary
}

type TopologyDomainLevel = {
  depth: number
  nodeIds: string[]
}
```

分域规则：

1. 以真实链路构成的连通分量作为一个网络域。
2. 优先选择 `internet` 资产作为域根；没有 `internet` 时，选择无上联关系的节点作为域根。
3. 多个候选根按资产类型优先级、资产编号和名称稳定排序，保证同一数据每次得到相同结果。
4. 包含家庭宽带入口的域显示为“家庭网络”；其他域优先使用根资产名称，例如“科技网”。
5. 没有任何链路的孤立节点进入“未连接”域，不伪造上联或下联。
6. 存在环路时保留真实链路，以根节点最短距离确定展示层级，并在详情栏标记“存在环路”，页面不能递归卡死。

层级顺序为：

1. 外网 / 上游网络
2. 光猫、网关、路由器、防火墙
3. 交换机、无线 AP
4. NAS、服务器、主机和其他有线终端
5. 手机、摄像头、插座和其他无线 / IoT 终端

同层节点按设备类型、名称和稳定 ID 排序。自动布局使用成熟的分层图布局库 `@dagrejs/dagre` 计算交叉更少的初始坐标，再按 Pulse 的固定节点尺寸、层间距和网格间距规整坐标。网络域之间纵向排列并保留清晰间隔。

## 节点设计

普通节点统一使用固定尺寸紧凑卡片，避免内容变化引起画布跳动。默认只显示：

- 设备名
- 设备类型图标和类型文字
- 在线 / 正常 / 离线 / 待接入状态
- 主 IPv4；没有固定 IPv4 时不显示占位行
- 网络设备显示“已连接接口 / 真实接口总数”
- 无线接入设备显示下联无线终端数

节点只使用克制的边框和小面积语义色。设备类型主要靠 Lucide 图标和文字识别，不使用大面积类型色块。互联网入口保持更窄的根节点样式，但与普通节点共享选中、悬停和详情触发规则。

选中节点时：

- 选中节点使用明确边框和焦点环。
- 直接上联、直接下联及对应链路保持正常对比度。
- 其他无关节点和链路降低对比度，但仍可辨认和点击。
- 右侧详情栏同步切换为节点详情。

## 链路设计

链路继续展示真实 `asset_relations`，不根据屏幕位置推断关系。

- 网线：实线，并显示网线图标语义。
- Wi-Fi：短虚线，并显示 Wi-Fi 图标语义。
- 光纤：双线或更细的实线组合，并显示光纤文字标识。
- 外网上联：使用稳定方向箭头表达从上游到下游。

颜色只作为辅助区分，线型和文字语义必须同时存在。默认取消所有链路持续运行的数据脉冲动画；只有选中链路时才增强描边和方向，减少整页视觉噪音。

悬停链路显示：

- 本端设备与本端接口
- 对端设备与对端接口
- 接入方式
- 链路 / 协商速率

点击链路后选中该关系，并在右侧显示完整链路详情和维护入口。

## 右侧详情栏

详情栏有三种状态。

### 网络域概览

未选节点或链路时显示当前筛选域：

- 上游入口
- 设备数、链路数、无线终端数
- 未接入设备数
- 孤立节点、缺少接口端点、环路等需要关注的问题
- 未接入拓扑的 Agent 机器

没有需要关注的问题时显示中性“连接关系完整”，不显示空白卡片。

### 节点详情

选中设备后按以下顺序显示：

1. 设备摘要：名称、类型、状态、IPv4、管理地址入口
2. 上联：真实上联设备、两端接口、接入方式和速率
3. 下联：真实下联设备列表
4. 网口状态：`网口 / 角色 / 对端 / 接入方式 / 速率`

交换机、路由器、光猫等多接口设备使用紧凑网口表。普通终端只显示实际存在的信息。接入关系不再作为另一张重复卡片出现，上联、下联和网口状态统一消费同一份关系展示模型。

### 链路详情

选中链路后显示：

- 两端设备
- 两端接口
- 上联 / 下联方向
- 网线、Wi-Fi 或光纤接入方式
- 标称和协商速率
- 当前关系状态
- 编辑关系入口

## 操作规则

- `自动整理`只修改当前内存中的节点坐标，不立即写入数据库。
- `保存布局`显式保存当前坐标、视口和选中网络域。
- 用户手动拖动后仍可继续编辑；切换网络域不会丢失未保存坐标。
- 刷新数据时保留当前域、选中对象和可复用视口；对象已删除时退回域概览。
- 从 `/network?asset=<id>` 或 `/network?relation=<id>`进入时，先切换到目标所属域，再聚焦并选中目标。
- 只读权限下隐藏新增、自动整理后的保存和所有编辑入口，查看与筛选保持可用。

## 数据流与组件边界

现有 `loadTopologyData()` 继续负责读取必要字段，`buildTopologyGraph()` 继续生成 React Flow 节点和边。新增模块函数负责：

- `buildTopologyDomains()`：连通分量、根节点、域名称和统计
- `buildTopologyHierarchy()`：上下联层级、环路和孤立节点诊断
- `layoutTopologyDomains()`：调用 Dagre 并规整坐标
- `buildTopologyInspectorModel()`：网络域、节点和链路详情模型
- `getTopologyFocusSet()`：计算选中对象的直接上下联和淡化集合

`home-network-topology.tsx` 只负责页面状态、React Flow 交互、弹窗和组合展示。新增领域函数及详情组件放入 `internal/site/src/modules/network-topology/`，避免继续扩大共享路由组件。

## 加载、空态与错误

- 首次加载使用与画布尺寸一致的中性加载状态，不改变工作区结构。
- 没有资产或链路时继续引导用户前往资产中心建立真实主档和关系。
- 刷新失败时保留最后一次成功拓扑，在顶部工具栏下显示简短错误提示并允许重试。
- 缺少接口端点、未知链路类型或对端资产不存在时保留关系并标记“待确认”，不能丢弃或伪造数据。
- 关系形成环路时正常渲染并提示，不让布局计算进入死循环。
- 未保存布局与远端数据刷新冲突时保留本地坐标，并提示用户先保存或重新整理。

## 视觉规则

- 继续沿用 Pulse 当前 Tailwind 变量、Card、Button、Badge、Tooltip、Sheet、DropdownMenu 和 Lucide 图标。
- 卡片圆角不超过现有 `rounded-lg`，不使用渐变、发光、玻璃拟态或装饰性背景。
- 画布背景使用低对比度网格，网络域只用文字标签和轻微分隔，不使用大块彩色底板。
- 统计、节点、网口表和按钮保持固定高度；文字溢出时截断并通过 Tooltip 查看完整值。
- 深色和浅色主题均保持足够对比度，状态不能只靠颜色表达。

## 测试与验收

自动化测试覆盖：

- 家庭网络和科技网被拆成独立网络域
- 外网、无上联资产和孤立节点的根选择
- 上游到终端的稳定层级和排序
- 环路不会导致死循环，并产生明确诊断
- 自动整理对同一输入生成稳定坐标
- 选中节点只强调直接上联和下联
- 网络域、节点、链路三种详情模型
- 刷新失败保留最后一次成功数据
- URL 参数定位目标所属网络域
- 首页只读总览不出现维护工具栏和详情栏

浏览器验收至少覆盖：

- 2494 × 1194 桌面窗口：完整拓扑、右侧详情固定、两套网络域清晰分开
- 1727 × 1272 较窄桌面窗口：画布可用、详情栏或抽屉不遮挡操作
- 深色和浅色主题
- `全部 / 家庭网络 / 科技网`切换与自动聚焦
- 节点、链路选择和无关对象淡化
- 新增设备、网口、链路弹窗
- 自动整理、手动拖动、保存和刷新
- 控制台无错误，节点文字和按钮不重叠

最终视觉验收使用重设计前后的同视口截图对比，确认画布利用率、网络域辨识、链路交叉数量、详情栏稳定性和信息密度均有明确改善。

## 非目标

- 不自动发现局域网设备
- 不自动修改资产接口或接入关系
- 不新增实时 SNMP、LLDP 或交换机端口采集
- 不把移动端适配纳入本轮
- 不重做资产详情页或首页布局
- 不改变模块开关、Hub API 或数据库集合
- 不把推测关系显示成已确认关系
