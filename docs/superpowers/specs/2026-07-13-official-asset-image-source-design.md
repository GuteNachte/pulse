# 图片搜索 Agent 设计

## 目标

资产中心自动收集可追溯的实体设备图片，不要求用户手动寻找或上传。厂商官网图片优先；官网候选不足时，使用适合中国网络环境的必应图片公开结果作为受限兜底。所有候选下载后归档到 Hub 本地，用户仍在编辑工作台确认唯一主图。

未来的生图 Agent 与本设计分离：届时才协调文本与生图模型；当前运行链路不生成图片。

## 来源与身份规则

- 实体设备优先读取 `official_image_url`，以及 `product_url`、`support_url`、`official_url` 页面及其同源资源。
- 官网候选未满时，图片搜索 Agent 才请求必应图片公开结果；服务类资产优先收集服务商官网 Logo，官网未命中时检索必应公开品牌 Logo 候选。服务候选标题或来源页必须包含服务商品牌，Google favicon 不作为 Logo 来源。
- 公共搜索要求资产同时具备厂商和可验证型号。型号或内部型号必须包含字母与数字，避免按名称、类型或泛化描述搜索。
- 必应候选的标题或来源页 URL 必须包含规范化后的型号标识；二维码、Logo、水印、海报、横幅、色卡和重复图片继续被拒绝。
- 候选元数据保存来源提供方、原始页面、图片地址和检索词。页面只展示本地文件 URL，不热链第三方图片；服务 Logo 最多保留 4 张候选，已知素材交易 / 水印站点不参与候选。

## 检索与模型边界

1. 规则根据厂商、型号、内部型号和颜色生成中文与英文检索词；已知厂商会补充中文品牌别名，例如 `MINISFORUM -> 铭凡`，以避免仅英文查询在国内搜索结果中跑偏。
2. 已配置的文本模型可以额外提供别名或检索词，只接受受限 JSON 字段 `queries`；URL、过长或异常结果被丢弃。
3. 文本模型未配置、不可用或返回无效内容时，继续使用规则检索，不阻断图片收集。
4. 图片搜索 Agent 不调用视觉模型查找 URL，也不调用生图模型。

## 归档、确认与可观测性

1. Hub 下载每张候选，校验响应、可解码性、尺寸、重复和明显非设备特征，再进行尺寸限制与空白边处理。
2. 通过的候选写入 `asset_visuals.files`；候选帧保留 `provider`、来源标题和来源页，用于显示“官网”或“必应图片”。
3. 若视觉校验模型已配置，仅审核已归档候选与当前资产的型号、外观和颜色，不输出检索词或图片 URL。
4. 用户点击候选后才写入唯一主图；详情页只展示该本地主图。
5. 任务摘要使用 `official_only` 或 `official_then_bing_public` 标明实际来源策略。

## 失败语义

没有官网候选且公开搜索未命中可验证型号时，任务返回无候选，不以无关图片代替。用户可补充厂商、型号或官方资料链接后再次运行图片搜索 Agent。
