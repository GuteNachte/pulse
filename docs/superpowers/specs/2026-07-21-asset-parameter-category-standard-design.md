# 资产详细参数固定分类设计规范

> 状态：用户已确认设计，等待实施前规格复核。

## 背景

Pulse 已经通过设备 Profile 区分不同资产类型，但详细参数仍混用“设备参数”“设备与环境”“硬件与端口能力”等宽泛分组。同一类事实在不同设备中可能落入不同卡片，部分卡片参数过多，也不利于 Agent 将采集结果稳定写入正确字段。

本规范在 `2026-07-12-asset-taxonomy-design.md` 已确定的资产类型和 Profile 架构上继续收口参数分类。旧规范中的类型划分、严格模板和采集白名单继续有效；涉及详细参数分类、设备管理 IPv6 和资料完整度标签的规则，以本规范为准。

## 目标

- 所有已经建档和以后新增的设备共用同一套详细参数分类名称、顺序和字段归属规则。
- “设备档案”继续作为所有设备的固定主档，不因详细参数重排而改变结构或位置。
- CPU、主板、显卡、内存、存储等主要硬件分别归类，不再堆入笼统的“硬件性能”。
- 分类保持中等粒度；允许卡片内部使用小标题，但不把有线、无线、光纤、路由、交换等拆成大量顶层卡片。
- Agent 采集、资料补全、编辑、详情、导入导出和完整度判断使用同一份字段目录。
- 移除设备档案中的管理 IPv6，并统一资产清单完整度百分比标签。

## 非目标

- 不改变资产大类和具体设备类型。
- 不把运行时软件、固件和操作系统版本加入硬件档案。
- 不新增“打印能力”“视频监控能力”“后备电源能力”“智能家居能力”等设备类型专属顶层分类。
- 不在本次分类调整中删除历史数据库字段或历史值。
- 不把宽带动态公网 IPv6 当作设备管理 IPv6 移除。

## 固定的设备档案

所有物理设备继续保留现有“设备档案”，负责跨设备通用且需要快速查阅的主档信息：

- 身份：资产编号、名称、类型、厂商、型号、序列号。
- 使用：状态、位置、用途 / 角色和颜色。
- 管理：管理 IPv4、MAC 和管理页面。
- 资料：厂家资料页。

“设备档案”中的字段不得在右侧详细参数卡重复展示。互联网接入继续使用“线路档案”，互联网服务监控继续使用服务档案语义，不强行套用物理设备档案。

## 固定详细参数分类

详细参数只允许使用以下顶层分类，并按此顺序展示：

1. 外观与尺寸
2. 电源
3. 主板与平台
4. 处理器
5. 显卡
6. 内存
7. 存储
8. 网络
9. 接口与扩展
10. 显示
11. 影像
12. 音频
13. 传感器
14. 散热与环境

每种设备类型只启用适用分类。没有已确认数据的分类不显示，也不占空卡片位置。

### 外观与尺寸

包含机身材质、结构形态、尺寸、重量、安装方式和防尘防水等稳定物理事实。设备颜色继续留在设备档案，不在此重复。

卡片内部允许使用“结构”“尺寸重量”“安装与防护”等小标题。

### 电源

包含供电方式、输入规格、电源适配器、电源供应器、功率、冗余供电、PoE、电池、充电和续航等参数。UPS 等设备的容量、输出和电池事实也归入本分类，不单独建立“后备电源能力”。

卡片内部允许使用“输入与供电”“电源硬件”“电池与充电”等小标题。

### 主板与平台

包含主板厂商与型号、芯片组、BIOS、CPU 插槽、PCIe 插槽、机架或平台形态等平台级事实。

### 处理器

包含处理器厂商、型号、架构、制程、核心、频率和插槽数量。移动设备的 SoC 处理部分也进入本分类。

### 显卡

包含 GPU 厂商、芯片型号、板卡品牌、显存和图形能力。集成显卡与独立显卡使用同一分类。

### 内存

包含容量、规格、品牌、类型、频率、通道、ECC 和最大支持容量。

### 存储

包含当前存储摘要、硬盘品牌与型号、介质、容量、总线、盘位、背板、阵列、缓存、热插拔和文件系统等稳定事实。NAS 和服务器不再单独建立“存储服务与阵列”顶层分类。

卡片内部允许使用“设备与容量”“盘位与扩展”“阵列与文件系统”等小标题。

### 网络

包含网卡硬件、端口数量与速率、无线规格、蜂窝通信、定位、PON / 光纤、交换能力、路由功能、VLAN、安全吞吐和网络功能状态。管理 IPv4、MAC 和管理页面属于设备档案，不在网络卡片重复。

卡片内部按实际字段量使用“网卡”“端口”“无线与蜂窝”“光纤”“网络功能”等小标题，但顶层始终只显示一张“网络”卡片。

### 接口与扩展

包含 USB、Thunderbolt、OCuLink、音视频物理接口、扩展槽和其他非网络连接能力。网络端口仍归入“网络”。

### 显示

包含屏幕尺寸、面板类型、分辨率、刷新率、亮度、色深、HDR 和显示保护。

### 影像

包含摄像头、镜头、传感器、主摄 / 超广角 / 长焦、视频规格、防抖和对焦。摄像头资产的成像事实也归入此分类，不新增“视频监控能力”。

卡片内部允许使用“镜头与传感器”“拍摄规格”“视频与防抖”等小标题。

### 音频

包含扬声器、麦克风、音频芯片、编解码、声道和音频认证。

### 传感器

包含生物识别、环境传感器、运动传感器和设备内置感知硬件。智能家居设备不会因此新增“智能家居能力”顶层分类。

### 散热与环境

包含散热方案、风扇 / 均热板、工作温湿度、存储温湿度、防雷和稳定环境要求。

## 分类约束

- 每个字段只能属于一个顶层分类。
- 同一个字段键在所有设备类型中必须保持相同分类。
- 每张卡片以 `3–8` 个参数为常规范围；超过 `8` 个参数时优先使用卡片内部小标题和紧凑双列排版。
- 小标题仍无法避免信息过载时，必须重新评审字段是否重复、是否应拆为独立记录，不能随手创建新的顶层分类。
- 禁止新增“设备参数”“硬件性能”“设备与环境”“其他硬件”“其他参数”等兜底分类。
- 不能归入现有分类的全新参数先作为待确认候选，不直接写入正式主档；评审具体设备类型后再决定是否扩展固定分类。
- 不适用于当前设备类型的字段不显示、不要求填写，也不影响完整度。

## 单一分类注册表

资产中心建立唯一的参数分类注册表。字段定义至少包含：

```ts
type AssetParameterFieldDefinition = {
  key: string
  label: string
  category: AssetParameterCategoryId
  section?: string
  order: number
  source: "asset" | "metadata" | "interface" | "relation"
  capture: AssetCaptureMode
  type?: AssetFieldType
}
```

每个严格类型模板只选择适用字段和必填规则，不重复定义分类名称。下列链路都读取同一注册表：

1. Agent 和资料补全结果的字段白名单与归类。
2. 新增和编辑页面的字段顺序。
3. 详情页参数卡、小标题和顺序。
4. 导入模板、导入校验和导出列。
5. 资料完整度要求和缺失项文案。

## 采集和识别流程

采集到的一长串原始文本不能直接作为一个正式参数显示。处理顺序固定为：

1. 根据资产类型、厂商和型号选择严格模板。
2. 识别原始值代表的硬件事实。
3. 能可靠拆分时，拆为多个已注册字段。
4. 对单位、固定选项和格式进行归一化。
5. 按注册表归入固定分类和内部小标题。
6. 无法可靠识别的内容保留为候选并说明来源，不写入错误参数。
7. 用户确认后才进入正式资产主档。

## 管理 IPv6 规则

- 所有物理设备的编辑、详情、严格模板、导入导出、资料补全和完整度均移除 `fixed_ipv6` / “管理 IPv6”。
- 管理入口只保留管理 IPv4、MAC 和管理 URL。
- 历史管理 IPv6 值暂时保留在数据库中，但不显示、不重新写入，也不影响完整度。
- Agent 即使采集到临时 IPv6，也只能作为运行时网络观测数据，不进入稳定资产档案。
- 宽带线路的 `public_ipv6` 属于动态公网地址，继续保留自动更新、上次更新时间和下次更新时间。

## 资料完整度百分比规则

资产清单只使用一个完整度百分比组件，并固定以下规则：

- `90–100%`：绿色，资料完整。
- `70–89%`：蓝色，资料可用。
- `45–69%`：橙色，资料待补。
- `<45%`：红色，资料缺口大。

标签使用固定 `44 × 20px` 尺寸、等宽数字、居中对齐和固定圆角。百分比独占状态列最右侧的固定槽位；“监控”等状态标签放在独立区域，不能改变百分比的位置或宽度。

分数区间、文案和颜色必须来自同一映射函数，筛选、列表、预览和详情不得分别维护阈值。

## 现有数据兼容

- 现有字段值不因分类迁移而改名或删除，只更新字段到分类的映射。
- 已进入严格模板的宽带、光猫 / ONT 和交换机继续保留自己的适用字段和固定选项。
- 历史未知字段保持只读兼容，不得继续写入或影响新模板完整度。
- 分类迁移先生成字段覆盖报告，确认每个正式字段都有唯一归属；存在未归类或重复归类时阻止合并。
- 详情页迁移后只改变卡片分组与顺序，不改变参数值和来源。

## 错误处理

- 字段没有注册分类：拒绝进入正式主档，并显示“参数分类待确认”。
- 字段同时属于多个分类：视为注册表错误，测试和构建失败。
- Agent 返回模板外字段：保留任务原始输出用于审计，但不生成可确认候选。
- 历史字段无法映射：保持数据库原值，只读兼容并纳入迁移报告。
- 单张卡片字段过多：构建期测试给出明确分类和字段数量，不允许页面静默堆叠。

## 验收标准

- 所有当前正式字段都能映射到一个且仅一个固定分类，或明确属于设备档案 / 线路档案。
- 详情和编辑使用相同的分类名称、顺序和内部小标题。
- CPU、主板、显卡、内存、存储和电源不再混入同一张宽泛卡片。
- 网络设备只显示一个顶层“网络”分类，内部按字段量分组。
- 页面不再出现“设备参数”“硬件性能”“设备与环境”“其他参数”等兜底分类。
- 设备编辑和详情不再出现管理 IPv6；宽带动态公网 IPv6 正常保留。
- 资产清单百分比标签尺寸、位置和颜色区间完全一致。
- 现有资产参数值、接口、关系、封面和维护记录不丢失。
- Agent 不能把未注册或当前类型不适用的字段写入正式主档。
- 桌面端和移动端均无卡片溢出、文字重叠、异常空白或顺序漂移。
- `npm test`、`npm run typecheck`、Biome、构建和浏览器端到端验收全部通过。

## 实施边界

本设计属于 `asset-center` 必需模块，不新增模块、路由或数据库集合。实施时按以下顺序推进：

1. 建立分类注册表和字段唯一归属测试。
2. 迁移现有字段分类与详情参数卡。
3. 让编辑、导入导出、Agent 白名单和完整度共用注册表。
4. 移除设备管理 IPv6 全链路入口。
5. 收敛完整度百分比组件和颜色映射。
6. 使用现有典型资产逐类回归，并验证未来模板的注册约束。
