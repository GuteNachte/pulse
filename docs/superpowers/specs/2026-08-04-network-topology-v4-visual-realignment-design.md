# 网络拓扑 v4 视觉回归设计

- 日期：2026-08-04
- 状态：视觉方案已确认，待书面复核
- 范围：家庭网与科技网网络拓扑视觉层重做
- 视觉基准：浏览器预览 `C 方案：资产驱动结构 + v4 视觉层级`

## 目标

保留已经完成的资产驱动数据投影、只读交互、稳定排序和关系高亮能力，重新制作网络拓扑的视觉层，使正式页面恢复已确认的 v4 卡片比例、端口节点造型、空间层级和信息可读性。

本次不是恢复旧自由画布，也不恢复连接线、拓扑编辑或手工坐标。正式拓扑继续根据资产中心真实数据自动生成。

## 保留边界

以下能力保持不变：

- `assets`、`asset_interfaces`、`asset_relations` 和系统状态仍是唯一真实数据源。
- 家庭网和科技网继续复用同一资产投影和固定排序模型。
- 默认按有效管理 IPv4 数值升序，网络设备继续按上游层级稳定排序。
- 宽带固定在左侧；网络设备位于中轴单排；有线终端在上方；无线终端在下方。
- 终端每排最多 5 台，不显示空槽位、添加卡片或分区标题。
- 拓扑继续只读；点击卡片进入资产详情，不提供编辑关系、编辑接口、拖拽或保存布局。
- 不绘制连接线；关系仍通过结构化关系条和双端高亮表达。
- 当前连通性和测速仍等待真实检测能力接入，不用资产在线状态伪装链路检测结果。

## 视觉结构

### 整体画布

- 使用响应式 DOM 网格重新排版，不再把完整 `1600px` 逻辑画布整体缩成不可读的缩略图。
- 桌面端拓扑占满导航下方可用空间，左右不保留无意义空白，拓扑内部不产生横向或纵向滚动条。
- 左侧宽带区固定为约 `176px`，整高显示，但不随终端数量变宽。
- 右侧工作区固定分为三层：上方有线终端、中轴网络设备、下方无线终端。
- 三层之间使用明显但克制的垂直间距，使网络设备成为视觉中心，终端卡片不贴在网络设备边缘。

### 终端卡片

- 桌面端基准尺寸约 `190-210 × 112px`，每排最多 5 张，整体沿中轴从中间向两侧展开。
- 卡片显示名称、类型、IPv4、连接规格、位置和状态灯，信息保持完整可读。
- 关系条固定在卡片底部，使用三段结构：角色、上游设备、配对标识。
- 有线终端的 RJ45 节点位于卡片底边中心；无线终端的 Wi-Fi 节点位于卡片顶边中心。
- 节点中心与卡片边缘重合，保持一半在卡片内、一半在卡片外。

### 网络设备卡片

- 主网关基准宽度约 `340-360px`，交换机基准宽度约 `390-450px`，高度统一约 `146px`。
- 网络设备卡片比终端卡片更宽，但不做成占据大半画布的巨型面板。
- 名称、设备类型、管理 IPv4、最高接口速率、接口数量和状态灯固定显示。
- 顶部只显示普通 LAN / 电口节点，按照真实接口编号均匀排布。
- WAN / PON 上联节点固定在左边缘；连接下一级网络设备的接口节点固定在右边缘。
- `5 GHz` 和 `2.4 GHz` 无线节点固定在卡片下边缘。
- 左右侧节点只显示介质造型和悬停说明，不在卡片外显示端口文字；端口角色放回卡片内关系条。

### 宽带卡片

- 宽带区显示名称、运营商、套餐上下行、接入方式、装机地址、公网地址和状态灯。
- 信息使用标签和值两级排版，不再把所有内容压成尺寸过小的连续文本。
- 宽带出口只显示位于右边缘的光纤节点，不在节点外显示端口名称。

## 节点造型

- 有线端口使用紧凑 RJ45 造型，包含端口轮廓、金属触点和卡扣轮廓。
- 光纤入口使用琥珀色双环节点。
- 无线频段使用绿色圆形节点。
- 三种节点使用相同的视觉尺寸层级、背景对比和半嵌入规则。
- 节点不添加装饰性动画，不使用发光效果表达不存在的实时链路状态。

## 无连线关系表达

### 配对标识

关系条新增紧凑配对标识，用于在没有连接线时快速识别两端关系：

- 交换机端口使用真实端口简称，例如 `P04`、`P05`、`P06`。
- 网络设备之间的下联关系使用真实接口简称，例如 `L1`。
- 无线关系使用真实频段简称，例如 `5G`、`2.4G`。
- 宽带上联使用 `WAN`。

配对标识只来自真实接口或频段，不生成无法追溯的随机编号。

### 双端高亮

- 鼠标悬停、键盘聚焦或点击关系条时，高亮关系两端卡片、关系条和真实接口节点。
- 悬停网络设备接口节点时，高亮所有使用该接口的终端关系。
- 高亮仅增加边框、背景和轻微阴影，不改变卡片尺寸和位置。
- 移开鼠标、失去焦点或再次点击空白区后恢复默认状态。
- 多条关系共享同一无线频段时，所有同频段终端同时进入高亮范围。

## 响应式规则

- 宽桌面保持 5 列终端卡片和单排网络设备，卡片使用固定可读尺寸，剩余空间由行两侧平均吸收。
- 中等宽度优先压缩行间距和卡片横向间距，其次在约定范围内收窄卡片，不整体缩放文字。
- 窄屏不再把桌面拓扑完整缩成缩略图；改用项目移动端的紧凑卡片降级布局，并允许页面自然纵向浏览，但拓扑画布自身不产生嵌套滚动条。
- 所有断点必须保证卡片文字不重叠、端口节点不互相遮挡、关系条配对标识完整可见。

## 数据与异常状态

- 设备无真实关系时仍显示资产卡片，关系条显示“关系待确认”，不伪造端口或上游设备。
- 缺少接口名称、频段或上游名称时显示“待确认”。
- 多条关系共享接口时显示“多条关系 · N”，并使用同一配对标识和高亮集合。
- 加载失败、无资产和无关系状态使用正式页面已有错误 / 空状态组件，不渲染半套卡片。

## 实现边界

- 保留当前资产投影模型和高亮索引，主要重写布局数据、正式 DOM 结构和 CSS。
- 删除当前基于完整逻辑画布 `transform: scale(...)` 的不可读缩放策略。
- 不恢复 React Flow、SVG 路径、旧拓扑工作区、Inspector、WAN 编辑弹窗或自由画布状态。
- 不改变资产中心的数据结构和编辑流程。
- 不在本阶段实现 Ping、连通性检测、实时速率或测速。

## 验收标准

1. 正式页面的卡片比例、节点造型、空间层级与已确认的 C 方案预览一致。
2. 家庭网和科技网继续完全由资产中心真实数据自动生成。
3. 宽带窄栏固定左侧，网络设备在中轴单排，有线与无线终端分别位于上下区域。
4. 桌面端终端卡片可读，每排最多 5 张；网络设备卡片不会过大或过小。
5. WAN / PON 位于左边缘，下联网络设备接口位于右边缘，普通 LAN / 电口位于顶部，无线频段位于底部。
6. 节点一半嵌入卡片、一半位于卡片外，侧边节点外不显示端口文字。
7. 页面没有连接线、添加入口、拓扑编辑入口、空槽位或分区标题。
8. 关系条使用真实配对标识；关系条和接口节点均可触发双端高亮。
9. 桌面窗口不出现拓扑内部滚动条或无意义左右留白；窄屏不缩成不可读缩略图。
10. 定向测试、类型检查、生产构建和真实浏览器桌面 / 窄屏验证全部通过。
