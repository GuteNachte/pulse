# 资产严格类型模板与互联网接入资源设计

## 背景

Pulse 资产中心将按“一个典型资产确认一种严格类型模板”的方式逐类整理。每种类型由一台真实典型资产验证；模板确认后，同类型资产统一使用相同参数、输入方式、分组、列表摘要、详情布局、采集映射和资料完整度规则。单台资产只保存具体值与来源，不自行改变字段结构。

首个整理类型是 `internet`（互联网接入）。当前典型资产是中国联通家庭宽带。它是线路资源，不是物理设备；运营商光纤直接进入一台华为 iFTTR 主网关，但华为设备的 ONT 类型模板不在本轮实施范围内。

## 目标

- 建立代码版本化的严格类型规格中心，成为资产字段和展示的唯一规则源。
- 统一参数输入方式、采集来源、结构化拆解、显示范围和完整度语义。
- 将 `internet` 明确为线路资源，不再套用物理设备字段、接口和“硬件档案”布局。
- 准确区分运营商线路带宽、动态公网地址、真实设备接口速率和资产连接关系。
- 让现有联通宽带在列表、详情、编辑和拓扑关系中使用同一套已确认语义。

## 非目标

- 本轮不创建或整理华为 OptiXstar V271-20 的光猫 / ONT 类型模板。
- 本轮不录入下游终端与华为主网关之间的 LAN、Wi-Fi 关系。
- 本轮不建设数据库动态字段设计器或低代码模板配置页。
- 本轮不保存宽带账号、拨号密码、管理密码、Wi-Fi 密码或支付凭据。
- 本轮不删除历史 metadata；不再使用的字段只隐藏并保持读取兼容。

## 一、严格类型规格中心

每种资产类型只有一份权威规格。现有 `asset-profiles.ts`、`asset-schema.ts`、编辑分组和摘要逻辑向该规格收敛，列表、详情、编辑、导入导出、完整度、Agent 和资料补全不能各自维护另一套字段语义。

### 参数定义

每个参数至少定义：

- 稳定字段键、中文名称、分组和顺序。
- 输入模式、保存位置、单位和格式化规则。
- 固定选项或允许的数据来源。
- 是否允许人工确认和人工修正。
- 是否出现在列表、详情、编辑、导入与导出。
- 是否参与资料完整度。
- 采集原文如何拆解并映射到该参数。

### 五种输入模式

1. `manual_required`：手动必填，自由输入。
2. `manual_optional`：手动选填，自由输入。
3. `fixed_choice`：只允许预设项，不允许自定义。
4. `captured_candidate`：来自 Agent、官网、搜索、图片 OCR 或模型拆解；允许人工修正，修正后来源记为“手动确认”。
5. `not_applicable`：该类型没有该参数；列表和详情显示“无”或直接隐藏，不计入缺失项。

固定选择项必须由类型规格提供。采集或搜索候选不能因为置信度高就绕过字段白名单、类型校验和冲突检查。

## 二、采集数据识别与映射

采集准确性优先于页面展示。任何长字符串或复杂原文必须经过下面的链路：

`原始证据 → 对象识别 → 属性拆解 → 单位归一 → 交叉校验 → 参数映射 → 候选确认`

### 处理原则

- 原始证据完整保存，结构化拆解不能覆盖或丢弃原文。
- 先判断数据描述的是设备、CPU、内存条、硬盘、网卡、接口还是其他对象，再拆解品牌、型号、容量、地址、速率等属性。
- 容量、频率、速率、尺寸和日期先统一单位，再写入候选。
- 使用设备类型、总线类型、MAC、PCI 标识、磁盘信息和相邻字段交叉验证。
- Agent 返回的明确结构化数据经类型与格式校验后，可作为当前采集值显示。
- 搜索、图片 OCR、模型拆解、模糊原文和冲突数据只能生成候选，不能直接修改正式档案。
- 不确定结果进入“待确认原文”，不能猜测写入相似字段。
- 多块硬盘、多条内存、多张网卡等一对多数据保存为独立部件或接口记录，不拼成单个长摘要。
- 每个候选保留原文、来源、采集时间和可信状态；人工修正后，后续采集只能提出新候选，不能静默覆盖。

## 三、互联网接入资源边界

`internet` 是线路资源，不是硬件设备。

### 适用资料

- 名称、运营商、资产编号、线路状态和备注。
- 线路接入技术、联网认证方式、上下行带宽。
- 动态公网 IPv4、IPv6 及检测状态。
- 套餐、费用、周期、到期日期和自动续费。
- 指向首台真实接入设备及其 PON / WAN 接口的有方向关系。

### 不适用资料

- 位置、用途、颜色、厂商设备型号、序列号、尺寸和硬件规格。
- 物理网卡、网卡速率和接口管理。
- 设备购买资料、设备保修和 Agent 安装入口。

这些字段对互联网接入资源属于“不适用”，不得降低资料完整度。既有值保留在历史数据中，但不继续展示或编辑。

## 四、互联网接入字段规格

### 基础资料

| 参数 | 输入模式 | 规则 |
| --- | --- | --- |
| 资源名称 | 手动必填 | 当前可保留“宽带”；不由运营商强制改名 |
| 运营商 | 固定选择 | 仅中国电信、中国联通、中国移动；历史“联通 / 电信 / 移动”归一为完整名称 |
| 资产编号 | 现有编号控件 | 沿用自动编号和自定义编号能力 |
| 使用状态 | 固定选择 | 使用中、暂停服务、已注销；新建默认使用中 |
| 备注 | 手动选填 | 只记录非结构化补充说明 |

状态继续使用现有底层枚举，但 `internet` 使用资源专属文案：`active` 为“使用中”、`inactive` 为“暂停服务”、`retired` 为“已注销”。历史 `planned` 可读取，但不再作为互联网接入编辑选项。

### 线路参数

| 参数 | 输入模式 | 选项或规则 |
| --- | --- | --- |
| 线路接入技术 | 固定选择 | 家庭光纤宽带（FTTH）、专线、移动网络（4G / 5G） |
| 联网认证方式 | 固定选择 | PPPoE 拨号、DHCP / IPoE 自动获取、静态 IP |
| 下行带宽 | 手动必填 | 按 Mbps 保存；正数 |
| 上行带宽 | 手动必填 | 按 Mbps 保存；正数 |

线路带宽按易读单位展示：1000 Mbps 显示为 1 Gbps，300 Mbps 保持 300 Mbps。线路带宽不能写入 `asset_interfaces.speed_mbps`，也不能显示成网卡速率。

建议使用新字段 `access_technology` 和 `auth_mode` 分别表达线路技术与认证方式，避免继续让含义混杂的历史 `access_mode` 同时承担两种语义。历史 `access_mode` 只做兼容读取或迁移来源。

当前联通宽带已由用户确认：

- `access_technology = ftth`
- `auth_mode = pppoe`
- `down_mbps = 1000`
- `up_mbps = 300`

### 动态公网地址

| 参数 | 输入模式 | 规则 |
| --- | --- | --- |
| 公网 IPv4 | 采集候选 | 自动检测，可人工确认 |
| 公网 IPv6 | 采集候选 | 自动检测，可人工确认 |

检测策略：

- Hub 启动后检测一次。
- Hub 每 30 分钟检测一次所有使用中的互联网接入资源。
- 编辑页保留“立即刷新”。
- IPv4、IPv6 分别成功或失败，单协议失败不影响另一协议。
- 失败时保留该协议上一次成功值和错误摘要。
- 保存最近检测时间；只有地址真实变化时才写入地址变更历史，避免定时任务制造无意义变更记录。
- 页面显示当前值、最近检测时间和“动态地址”来源标识。
- 人工修正保存独立来源状态；后续自动值变化只生成待确认候选，不静默覆盖人工确认值。

现有 `public_ipv4`、`public_ipv6`、`public_ip_checked_at` 和协议错误字段继续复用；实现计划需补充来源状态和地址变化记录的具体存储方式。

### 套餐与续费

| 参数 | 输入模式 | 选项或规则 |
| --- | --- | --- |
| 套餐名称 | 手动选填 | 例如“联通千兆融合套餐” |
| 套餐费用 | 手动选填 | 人民币数值 |
| 计费周期 | 固定选择 | 月付、季付、半年付、年付 |
| 到期日期 | 手动选填 | 只使用日期控件，不显示来源箭头 |
| 自动续费 | 固定选择 | 是、否 |

新增 `package_name` 和 `auto_renew`。现有 `recurring_price_cny`、`billing_cycle`、`renewal_date` 继续复用；`billing_cycle` 对互联网接入不再显示“按量计费”和“免费 / 无续费”。当前典型资产已有月付 165 元和到期日期，原值保持。

## 五、接口与接入关系

互联网接入资源没有物理接口：

- 不创建 `asset_interfaces` 记录。
- 详情标题栏隐藏“接口”操作。
- 列表“网卡速率”显示“无”。
- 编辑工作台不显示网卡管理区。

宽带使用一条有方向的当前“外网接入”关系：

`互联网接入 → 首台真实设备的 PON / WAN 接口`

关系规则：

- 使用现有 `connected_to` 关系，并以 `link_kind = internet` 表达外网链路。
- 宽带作为 source，不设置 `source_interface`。
- target 必须是光猫 / ONT、路由器或网关。
- target interface 必须是 PON 或 WAN 语义的真实接口。
- 一条宽带同时只允许一个当前接入目标。
- 更换目标时更新当前关系，并把变化写入资产变更记录。
- 未录入目标设备时允许保存宽带，但显示“待关联接入设备”。
- 接入关系参与完整度。
- 拓扑方向固定从互联网接入指向内网设备。

现有接口类型需要支持准确的 PON 语义；实现计划应评估新增 `pon` 接口种类，不能用普通以太网伪装光纤 PON。华为设备的完整接口清单仍留到 ONT 类型模板轮次处理。

## 六、页面与交互

### 资产列表

- 编号：现有资产编号。
- 资产：资源名称，次级信息显示完整运营商名称。
- 位置：显示“无”。
- IPv4：显示当前公网 IPv4，没有成功值时显示“未获取”。
- 网络接入方式：主行显示“家庭光纤宽带”；次行显示“PPPoE · 下行 1 Gbps / 上行 300 Mbps”。
- 网卡速率：显示“无”。
- 状态 / 资料：显示资源状态和资料完整度。

### 资产详情

- 标题区保留名称、编号、互联网接入类型和资源状态。
- 不显示位置、用途和颜色标签。
- 运营商 Logo 可继续作为资源封面。
- “硬件档案”改为“线路档案”。
- 内容分为基础资料、线路参数、动态公网地址、套餐与续费、接入关系、备注。
- 隐藏接口操作；关系操作可使用“接入关系”语义。

### 资产编辑

- 分组顺序：基础资料、线路参数、动态公网地址、套餐与续费、接入关系、备注。
- 固定选择不提供自定义输入。
- 上下行带宽使用带 Mbps 单位的数字控件。
- 公网地址以只读采集状态为主，同时提供刷新和人工确认入口。
- 到期日期只保留日期选择按钮，不显示候选来源箭头。
- 不显示位置、用途、物理接口和硬件资料。

## 七、资料完整度

以下内容必须齐全：

- 资源名称。
- 运营商。
- 使用状态。
- 线路接入技术。
- 联网认证方式。
- 上、下行带宽。
- 当前接入关系。

以下内容不参与完整度：

- 位置、用途、硬件资料和物理接口。
- 动态公网 IPv4、IPv6；检测失败不视为主档缺失。
- 套餐、续费、到期日期、自动续费和备注。

关系尚未建立时，宽带可以保存，但资料状态明确显示“待关联接入设备”。

## 八、现有数据兼容

当前典型宽带按以下方式收敛：

- “联通”归一显示并保存为“中国联通”。
- `status = active` 显示为“使用中”。
- 现有上下行、公网地址、续费价格、计费周期和到期日期原样保留。
- 写入已确认的 FTTH 与 PPPoE 值。
- 套餐名称和自动续费保持未填，不猜测。
- 当前没有华为光纤网关资产记录，关系保持为空并显示待关联。
- 既有位置、用途、硬件或接口兼容数据不删除，但从互联网接入页面隐藏。
- 已有运营商 Logo 和封面关系保持不变。

## 九、错误与降级处理

- 类型规格不能识别字段时，保留历史值并显示可诊断日志，不把值移动到相似字段。
- 公网检测失败按协议独立降级，不清空成功值。
- 定时检测任务失败不能阻断 Hub 或资产页面。
- 关系目标或接口被删除后，宽带显示“接入关系失效”，并重新进入待补状态。
- 固定选择遇到历史未知值时，以只读兼容值显示；用户编辑时必须选择当前有效项。
- 任何自动采集和迁移都不能写入模板白名单之外的字段。

## 十、验收标准

### 规则测试

- 类型规格只有一个字段来源，列表、详情、编辑和完整度读取同一语义。
- 五种输入模式、固定选项和不适用规则有直接回归测试。
- 运营商历史别名、状态专属文案、单位格式和旧 metadata 兼容有回归测试。
- `internet` 不生成接口、不显示接口操作，网卡速率稳定显示“无”。
- 关系仅允许一个当前目标并要求真实 PON / WAN 接口。

### Hub 测试

- 启动检测、30 分钟调度、手动刷新和只处理使用中宽带均有测试。
- IPv4、IPv6 部分失败保留上次成功值。
- 只有地址变化才写变更记录；人工确认值不会被自动任务静默覆盖。
- 保存和导入拒绝模板外字段、无效固定选项和非正数带宽。

### 浏览器验收

- 桌面与窄屏列表字段对齐，无横向溢出。
- 详情显示“线路档案”，不出现硬件、位置、用途或接口入口。
- 编辑控件类型、分组和顺序符合本设计。
- 公网地址可刷新并显示检测状态。
- 没有目标设备时显示待关联；后续录入目标后可选择真实 PON / WAN 接口。
- 浏览器控制台无相关错误或框架覆盖层。

## 十一、后续类型梳理流程

每种类型使用固定状态：

`待梳理 → 规格确认 → 识别规则确认 → 实施中 → 浏览器验收 → 已锁定`

每轮读取一台典型资产的现有档案与采集原文，确认字段、输入模式、拆解规则、显示范围和完整度，然后一次性实施到所有相关链路，并用另一台同类型资产证明规则属于类型模板。特殊设备字段只有在用户明确提出后才扩展，不自动污染整类模板。
