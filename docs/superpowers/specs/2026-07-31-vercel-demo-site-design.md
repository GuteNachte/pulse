# Pulse Vercel 公开演示站设计

## 状态

- 方案：已确认采用前端静态演示模式。
- 托管：Vercel。
- 数据：独立虚构数据，不复制、脱敏或转换任何真实实例数据。
- 目标：提供可公开访问、可交互、可重复截图的 Pulse 产品演示环境。

## 目标

1. 外部用户打开演示地址后，无需登录即可看到 Pulse 的真实界面和主要工作流。
2. README、文档和社交素材从同一个演示站自动生成，避免宣传图与当前产品不一致。
3. 演示构建不连接 Hub、Agent、飞牛、私人 Gitea、Harbor 或家庭网络。
4. 正式构建不包含演示数据，不改变现有认证、采集、写入和部署行为。

## 非目标

- 不在 Vercel 运行 PocketBase、SQLite、WebSocket 或 Agent。
- 不模拟真实硬件采集、容器控制、网站检测、备份恢复和用户管理写入。
- 不把演示站作为生产实例、性能基准或兼容性证明。
- 首期不覆盖全部设置页和所有边缘状态。

## 方案选择

### 采用：现有前端 + MSW 浏览器模拟

Vercel 只发布 `internal/site` 的静态构建。构建变量 `VITE_PULSE_DEMO=1` 启用演示模式；应用启动前加载 Mock Service Worker，拦截 PocketBase REST 请求并从版本化虚构数据集中返回响应。

页面继续使用现有路由、页面容器、领域逻辑和视觉组件。演示层只替代外部数据和运行环境，不另做一套营销式仿制页面。

选择该方案的原因：

- 相比单独制作静态页面，界面与正式产品一致，截图可长期复用。
- 相比云端部署完整 Hub，不需要数据库、长期凭据、持久卷或公网管理入口。
- 相比在每个页面手工注入数据，API 边界更集中，对正式代码侵入更小。
- MSW 是成熟的请求模拟工具，适合浏览器演示和自动化测试共用同一批 handlers。

## 架构

### 构建入口

- 正式构建：保持当前 `npm run build` 行为。
- 演示构建：新增 `npm run build:demo`，以 `VITE_PULSE_DEMO=1` 构建。
- Vercel 项目根目录保持在公开仓库，输出目录指向 `internal/site/dist`。
- `vercel.json` 负责构建命令、静态输出、SPA fallback 和安全响应头。

### 演示运行时

新增独立目录 `internal/site/src/demo/`：

- `mode.ts`：唯一的演示模式判断入口。
- `fixture.ts`：类型化的虚构家庭数据。
- `handlers.ts`：PocketBase REST 和 Pulse 自定义 API 的只读响应。
- `browser.ts`：启动 MSW Worker，并在完成后进入 React 渲染。
- `auth.ts`：创建本地演示用户身份，不保存真实凭据。
- `write-guard.ts`：统一阻止 POST、PATCH、PUT、DELETE 和危险自定义动作。

应用入口在演示构建中执行以下顺序：

1. 清理可能残留的真实 PocketBase 登录信息和已保存 Hub 地址。
2. 写入固定的演示管理员身份，仅用于通过前端认证门槛。
3. 启动 MSW，并确认关键 handler 已注册。
4. 跳过实时订阅和移动端 Hub 探测。
5. 渲染现有 Pulse 应用。

正式构建不导入演示 fixture 和 handlers，构建检查需要验证演示数据不会进入正式产物。

### 数据流

```text
浏览器路由
  -> 现有 Pulse 页面和数据加载逻辑
  -> PocketBase JS SDK / Pulse API 请求
  -> MSW handlers
  -> 虚构 fixture
  -> 现有页面组件渲染
```

演示站不向外发送业务 API 请求。安全响应头将 `connect-src` 限制为自身，外部图片也只允许仓库内静态资源。

## 虚构数据规范

演示家庭固定包含：

- 一条互联网接入线路。
- 家庭网主网关、交换机、无线接入点和 NAS。
- 一台 Windows 客户端、一台 Linux 服务器、手机和平板。
- 科技网路由器、实验服务器和容器服务。
- 智能灯、传感器和其他智能家居资产。
- 三个互联网服务监控目标。
- 正常、警告、离线三类状态和一组可解释的历史指标。

数据约束：

- 管理地址统一使用 `192.168.50.0/24`。
- 文档公网 IPv4 使用 RFC 5737 保留地址段。
- 域名统一使用 `example.com` 子域。
- MAC 使用本地管理地址，首字节固定为 `02`。
- 用户、设备、位置和服务名称均为虚构名称。
- 图片使用 Pulse 自带图标或明确可公开分发的通用素材。
- 不包含真实序列号、账号、邮箱、Token、日志、备份、图片文件名和家庭拓扑。

fixture 需要通过自动测试验证保留网段、域名、MAC、唯一 ID、关系完整性和禁止词扫描。

## 首期演示范围

首期支持以下可直接访问路由：

- `/`：双网络概览和主要运行状态。
- `/assets`：资产中心。
- `/assets/:id`：典型网络设备、服务器和智能设备详情。
- `/network/home`：家庭网络拓扑。
- `/network/technology`：科技网拓扑。
- `/clients`：客户端监控。
- `/containers`：容器监控。
- `/websites`：互联网服务监控。
- `/settings/backups`：备份能力展示。
- `/settings/about`：版本与项目说明。

资产搜索、筛选、详情切换、拓扑缩放和页面导航可以交互。所有创建、编辑、删除、立即检测、控制、恢复和用户管理操作统一不可执行。

## 只读交互

- 导航栏显示紧凑的“公开演示”状态标识。
- 被禁用的写入按钮仍可用于说明功能，但点击只显示统一提示：演示数据不会被修改。
- 不让前端产生看似成功但刷新后消失的假写入。
- 对不可模拟的运行能力展示清晰的演示状态，不伪装成真实 Agent 连接。
- 演示站提供“查看 GitHub”和“下载测试版”入口，不增加营销落地页。

## Vercel 配置

- 项目建议名：`pulse-demo`。
- 建议公开地址：`https://pulse-demo.vercel.app`；最终以 Vercel 可用项目名为准。
- Framework Preset：Vite。
- 安装目录：`internal/site`。
- 构建命令：`npm run build:demo`。
- 输出目录：`internal/site/dist` 或在项目 Root Directory 为 `internal/site` 时使用 `dist`。
- 所有应用路由回写到 `index.html`，静态资源保持长期缓存并带内容哈希。
- 不配置数据库、外部 API、运行时密钥或生产 Hub 地址。
- 首次先创建 Preview Deployment；验证通过后再提升为公开 Production Deployment。

Vercel CLI 登录、项目 ID 和 Token 只保存在本机或 GitHub Secrets，不提交 `.vercel/` 和环境变量文件。

1. 首页双网络概览。
2. 资产中心。
3. 典型资产详情。
4. 家庭网络拓扑。
5. 科技网拓扑。
6. 客户端监控。
7. 容器监控。

GitHub Social Preview 使用独立的 `1280x640` 封面，不直接裁切包含大量小字的页面截图。

## 测试与验收

### 单元与契约测试

- fixture 的隐私和引用完整性测试。
- PocketBase 列表、单条、分页、筛选和排序响应契约测试。
- 所有写入方法返回只读拒绝结果。
- 正式构建不包含演示 fixture 中的标记字符串。
- Vercel 配置、SPA fallback 和安全响应头测试。

### 浏览器验收

- 桌面、平板、手机主要路由无白屏、无重叠、无横向溢出。
- 页面刷新和深链接可以直接打开。
- 浏览器控制台无未处理错误。
- 网络面板不存在对飞牛、局域网、私人域名或真实 Hub 的请求。
- 写入操作不会改变演示数据。
- 自动截图与手工隐私复核全部通过。

### 发布门槛

- `npm test`、`typecheck`、演示构建、正式构建和公开仓库审计通过。
- `docs/release-notes-next.md` 与 About 页按端记录本次演示站和部署变化。
- Preview Deployment 验证通过后才能提升为公开 Production Deployment。
- README 链接和截图只在 Production URL 稳定后更新。

## 错误处理

- MSW 未启动时显示明确的“演示数据初始化失败”，不回退请求真实 `/api`。
- fixture 缺失记录时返回可诊断的 404/空列表，不静默访问其他地址。
- 未覆盖的请求在开发和测试中作为错误处理，在公开演示中显示受控空状态。
- Vercel 部署失败时保留上一个生产部署，不直接覆盖可用版本。

## 风险与控制

| 风险 | 控制 |
| --- | --- |
| 真实资料混入 fixture 或截图 | 独立手写数据、保留网段校验、禁止词扫描、人工复核 |
| 演示代码影响正式运行 | 编译时模式隔离、正式构建排除测试、双构建验证 |
| 页面改动导致演示接口漂移 | API 契约测试、主要路由 Playwright 验收 |
| 用户误以为演示状态是真实采集 | 明确演示标识、只读提示、能力边界说明 |
| 演示站被用作写入或攻击入口 | 无后端、无凭据、拒绝写入、同源连接限制 |
| Vercel 项目或账号配置丢失 | 配置入库、CLI 可复现部署、生产版本可回滚 |

## 实施顺序

1. 建立演示模式、fixture 契约和写入保护。
2. 打通认证、系统、资产和拓扑的读取链路。
3. 补齐客户端、容器、网站和备份演示响应。
4. 完成演示模式 UI 标识、错误状态和深链接。
5. 增加 Vercel 配置并完成本地双构建验证。
6. 创建 Vercel Preview Deployment 并执行浏览器验收。
7. 生成截图和 Social Preview，完成隐私复核。
8. 更新中英文 README、仓库元数据和发布记录。
9. 提升为 Production Deployment，并把演示地址写入 GitHub Homepage。

## 完成标准

- 公开演示地址无需账号即可访问。
- 首期路由全部来自现有 Pulse 界面并使用虚构数据。
- 演示站不依赖任何真实后端、密钥和私人基础设施。
- 正式 Pulse 构建和运行行为不变。
- 自动生成并审核至少六张公开截图。
- README、GitHub Homepage、Release 和项目说明能够引导用户进入演示、下载和反馈入口。
