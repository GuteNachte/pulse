# 光猫 / ONT 严格模板与 iFTTR 主网关设计

## 背景

Pulse 已将中国联通家庭宽带整理为首个严格类型模板。下一台典型资产是中国联通安装的华为 iFTTR 主网关：Huawei OptiXstar V271-20。它既是 10G-EPON ONU，也承担家庭主路由、主网关、DHCP、Wi-Fi 和有线接入能力，不能按普通路由器或仅桥接光猫处理。

本轮继续采用“一个典型资产确认一种严格类型模板”的方式整理 `ont`（光猫 / ONT）。同类型资产使用同一字段结构、输入方式、分组、接口语义、关系统一规则和资料完整度规则；具体设备只保存字段值与来源，不能自行改变模板。

## 已确认事实

- 资产类型：`ont`，中文显示“光猫 / ONT”。
- 工作角色：iFTTR 主网关。
- 厂商：华为。
- 产品系列：Huawei OptiXstar。
- 型号：V271-20。
- 运营商：中国联通。
- 设备形态：10G-EPON ONU、主路由、主网关、DHCP、Wi-Fi 一体设备。
- 位置：`家 / 弱电箱`。
- 状态：使用中。
- 管理地址：`192.168.1.1`。
- 无线标准：Wi-Fi 7。
- 5 GHz Wi-Fi：启用。
- 2.4 GHz Wi-Fi：未启用。
- 有线接口：1 个 2.5GbE LAN、3 个 1GbE LAN。
- 当前接线：2.5GbE LAN 已接交换机；3 个 1GbE LAN 未接线。
- 其他能力：下联光口、USB、电话接口、WPS、指示灯、无线控制、复位与电源控制。
- 电源规格：DC 12V / 2A。
- 外观颜色：白色。
- 生产日期：2024 年 11 月。
- Redmi K50 当前通过 5 GHz Wi-Fi 连接主网关。

铭牌中的产品编号、PON SN、设备序列号与 MAC 可作为本地设备身份参数保存。管理密码、Wi-Fi 名称、Wi-Fi 密码、二维码登录凭据和其他认证秘密即使能够识别也不得写入资产库、日志、版本记录或测试夹具。

## 目标

- 将 `ont` 从通用网络设备字段集合升级为代码版本化的严格类型规格。
- 在不新增过细资产类型的前提下，准确表达桥接光猫、光猫路由一体机和 iFTTR 主网关。
- 统一列表、详情、编辑、导入导出、资料完整度、资料补全、接口和关系使用的字段语义。
- 准确区分设备能力、接口启用状态、物理接线状态和资产关系。
- 以真实接口连接宽带、交换机和已建档无线终端，不创建假设备或占位关系。

## 非目标

- 本轮不整理交换机严格类型模板，不猜测交换机型号或上联接口名称。
- 本轮不接入运营商远程管理、TR-069、SNMP 或设备后台自动采集。
- 本轮不保存管理密码、Wi-Fi 密码、宽带账号或其他认证凭据。
- 本轮不根据相似型号猜测照片和可信资料中无法确认的无线速率、空间流、天线数量或光功率范围。
- 本轮不把 USB、电话、电源、按钮伪装成网络拓扑接口。

## 模块归属与代码边界

本功能属于必需模块 `asset-center`，不新增大模块，也不新增模块开关。关闭其他可选模块不会影响 ONT 主档、接口和关系数据；网络拓扑只消费资产中心已经确认的真实数据。

前端严格规格继续位于 `internal/site/src/modules/asset-center`。实施时应建立单一 `ont` 规格源，并让以下能力从该规格派生：

- 创建与编辑字段。
- 详情参数分组。
- 列表摘要与资料完整度。
- 导入导出字段。
- 资料补全白名单和候选映射。
- Hub 保存校验与兼容边界。

现有 `asset-profiles.ts`、`asset-schema.ts` 和通用网络设备字段不应继续为 `ont` 各自维护另一套字段语义。

## 类型与工作角色

资产类型保持 `ont`。新增固定选择字段 `operating_role`，只允许：

- `bridge_ont`：桥接光猫。
- `router_ont`：光猫路由一体机。
- `ifttr_main_gateway`：iFTTR 主网关。

当前典型资产固定选择 `ifttr_main_gateway`。工作角色不能自由输入。所有 ONT 使用同一模板；特定角色当前未启用或不适用的能力使用“未启用”或“无”，不通过删除字段改变模板结构。

- 使用状态。
- 位置。
- 厂商。
- 产品系列。
- 型号。

### 光纤接入

- ONU 类型。
- PON 标准。
- PON 上联能力。
- 光纤连接器类型；无法从可信来源确认时保持未确认。
- 下联光口数量。
- 下联光口状态。

### 路由与管理

- 主路由状态。
- 主网关状态。
- DHCP 状态。

- 管理 URL，由管理地址规范化生成或手工确认。

### 无线网络

- 5 GHz 支持状态。
- 5 GHz 启用状态。
- WPS 支持状态。

无线状态只显示“启用 / 未启用”，不在参数或接口状态中追加“手机连接中”。终端连接只进入资产关系。

### 有线网络

- LAN 总数。
- 2.5GbE LAN 数量。
- 1GbE LAN 数量。
- 各真实 LAN 的速率与接线状态。

### 其他端口与电源

- USB 数量。
- 电话接口数量。
- 电源规格。
- 指示灯控制。
- 无线 / WPS 控制。
- 复位能力。
- 电源开关。

这些字段是硬件能力，不进入网络拓扑接口。

### 设备身份标识

- 产品编号。
- PON SN。
- 设备序列号。
- MAC。
- 无线电型号核准编号；只在铭牌明确且确有维护价值时保存。

身份标识在详情页使用普通参数显示，不进入列表主摘要；导出时保留，页面不得把它们与密码一起归类或自动复制。

## 输入方式与来源

- 工作角色、运营商、接口启用状态和支持状态使用固定选择，不能自定义。
- 端口数量、端口速率、Wi-Fi 7、10G-EPON、电源规格和生产日期可从设备照片或可信厂家 / 运营商资料生成候选，由用户确认后写入。
- 管理地址、位置、当前启用状态、接线状态和关系属于当前家庭部署事实，优先手工确认，不由官网规格覆盖。
- 产品编号、PON SN、设备序列号和 MAC 可从设备铭牌识别；保存前需要通过格式检查。
- 无法确认的字段保持“未确认”，不从相似型号或搜索摘要推断。
- 任何密码、密钥、二维码凭据或宽带认证数据在识别阶段即丢弃，不能成为候选。

## 真实接口模型

网络拓扑接口只包含能承载网络连接的真实接口：

- `PON 上联`：种类 `pon`，角色 `uplink`，技术 `10G-EPON`。
- `下联光口`：新增通用光纤接口语义 `optical`，角色 `downlink`。
- `LAN 1`：种类 `lan`，速率 2500 Mbps，已接线。
- `LAN 2`：种类 `lan`，速率 1000 Mbps，未接线。
- `LAN 3`：种类 `lan`，速率 1000 Mbps，未接线。
- `LAN 4`：种类 `lan`，速率 1000 Mbps，未接线。
- `2.4 GHz Wi-Fi`：种类 `wifi`，支持但未启用。
- `5 GHz Wi-Fi`：种类 `wifi`，启用。

接口需要分别表达：

- `enabled`：该接口当前是否启用。
- `connected`：该物理接口当前是否接线或该无线网络是否承载连接。
- `speed_mbps`：只在照片或可信资料明确时填写。
- `metadata.role`：uplink、downlink、lan 或 radio。
- `metadata.band`：仅 Wi-Fi 使用 2.4 GHz 或 5 GHz。
- `metadata.connection_note`：目标资产尚未建档时可写中性说明，不创建假关系。

USB、电话、电源、指示灯、按钮和复位不进入 `asset_interfaces`。

## 资产关系

### 宽带到主网关

- source：当前中国联通宽带资产。
- target：华为 iFTTR 主网关资产。
- kind：`connected_to`。
- link kind：`internet`。
- target interface：`PON 上联`。

该关系替换宽带当前的“待关联接入设备”，并参与宽带资料完整度。

### 主网关到交换机

照片和用户确认表明 `LAN 1（2.5GbE）` 已连接交换机。交换机尚未建档，因此本轮只把 LAN 1 标记为已接线，并显示“交换机（待建档）”。不创建占位交换机，不创建无 target 的关系。交换机完成严格模板和真实建档后，再建立主网关 LAN 1 到交换机上联口的正式关系。

### 手机到主网关

- source：Redmi K50 资产。
- target：华为 iFTTR 主网关资产。
- kind：`connected_to`。
- link kind：`wifi`。
- target interface：`5 GHz Wi-Fi`。

手机连接信息只显示在关系区域。5 GHz 接口本身只显示启用状态；2.4 GHz 接口显示未启用。

Hub 必须拒绝把无线关系连接到未启用的 Wi-Fi 接口，也必须拒绝把互联网接入关系连接到非 PON / WAN 上联接口。

### 资产详情

- 其他端口与电源。
- 设备身份标识。

接口和关系继续使用详情标题栏现有入口，不在参数卡片中重复渲染完整接口和关系列表。

### 编辑工作台

- 工作角色、2.4 GHz 状态和 5 GHz 状态使用固定下拉选择。
- 型号规格候选按照片 / 可信资料来源展示，确认后才写入。
- 当前部署字段与型号规格字段分组显示，避免官网资料覆盖家庭实际配置。
- 接口管理区显示真实网络接口、速率、启用状态、接线状态和关系目标。
- 保存时 Hub 按 ONT 严格白名单、固定选项和接口规则二次校验。

## 兼容与错误处理

- 历史 `ont` metadata 原样保留；新模板不认识的字段只读兼容，不能继续新增或修改。
- 缺少值时显示“未确认”；明确不适用时显示“无”；能力存在但关闭时显示“未启用”。三种状态不能混用。
- 接口目标未建档时允许保存真实接线状态，但不能创建无目标关系。
- 接口、关系或主档保存失败时保留当前编辑草稿，显示具体错误，不清空已确认数据。
- 图片和铭牌识别不得把密码或二维码凭据写入日志、候选、测试快照和版本说明。
- 只有地址、接口或关系真实变化时才写入资产变更记录。

## 初始数据落地

实施阶段创建真实的华为 iFTTR 主网关资产，并保存已确认参数、接口和两条可立即建立的关系：宽带到 PON 上联、Redmi K50 到 5 GHz Wi-Fi。交换机关系等待真实交换机资产建档后补齐。

设备照片应通过现有本地媒体库上传和确认封面，不提交桌面原图或包含敏感铭牌信息的文件到 Git 仓库。封面如包含铭牌区域，应先裁剪到设备正面外观，避免把登录凭据带入展示图。

## 测试与验收

### 自动测试

- ONT 严格规格字段、分组、固定选项和资料完整度契约。
- Hub ONT metadata 白名单、固定选项、身份格式与秘密字段拒绝测试。
- 接口种类、enabled / connected 状态和端口速率测试。
- 宽带只能连接 PON / WAN 上联接口的关系测试。
- Wi-Fi 关系不能连接未启用无线接口的测试。
- 列表摘要、详情分组和编辑字段来源一致性测试。
- 导入导出和资料补全不能产生模板外字段或密码字段的测试。

### 浏览器验收

- 列表、详情和编辑显示同一型号、角色、位置、接口状态和关系。
- 5 GHz 显示启用，2.4 GHz 显示未启用；接口卡不显示“手机连接中”。
- 关系区域显示 Redmi K50 连接 5 GHz Wi-Fi。
- 宽带不再显示“待关联接入设备”，而是指向主网关 PON 上联。
- LAN 1 显示 2.5GbE、已接线、交换机待建档；LAN 2 / 3 / 4 显示 1GbE、未接线。
- 桌面与 390 × 844 移动视口无横向溢出、遮挡、错误叠层或不可读长值。
- 控制台无相关 warning / error。

### 完整验证

- 前端 ONT 定向契约测试。
- `npm run test`、`npm run typecheck`、`npm run build`。
- Hub 相关定向测试与完整 `go test -tags=testing ./internal/hub ./internal/migrations -count=1`。
- 源码预览 Hub `8090` 与 Vite `5173` 端到端验收。

## 后续可复用规则

- 一体设备仍归属最基础的硬件类型，通过固定工作角色表达部署职责，不为每个运营商套餐新增资产类型。
- 能力、启用状态、接线状态和资产关系分层保存，页面不把它们合并为一句模糊描述。
- 只有真实网络接口进入拓扑；其他物理端口属于硬件参数。
- 未建档目标使用中性待建档说明，不创建占位资产或假关系。
- 照片可以补全设备事实，但任何凭据必须在识别入口丢弃。
