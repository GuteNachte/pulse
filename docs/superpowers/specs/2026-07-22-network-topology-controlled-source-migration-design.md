# 网络拓扑受控源码移植设计

## 1. 目标

将 Pulse 的网络拓扑页重构为面向家庭网络和科技网的专用拓扑工作台，并采用 Homelable 已验证的拓扑编辑能力作为源码基础。

最终用户只看到一套 Pulse 网络拓扑系统：

- 设备、网口、真实关系、状态和权限继续由 Pulse 管理。
- 画布支持自由拖动、四边连接、手工理线、撤销重做和独立网络页面。
- 家庭网络与科技网分别保存，不再把两套网络堆在同一张画布上。
- 不自动伪造设备关系，不复制第二套资产数据库。

本设计取代此前“固定四列分层矩阵”作为网络拓扑工作台的视觉和交互方案。矩阵分类可以继续作为自动整理和诊断逻辑使用，但不再限制用户的自由布局。

## 2. 范围

### 包含

- `/network/home`：家庭网络拓扑。
- `/network/technology`：科技网拓扑。
- `/network`：进入上次访问的网络页面；首次进入默认家庭网络。
- 节点自由拖动、网格吸附和对齐辅助线。
- 每张节点卡片上、下、左、右四个连接点。
- 网线、无线、光纤三类链路的不同路径、端点和标签表现。
- 选中链路后增加、移动、删除折点。
- 从拖线流程中选择双方真实设备、真实网口、网络域和连接介质。
- 节点和链路的详情、编辑、删除、重连、撤销和重做。
- 家庭网络与科技网独立保存节点位置、折点和视口。
- 保存失败、远端冲突、缺失设备、缺失网口和只读权限处理。
- 资产中心现有 `assets`、`asset_interfaces`、`asset_relations`、`network_layouts` 数据复用。

### 不包含

- Homelable 的后端、扫描器、设备认领队列和独立数据库。
- Proxmox、Zigbee、Z-Wave 导入。
- 新增 SNMP、LLDP、实时交换机端口采集或自动网络发现。
- 移动端专门页面。
- 删除资产主档；资产删除仍在资产中心执行。
- 将拖动节点位置解释为真实网络关系变化。
- 使用第二个拓扑数据库或把视觉草稿当成真实关系。

## 3. 核心架构

### 3.1 受控源码移植

移植 Homelable 的拓扑编辑内核，不移植完整应用。固定来源为：

- 项目：`https://github.com/Pouzor/homelable`
- 版本：`v3.1.1`
- 源码基准提交：`d9f3b4c18ab8adb1be742abd45806e6bb302dbce`
- 许可证：MIT

移植并按 Pulse 目录重构的能力：

- 四边端点与端口规则。
- 节点拖动、网格吸附、对齐辅助线。
- 链路绘制、链路样式、折点添加 / 拖动 / 删除。
- 节点移动时折点跟随。
- 选择、布局删除、撤销和重做的最小状态能力；不复制真实资产节点。
- 画布序列化、反序列化及相关测试。

不移植的能力：

- Homelable 后端和 API。
- nmap 扫描、待认领设备和设备库存。
- Proxmox、Zigbee、Z-Wave、容器导入。
- Homelable 自己的资产、用户、权限、监控和主题模型。
- 楼层底图、霓虹主题和与 Pulse 视觉规范无关的装饰能力。

根目录新增第三方来源说明，记录上游 URL、版本、提交、许可证、实际移植文件和后续同步规则。后续只挑选上游修复，不自动合并上游业务代码。

### 3.2 Pulse 模块边界

建议目录：

```text
internal/site/src/modules/network-topology/
  canvas-core/
    handles/
    edges/
    waypoints/
    history/
    serialization/
  pulse-adapter.ts
  workspace-state.ts
  topology-domain.ts
  components/
  tests/
```

职责：

- `canvas-core`：纯画布能力，不读取 PocketBase，不理解 Pulse 资产类型。
- `pulse-adapter`：将资产、网口、关系和系统状态转换成画布节点 / 边。
- `workspace-state`：管理当前网络页面、草稿、保存状态、冲突状态和撤销队列。
- `topology-domain`：网络域、链路介质、上联 / 下联、诊断和关系合法性。
- `components`：工具栏、节点、边、详情 Sheet、连接配置 Sheet。
- `tests`：领域纯函数、适配器、序列化和浏览器交互测试。

不把 Homelable 的千行 `canvasStore` 原样复制为新全局状态仓库。只保留当前需求所需的节点、边、折点和历史操作，并让 Pulse 的数据适配层成为唯一外部入口。

## 4. 数据模型

### 4.1 真实数据

继续使用现有集合：

- `assets`：设备和网络资源主档。
- `asset_interfaces`：设备真实网口、无线接口、光口和管理口。
- `asset_relations`：真实资产关系。
- `network_layouts`：用户画布布局和视口。

拓扑页面不写入旧的 `network_devices`、`network_ports`、`network_links`。

### 4.2 关系元数据

新建或编辑网络关系时，在 `asset_relations.metadata` 中保存：

```ts
{
  network_domain: "home" | "technology",
  link_kind: "ethernet" | "wifi" | "fiber",
  source_interface: "asset_interface_xxx",
  target_interface: "asset_interface_yyy"
}
```

字段语义：

- `network_domain`：关系所属拓扑页面。
- `link_kind`：视觉和诊断使用的连接介质；旧值 `internet` 继续兼容并按光纤 / PON 上游关系显示。
- `kind` 仍使用现有关系类型，例如 `connected_to`。
- `source_interface` 和 `target_interface` 保存真实双方接口 ID；不使用视觉节点 ID 代替资产 ID。

同一设备可以因为多张关系出现在两个网络页面，例如多网卡或跨网络设备。单独没有关系的资产由资产中心管理，不自动出现在拓扑页面中，除非用户将其加入当前画布草稿。

### 4.3 布局版本

继续使用 `network_layouts`，通过 `key` 拆分两个工作区：

- `network-home`
- `network-technology`

布局 JSON 使用版本 2：

```ts
{
  version: 2,
  nodes: {
    "asset_xxx": { "x": 320, "y": 180 }
  },
  edge_waypoints: {
    "relation_xxx": [{ "x": 520, "y": 220 }]
  },
  viewport: {
    "x": 0,
    "y": 0,
    "zoom": 1
  }
}
```

选中对象、临时拖动状态、未保存草稿和折点编辑态不写入服务端布局。

旧版扁平布局读取时兼容 `nodes` 和 `viewport`，第一次保存时转换到对应的新 key，不删除旧数据。无法判断网络域的旧关系沿用当前兼容识别规则，并在编辑关系时要求补齐显式域标识。

## 5. 页面和视觉设计

### 5.1 页面骨架

页面不使用大面积背景卡或网络带。结构为：

1. 紧凑顶部工具栏。
2. 家庭网络 / 科技网页面切换。
3. 点阵网格画布。
4. 按需打开的右侧节点 / 链路详情 Sheet。

顶部工具栏包含：

- 页面标题和当前网络名称。
- 设备、链路、网口、无线等紧凑统计。
- 撤销、重做、自动整理、新增、保存。
- 未保存状态和保存失败提示。

默认画布锁定关系编辑之外的误操作；节点拖动和折点编辑在明确的编辑状态下启用。只读用户隐藏新增、连线、删除、重连和保存入口。

### 5.2 节点

节点使用 Pulse 现有设计语言，采用紧凑矩形卡片：

- 名称。
- 类型图标和短类型。
- 在线状态点（有 Agent 状态时）。
- 管理 IPv4（存在时）。
- 基础设施节点的已用 / 总网口数。

不把完整规格、IPv6、长备注和所有参数塞进卡片；详情 Sheet 展示完整信息。文本超长截断，Tooltip 展示完整值。

四个连接点使用中性小圆点，位置固定在卡片四边中点。连接点只表达可连接方向，不表达真实接口；真实接口在连接配置 Sheet 中选择。

### 5.3 链路

链路必须同时使用路径、线型、端点和标签区分：

- 网线：横平竖直直角实线，方形网口端点。
- 无线：平滑弧形短虚线，链路中部显示 Wi-Fi 标记。
- 光纤：双层平行线，圆形光口端点，中部显示“光纤”或 PON。

默认隐藏速率标签，悬停或选中链路时显示双方网口、介质和协商速率。选中链路增强描边和方向信息，其余链路降低对比度。默认不播放持续动画。

新链路先使用可读的默认路径；用户可以选中后增加、拖动和删除折点。节点移动时，已保存折点按节点位移同步，避免手工理线被拖散。

### 5.4 自动整理

“自动整理”只修改节点位置和必要的默认折点，不修改设备关系、接口、网络域和链路介质。执行后仍需用户点击保存，用户可以继续自由拖动。

## 6. 操作与数据流

### 6.1 新建连线

1. 用户从任一节点的四边连接点拖出临时连线。
2. 拖到目标节点后打开紧凑连接配置 Sheet。
3. 选择起点设备 / 真实接口、终点设备 / 真实接口、网络域和连接介质。
4. 若设备没有所需网口，提供“先去添加网口”的明确入口，不创建假接口。
5. 保存成功后创建 `asset_relations`；失败时保留本地草稿，不显示为已确认关系。

### 6.2 编辑、重连和删除

- 选中链路后可编辑双方接口、网络域、介质、方向标签和备注。
- 重连保存为现有关系更新，不创建视觉副本。
- 删除链路就是删除真实资产关系，必须二次确认。
- 删除设备不在拓扑页执行，跳转资产中心。
- 节点移动、折点修改和视口修改只改变布局，不改变真实关系。

### 6.3 详情

右侧 Sheet 分两种：

- 节点 Sheet：设备档案摘要、管理 IPv4、接口状态、上联 / 下联关系和资产中心入口。
- 链路 Sheet：两端设备、两端真实接口、网络域、介质、速率、方向、备注和编辑 / 删除入口。

左侧设备档案不混入接入关系；关系只在拓扑画布和右侧独立 Sheet 展示。

## 7. 保存、冲突和错误处理

### 7.1 保存边界

- 节点位置、折点和视口先进入当前工作区本地草稿。
- 点击“保存”后写入对应 `network_layouts` 记录。
- 真实关系在连接配置 Sheet 确认时单独写入或更新。
- 关系保存和布局保存分别显示结果，避免一个失败掩盖另一个成功。
- 保存期间禁用重复提交，按钮显示进行中状态。

### 7.2 保存失败

- 布局保存失败：保留本地草稿，显示“关系已保存，布局待重试”或“布局保存失败”。
- 关系保存失败：临时链路保持草稿态，不显示为已确认关系，提供重试和取消。
- 页面刷新前若有未保存草稿，弹出浏览器离开提示。
- 刷新远端数据时保留本地未保存改动，并要求用户保存或放弃。

### 7.3 冲突

加载布局时记录服务端 `updated` 时间。保存前重新读取记录：

- 未变化：正常覆盖更新。
- 已变化：不覆盖远端，打开冲突提示。
- 用户可选择读取远端，或保留本地草稿后重新保存。

节点位置按节点 ID、折点按关系 ID 管理，后续可以在冲突界面提供逐项合并；第一版至少保证不静默覆盖。

### 7.4 诊断状态

- 关系缺少设备：显示灰色占位端点并标记“设备待建档”。
- 关系缺少网口：显示警告端点并标记“网口待确认”。
- 没有上联或下联：保留节点，不伪造关系。
- 多个关系连接同一接口：标记接口冲突，不阻断其他关系渲染。
- 未知介质：使用中性虚线并标记“介质待确认”。

## 8. 测试与验收

### 8.1 单元测试

- 四边端点创建连接时方向和端点 ID 稳定。
- 折点新增、移动、删除和 45 度吸附。
- 节点移动后相关折点按位移同步。
- 节点、边、折点和视口序列化 / 反序列化。
- Pulse 资产、接口、关系映射为画布节点和边。
- `network_domain`、`link_kind`、`source_interface` 和 `target_interface` 的兼容读取和默认值。
- 旧版布局迁移到两个新 key。
- 缺失端点、接口冲突和未知介质诊断。
- 撤销、重做和本地草稿恢复。

### 8.2 浏览器验收

- `2494 × 1194`：工具栏、节点、端点、链路和 Sheet 不重叠。
- `1727 × 1272`：画布可平移缩放，长名称截断，右侧 Sheet 不挤压画布。
- 家庭网络和科技网页面独立打开、独立保存、独立恢复。
- 四个方向均可发起连线。
- 网线、无线、光纤无需依赖颜色即可区分。
- 新建、编辑、重连、删除和撤销均写入正确数据。
- 保存失败和远端冲突不丢本地草稿。
- 只读账号不显示修改入口。
- 深色 / 浅色主题下文本、端点和链路均可辨识。
- 控制台无 React、请求和序列化错误。

## 9. 实施顺序

1. 建立第三方来源说明，固定 Homelable 版本和移植清单。
2. 增加网络域和介质元数据的兼容读写测试。
3. 移植 `canvas-core` 的端点、边、折点、历史和序列化能力，先通过其纯函数测试。
4. 编写 Pulse 适配层和领域模型。
5. 接入紧凑节点、三类链路、自由拖动和手工理线。
6. 接入连接配置 Sheet、关系保存、重连、删除和错误状态。
7. 接入两个独立网络路由和布局 key。
8. 接入冲突提示、只读权限、自动整理和详情 Sheet。
9. 完成旧 `/network` 入口兼容跳转和首页只读入口调整。
10. 运行单元测试、类型检查、构建和浏览器验收。
11. 更新 `docs/release-notes-next.md`、设置页 About 版本记录和模块说明。

## 10. 完成标准

本设计的实施只有在以下条件同时满足时才算完成：

- 网络拓扑页面只使用 Pulse 的资产、接口、关系和布局数据。
- 家庭网络与科技网是两个可独立编辑和保存的页面。
- 用户可以自由拖动节点、从四边创建连接并手工整理折点。
- 正式连线全部绑定真实接口和真实资产关系。
- 保存失败、冲突、只读和缺失端点均有明确行为。
- 受控移植文件有来源、许可证和测试记录，不包含 Homelable 的重复后端业务。
- 自动化测试、类型检查、构建和桌面浏览器验收全部通过。
