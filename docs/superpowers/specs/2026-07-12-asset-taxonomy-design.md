# 资产分类与设备 Profile 设计规范

> 状态：已获用户确认的设计草案，进入实现前审阅。

## 目标

把资产中心从“平面类型 + 共用一套参数”调整为“资产大类 + 具体类型 + 设备 Profile + 采集 Profile”四层模型，使每种设备只展示与自身相关的参数，Agent 补全结果也能按类型准确落位。

产品定位保持为家庭资产管理与监控。资产中心继续是主数据源，监控、网络拓扑、告警、智能家居和 Agent 只消费或补充已经确认的资产档案。

## 当前实现盘点

当前 `asset-schema.ts` 提供网络、主机、移动 / 物联、娱乐、电源 / 外设、智能家居、服务和其他分组；`AssetType` 还保留 `vm`，但类型选择器没有虚拟机入口。

当前表单已经按部分大类区分字段，但手机、平板、可穿戴、电子阅读器、游戏设备、电视和音频设备大量复用 `personalDeviceFields`；网络设备也共用一套网络字段。这样会造成无关字段出现、参数分类不准确和详情页空白分组过多。

当前 Agent Profile（`windows-host`、`linux-container`）属于采集能力，不应与资产类型混合。软件版本和固件版本按产品决定不进入硬件参数主展示。

## 目标分类

### 计算设备

- `physical_host`：台式机 / 工作站
- `mini_pc`：迷你主机
- `nas`：NAS
- `server`：服务器

统一展示处理器、显卡、内存、存储、主板 / BIOS、网卡、机箱 / 电源和 Agent 采集状态；NAS 与服务器增加存储阵列、盘位、共享用途等可选分组。

### 网络设备

- `router`：路由器
- `gateway`：网关
- `firewall`：防火墙
- `ont`：光猫 / ONT
- `switch`：交换机
- `ap`：无线 AP / Mesh

保留细分类型，但按设备 Profile 分别展示 WAN / LAN、DHCP / NAT、端口、PoE、VLAN、无线频段、桥接 / 路由、管理入口和拓扑关系。

### 移动设备

- `phone`：手机
- `tablet`：平板
- `wearable`：可穿戴
- `ebook`：电子阅读器

按设备展示芯片、内存、存储、屏幕、电池、影像、蜂窝网络、无线连接、接口、尺寸、重量、颜色、防护和传感器；可穿戴和阅读器不显示不适用的摄像头或蜂窝字段。

### 娱乐与显示设备

- `game_console`：游戏主机
- `handheld`：游戏掌机
- `tv`：电视 / 显示器 / 投影
- `speaker`：音箱 / 功放 / 网络音频

按设备展示 SoC / GPU、内存、存储、屏幕 / 视频输出、HDR / 刷新率、音频、网络、接口、控制器 / 配件、功耗和尺寸。

### 安防与办公设备

- `camera`：摄像头
- `printer`：打印机 / 扫描仪

摄像头展示传感器、镜头、视频规格、夜视、云台、RTSP / ONVIF、存储和供电；打印机展示打印技术、速度、分辨率、耗材、纸张、双面、扫描和网络。

### 电源设备

- `ups`：UPS

展示 VA / W 容量、电池、输出口、预计续航、USB / SNMP / NUT、保护资产和维护记录。

### 智能家居设备

- `smarthome_gateway`：智能家居网关
- `sensor`：传感器
- `light`：灯具
- `plug`：插座 / 开关
- `lock`：门锁
- `vacuum`：扫地机器人
- `iot`：其他 IoT

展示设备用途、协议、所属网关、房间、实体 ID、供电 / 电池、自动化关系和状态；具体控制能力仍由智能家居模块提供。

### 资源与服务

- `internet`：互联网线路，不视为物理设备
- `web_endpoint`：网页端点，不视为硬件设备
- `custom`：暂未归类的资产或资源，作为兜底类型并放入高级选项

互联网线路展示运营商、套餐、接入方式、上下行、公网地址和入户位置；网页端点展示 URL、端点范围、归属资产和检测状态。

### 虚拟机规则

`vm` 保留为历史数据兼容类型，但不再出现在新增资产类型选择器中，也不作为家庭资产主档创建。后续虚拟机作为客户端监控中宿主机的子对象展示，通过宿主关系、虚拟化平台和采集结果关联。

## Profile 注册表

新增统一的设备 Profile 定义，建议放在 `internal/site/src/modules/asset-center/asset-profiles.ts`：

```ts
type AssetProfileDefinition = {
  type: AssetType
  assetClass: AssetClass
  label: string
  summaryKeys: string[]
  sections: AssetProfileSection[]
  requiredFields: string[]
  addressMode: "required" | "optional" | "not_applicable"
}
```

Profile 负责：

- 新增 / 编辑表单字段和字段顺序。
- 详情页参数分组与摘要字段。
- 类型专属必填项。
- Agent 可采集字段与官方资料补全字段。
- 官方图片适用性和颜色规则。

采集 Profile 单独维护：

- `manual`
- `windows-host`
- `linux-container`
- `network-device`
- `smart-home`

采集 Profile 不改变资产类型，只决定数据来源、采集状态和可用操作。

## 公共字段与类型字段

所有物理资产共用身份层：资产编号、资产名称、资产大类、具体类型、状态、位置、用途 / 角色、厂商、型号、内部型号、颜色、序列号和官方来源。

网络地址层不再简单假设所有资产都有固定 IPv4。由 Profile 声明地址模式：固定地址设备填写 IPv4 / IPv6 / MAC；动态设备记录动态地址状态；无地址设备明确显示“无网络地址”，不能留下模糊空值。若业务仍要求录入时统一填写 IPv4，应提供“无固定 IPv4”的显式选项，而不是伪造地址。

硬件参数只保存稳定、可追溯的硬件事实。软件版本、固件版本和运行时版本不进入硬件主展示，放入 Agent / 监控状态区域。

## 页面展示规则

### 资产列表

只展示跨类型都可比较的字段：资产编号、名称 / 类型、厂商 / 型号、位置、IPv4、接入网络、监控状态、资料完整度和详情入口。

### 资产查看页

保持现有三列布局：

1. 左列：设备主图或官方图片。
2. 中列：资产身份、网络摘要和当前 Profile 的硬件分类摘要。
3. 右列：点击某一分类后展示该分类的全部详细字段；如果分类字段较少，直接在中列完整显示。

只渲染有值的分类；空分类不显示。公共字段不能在标签、资产信息和硬件参数中重复出现。

### 资产编辑页

1. 顶部固定操作区：保存、资料补全、找图、删除和取消。
2. 第一段：类型对应的必填身份字段。
3. 第二段：类型专属参数。
4. 第三段：网络 / 采集 / 生命周期 / 来源等可折叠高级字段。

不同类型不得再渲染整套通用个人设备字段。

## Agent 数据规则

资料补全 Agent 和本地 Agent 都只能返回 Profile 允许的字段键。每个字段保留来源、来源类型、可信度、采集时间和冲突信息；用户确认后才覆盖主档。

Agent 处理顺序：

1. 使用资产类型、厂商、型号和内部型号确定 Profile。
2. 本地 Agent、数据库和官方资料分别采集。
3. 按字段合并、去重、校验和排序。
4. 只生成当前 Profile 允许的建议。
5. 用户单项或一键确认后写入资产主档。

设备找图 Agent 只返回与厂商、型号和选定颜色匹配的候选图，不改变参数 Profile；图片来源和用户选定结果继续独立保存。

## 分阶段实施

### 第一阶段：分类与兼容层

- 建立 Profile 注册表和分类映射。
- 重新整理新增资产类型选择器分组。
- 隐藏 `vm` 新建入口，保留历史数据读取。
- 将摄像头、打印机、UPS、互联网线路和网页端点移到正确大类。
- 为每个 Profile 补齐摘要字段和必填规则测试。

### 第二阶段：表单与详情展示

- 将个人设备共享字段拆成手机、平板、可穿戴、阅读器、娱乐设备等 Profile。
- 将网络设备拆成路由器、交换机、AP、光猫、防火墙 Profile。
- 详情页按 Profile 动态显示分类和详细字段。
- 编辑页按 Profile 展示必填字段、专属字段和高级字段。

### 第三阶段：Agent 与来源收口

- Agent 输出按 Profile 字段白名单校验。
- 增加字段级来源和冲突展示。
- 统一本地采集、数据库采集、官方资料和找图候选的合并规则。
- 补齐每类设备的定向测试和真实页面验收。

## 验收标准

- 新增资产选择器不再显示虚拟机。
- 摄像头、打印机、UPS、互联网线路和网页端点出现在正确分类。
- 手机页面不出现电视、音箱、阅读器专属字段。
- 网络设备之间不再显示明显不适用的字段。
- 详情页没有空分类和公共字段重复。
- Agent 不能把不属于当前 Profile 的字段写入资产。
- 软件 / 固件版本不出现在硬件参数主区域。
- 现有资产、已有 `vm` 历史数据和现有 Agent 关联不丢失。
- `npm run check`、`npm run typecheck`、`npm test`、`npm run build` 和浏览器桌面 / 移动端验收全部通过。
