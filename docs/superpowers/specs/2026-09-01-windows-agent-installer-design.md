# Windows Agent 安装软件技术设计

> 状态：待用户确认
> 日期：2026-09-01

## 1. 目标

- 将现有 Go Windows Agent 产品化为可安装软件。
- 后台采集使用 Windows Service，开机自启，不依赖用户登录或配置窗口。
- 本地只保留轻量连接配置；日常管理统一在 Pulse 网页完成。
- 安装位置可选择，相关程序、配置、日志、更新和回退文件集中在用户选择的根目录。
- 支持标准安装、升级、失败回退和尽量干净的卸载。
- 不创建桌面图标、不使用托盘常驻、不自动启动配置窗口。

## 2. 现状调查结论

- `agent/` 已是 Go 实现，包含 Windows 硬件、网络、服务、软件、GPU、SMART、Docker 等采集能力。
- Agent 已有 WebSocket 主动连接 Hub、配对、受保护凭据保存和 Windows 自更新基础。
- Hub 已有 Agent 更新任务、服务控制和能力状态上报基础。
- 现有安装文档仍以 NSSM 包装服务，尚未形成最终的原生服务、窗口和安装器组合。

## 3. 推荐技术组合

### 3.1 后台服务：Go 原生 Windows Service

继续复用现有 Agent 核心，增加服务宿主层：服务名固定为 `pulse-agent`，自动启动，配置有限次数的异常恢复，不依赖登录、桌面窗口或托盘进程。

优点是资源低、依赖少、和现有 Go 代码一致；缺点是服务注册、权限、停止超时、事件日志和升级切换需要我们自己实现和测试。暂不继续使用 NSSM，因为它会增加外部组件、版本管理和卸载清理边界。

### 3.2 连接窗口：Wails 2 + React 子应用

复用现有 React / TypeScript 表单和状态展示能力，使用系统 WebView2。窗口按需打开、关闭即退出，使用标准标题栏和单实例锁；不保存上次位置，窗口不可见时放到当前主屏幕中央。

优点是前端复用率高、资源占用低于 Electron、主要语言仍为 Go；缺点是安装器需要检测 WebView2，部分旧 Windows 环境可能需要额外处理。Tauri 可作为备选，但会新增 Rust 工具链和维护面。

### 3.3 安装器：Inno Setup

安装向导允许选择位置，创建 `Pulse Agent` 开始菜单文件夹和“打开配置”“卸载 Pulse Agent”入口，注册服务、设置开机自启并支持升级安装。

优点是成熟、直观、适合当前个人项目；缺点是不是 MSI，企业统一分发能力弱于 WiX。当前不引入 WiX，以控制学习和维护成本。

## 4. 安装流程

1. 用户运行安装包并选择安装位置。
2. 安装器创建 `Pulse Agent` 根目录，复制服务、配置窗口和内置组件。
3. 创建配置、凭据、日志、更新和回退子目录并设置访问权限。
4. 注册 Windows Service，设置自动启动和有限次数恢复。
5. 创建开始菜单文件夹及两个入口，不创建桌面快捷方式。
6. 安装器可自动打开一次配置窗口；用户也可以跳过连接配置。
7. 未配置时服务保持开机自启，但低频等待，不反复进行无效连接。

## 5. 目录和权限

```text
Pulse Agent/
├─ bin/
│  ├─ pulse-agent.exe
│  └─ pulse-agent-config.exe
├─ data/
│  ├─ config/
│  ├─ credentials/
│  ├─ logs/
│  ├─ updates/
│  └─ rollback/
└─ uninstall.exe
```

- 连接凭据只保存受保护 Token，不保存原始机器连接码。
- 凭据目录只允许系统、管理员和 Agent 服务账户访问。
- 配置使用临时文件加原子替换，避免半配置状态。
- 多用户共用机器级配置，连接编辑使用跨用户互斥锁。
- 配置窗口默认普通权限，仅保存配置时临时请求管理员权限。

## 6. 网页与本地窗口边界

本地窗口只保留服务状态、Hub 地址、连接状态、最近结果、本机名、版本、连接 / 重试、重新配置和打开网页；服务确认停止时可提供“启动服务”。

网页统一负责停止、重启、暂停、恢复、维护状态、采集开关和频率、日志诊断、Agent 更新、进度、回退及操作记录。

## 7. 更新和回退

管理员从网页发起更新并二次确认。Hub 下发版本说明、下载地址和校验信息；Agent 下载到更新目录后校验版本、完整性和发布可信性，保留旧版本到回退目录，再原子替换并重启服务。Hub 等待新版本重新连接并确认真实运行；启动失败、校验失败或重连超时则恢复旧版本。Hub 不可达时不影响当前版本采集。

## 8. 卸载规则

- 卸载器先停止并注销服务，再删除安装器创建的程序、目录、开始菜单入口和临时文件。
- 不远程删除 Hub 中的设备记录、历史监控或告警。
- 默认建议彻底删除本地配置、凭据、缓存、日志、更新和回退文件；如保留配置，必须由用户主动选择且不默认勾选。
- 只删除安装器清单内的内容，不误删用户指定目录中的其他文件。
- 卸载失败必须显示实际失败阶段，不能伪装成已清理。

## 9. 采集完整度与资源控制

- 默认开启所有已实现采集项，网页可按机器关闭。
- CPU、内存、网络在线状态和基础状态默认 30 秒。
- 磁盘、温度、GPU、Docker / Podman、Windows 服务和软件状态默认 60 秒。
- SMART 和虚拟机清单默认 5 分钟。
- 失败显示“不可用”和真实原因，不显示假零值；失败任务采用退避，避免持续占用资源。
- 特殊硬件和大型组件按需安装，安装前单独确认。

## 10. 主要风险

| 风险 | 应对 |
|---|---|
| 更新后服务无法启动 | 保留旧版本，健康检查失败自动回退 |
| WebView2 缺失 | 安装器检测并给出中文提示 |
| 权限过高 | 服务与窗口分权，写配置时才临时提权 |
| 多用户同时修改 | 机器级互斥锁和失效占用清理 |
| 卸载误删文件 | 只删除安装器清单内文件 |
| 采集过重 | 分层频率、独立开关、退避和实机测量 |
| 版本不兼容 | 显式版本号、兼容范围和更新前检查 |
| 配对码泄露 | 不落盘、不进日志、不进剪贴板、不进命令行 |

## 11. 分阶段实施

1. 原生 Windows Service：注册、启动、停止、恢复和状态读取，不改变采集协议。
2. 连接配置窗口：Wails 窗口、单实例、标题栏、配置读写和权限边界。
3. 安装器：Inno Setup 安装位置、开始菜单、服务注册和卸载。
4. 网页更新闭环：进度、校验、原子替换、失败回退和端到端验证。
5. 真实 Windows 实机测量采集完整度与资源占用。

## 12. 验收标准

- 普通用户可完成安装并打开配置窗口。
- 重启电脑、注销用户、关闭配置窗口后仍继续采集。
- 服务异常退出可按有限规则恢复。
- 配置窗口显示真实服务和连接状态。
- 网页可发起更新并在失败时恢复旧版本。
- 卸载后服务、入口和安装器创建内容清理干净。
- 连接凭据和机器连接码不泄露，采集失败原因可追溯。
- 资源占用达到实测目标。

3. 卸载是否默认彻底删除连接配置和凭据；本设计建议默认彻底清理。
4. Windows 支持下限是否按现有项目范围执行。
