# Agent 1.0 安装方式

当前只保留两种 Agent：

- Windows 主机版：安装为 Windows Service。
- Linux / 飞牛 / NAS / Unraid 容器版：通用 Linux 和飞牛使用 Docker Compose，Unraid 使用 root 直连下载命令把 XML 写入 Unraid 的模板目录。

两种 Agent 都通过 WebSocket 主动连接 Hub。首次接入只需要 Hub 地址和网页为目标资产生成的 6 位长期机器连接码；配对成功后由 Hub 自动发放机器独立连接凭据，后续不再需要人工 Token。

## Windows 主机版

适合 Windows 设备。支持基础指标、Windows 服务监控/控制、手动添加的软件运行状态监控、Docker Desktop / Engine 容器监控/控制、Agent 手动更新，以及核显型号和占用率采集。

要求：

- 使用管理员 PowerShell 执行安装命令。
- Windows 安装包提供安装位置页面，默认优先选择空间合适的非系统本地固定磁盘，并创建独立的“Pulse Agent”根文件夹；不默认安装到 C 盘，也不自动选择移动盘或网络盘。电脑只有 C 盘或用户主动选择 C 盘时，用户确认目标路径和空间信息后可以继续。
- 服务通过 NSSM 管理；缺失时安装命令会尝试通过 WinGet 安装 NSSM。
- 新安装包必须把后台采集服务注册为随 Windows 开机自动启动，并配置有限次数、合理间隔的异常恢复；服务运行不依赖用户登录或连接窗口。新安装包不提供托盘程序，连接窗口不得随登录自动启动，关闭后直接退出。
- 连接配置程序必须单实例运行；窗口已经打开时，再次点击开始菜单中的“Pulse Agent”只恢复并前置原窗口，不创建第二个进程或重复窗口，也不得重复提交连接或修改后台服务。
- 连接配置窗口使用普通 Windows 软件的标准标题栏，保留“最小化”“最大化 / 还原”和“关闭”三个按钮。最小化后窗口进入任务栏，不创建托盘图标；最大化与还原只改变窗口尺寸；关闭后界面进程退出并释放资源。三种操作都不停止或修改后台采集服务。
- Hub 地址、机器连接码或其他可编辑连接内容被修改但尚未成功保存时，点击标题栏“关闭”或界面内“关闭”必须显示中文确认“更改尚未保存，确定关闭吗？”。选择继续编辑时保留当前输入，确认关闭时丢弃未保存内容并退出；没有未保存修改时直接关闭。未提交的机器连接码不得写入本机磁盘、日志或后台服务。
- 连接配置窗口不保存上次的窗口大小、最大化状态或屏幕位置，每次启动都使用产品设定的默认大小和默认位置。启动或恢复窗口时检查当前可用屏幕；显示器拔出、分辨率变化或原位置不可见时，自动恢复默认大小并移到当前主屏幕中央。
- 连接配置窗口在本次运行期间允许拖动边框自由调整大小，并支持标准最大化与还原；关闭后不保存调整后的大小，下次仍使用默认大小。窗口必须设置最小宽度和最小高度，确保中文文案、状态、输入框和主要按钮完整显示且不重叠；具体默认尺寸和最小尺寸在实现时根据最终内容与 Windows 显示缩放实测确定。
- 连接配置窗口默认以普通用户权限启动；打开窗口、查看服务和连接状态、打开 Pulse 网页及执行不修改配置的单次重试不要求管理员权限。仅在首次连接验证成功后保存连接、重新配置 Hub 并替换原连接等需要写入受保护配置时，调用 Windows 标准管理员确认进行一次临时授权，界面不得长期以管理员权限运行。取消授权或授权失败时不写入新配置、不替换原凭据、不修改后台服务，继续使用原状态并显示“未获得管理员权限，连接设置未保存”。
- 安装器将开始菜单中的“Pulse Agent”文件夹和配置入口创建为本机所有登录账号可见。所有账号都能以普通权限打开窗口并查看整台电脑共用的服务状态、当前 Hub 地址和连接状态，但不能查看连接凭据；保存首次连接或重新配置仍需管理员确认。Agent 只维护一份机器级连接配置，不为每个 Windows 账号分别建立连接；单实例窗口按当前登录会话管理。
- 机器级连接编辑必须使用跨登录账号的互斥保护，同一时间只允许一个账号进行首次连接或重新配置。其他账号仍能查看状态，但编辑入口禁用并显示“另一位用户正在修改连接，请稍后再试”。编辑者保存、取消、确认关闭或进程异常退出后释放编辑权；程序还必须清理崩溃、注销或断电造成的失效占用，避免永久无法修改。没有取得编辑权的窗口不得写入配置或提交机器连接码。
- 连接配置窗口打开期间自动刷新后台服务状态、Hub 连接状态和最近连接结果，窗口最小化或不可见时降低刷新频率，避免增加不必要的资源占用；具体刷新间隔在实现时实测确定。状态变化只更新界面内容和更新时间，不弹出提示框。状态读取失败时显示“暂时无法获取状态”；允许保留上一次结果作为参考，但必须标为历史状态并显示更新时间，不能当作当前状态，读取恢复后自动更新。
- 采集频率采用分层策略：CPU、内存、网络在线状态和基础运行状态默认每 30 秒采集一次；磁盘使用量、温度、GPU、Docker / Podman、Windows 服务和软件状态默认每 60 秒采集一次；S.M.A.R.T. 与虚拟机清单默认每 5 分钟采集一次。窗口最小化、Agent 离线或对应项目已关闭时应自动降低或暂停无效采集，避免资源浪费；频率调整在网页中按机器生效并显示当前设置。
- 状态区域右上角提供带中文悬停说明“刷新状态”的标准刷新图标按钮。点击后只立即重新读取一次后台服务、Hub 连接和最近连接结果，不修改配置、不请求重新连接、不启动或重启服务，也不要求管理员权限。刷新期间按钮不可重复点击，完成后更新最后刷新时间；失败时按历史状态规则显示。“刷新状态”与会让后台服务主动连接 Hub 的“重试连接”必须明确区分。
- 只有确认后台采集服务已经停止、且 Windows 服务机制当前没有正在自动恢复时，连接配置窗口才显示“启动服务”。点击后通过 Windows 标准管理员确认启动服务，不修改 Hub 地址、连接凭据或其他配置；启动期间显示“正在启动服务”并禁止重复点击，成功后自动刷新真实状态。取消授权或启动失败时不自动反复重试，保留原配置并显示中文原因和下一步。自动恢复中只显示“正在恢复服务”，无法确认服务状态时不显示启动按钮。
- 连接配置窗口不提供“停止服务”按钮或其他停止采集入口，只保留故障恢复所需的“启动服务”。主动停止采集必须在 Pulse 网页中由管理员选择设备、查看设备离线与监控中断影响并完成中文二次确认；执行过程与结果由网页如实显示和记录，不允许从本地窗口绕过确认。
- 停止服务、重启服务、暂停或恢复采集、进入或退出维护状态及后续同类运行控制全部由 Pulse 网页提供，本地连接配置窗口不重复实现。网页执行前显示目标设备、当前任务或更新状态、预计离线时间、监控与告警影响和恢复方法，并要求管理员中文二次确认；执行中显示进度，完成后记录真实结果和失败原因。更新、连接切换或其他互斥任务进行中时拒绝冲突操作并说明原因。本地“启动服务”仅作为服务意外停止后的故障恢复入口。
- 连接配置窗口底部只读显示组件自身真实构建信息中的“Agent 版本”和“配置程序版本”。读取失败时显示“暂时无法获取”，不得用目标版本、默认值或猜测值替代；版本不一致时如实显示双方版本和简短兼容状态。本地窗口不提供更新按钮、更新说明、版本选择、升级或回退，所有版本管理继续在 Pulse 网页中完成。
- 连接配置窗口不显示安装位置、程序目录、配置目录、连接凭据目录、缓存目录、日志目录、更新包目录或回退目录，也不提供打开目录按钮。需要查看安装位置时使用 Windows 开始菜单中“Pulse Agent”图标的系统右键功能；普通账号不得借此读取连接凭据或其他秘密目录。安装和数据目录的完整说明保留在安装文档，日志与诊断管理继续通过 Pulse 网页完成。
- 连接配置窗口只读显示从 Windows 实时读取的“本机名称”，用于确认当前正在配置的电脑；读取失败时显示“暂时无法获取”，不得用 Pulse 设备显示名称、旧缓存或猜测值代替。本地窗口不能修改电脑名或设备显示名称，Pulse 设备显示名称仍在网页中管理，并与真实主机名分开保存和展示。
- 连接配置窗口显示错误时先提供中文原因和下一步，并在错误区域提供带中文悬停说明“复制错误信息”的标准复制图标。复制内容只包含错误编号、发生时间、本机名称、组件版本、服务与连接状态和简短原因，并在写入剪贴板前隐藏机器连接码、连接凭据、Token、密码、授权头等秘密信息；不得包含完整日志、秘密目录或无关数据。复制不会自动上传或发送；成功显示“错误信息已复制”，失败显示“复制失败，请稍后重试”。详细日志与诊断仍由 Pulse 网页提供。
- 机器连接码由 Pulse 网页在资产管理选定机器的接入监控流程中生成并长期保留；Pulse 永久统一使用 6 位数字配对码，显示时可按 `123-456` 分组，输入时自动忽略空格和短横线。以后不再规划或兼容 `PMC-...` 长码，避免两套格式并存。本地输入框使用普通明文输入，直接显示用户填入的完整内容，不使用密码圆点，也不提供显示 / 隐藏、生成、重置或复制入口。连接成功、验证失败、放弃未保存修改或关闭窗口后立即清空本地输入内容；原始连接码不得写入 Windows 本地磁盘、日志、错误信息、剪贴板或后台服务，网页接入记录在添加过程中和添加完成后都可由管理员查看和复制。
- 首次安装完成后，安装器只自动打开一次连接配置窗口以填写 Hub 地址和资产接入记录中由 Pulse 网页提供的机器连接码；窗口关闭后不得再次自动启动，后续仅通过开始菜单中的“Pulse Agent”入口手动打开。配置失败不回滚已经完成的程序和服务安装。
- 用户可以在首次安装后暂时跳过 Hub 配置并关闭窗口。后台服务继续保持已安装和开机自启，但在没有 Hub 配置时只低频等待，不反复进行无效连接；后续从开始菜单继续配置即可，无需重新安装。界面应显示“尚未配置连接”，不能显示为普通连接故障。
- 连接成功后，连接窗口显示“连接成功”和当前 Hub 地址，并保留“打开 Pulse 网页”和“关闭”按钮，不自动关闭。打开网页时使用系统默认浏览器；关闭窗口只结束界面进程，不停止后台服务。
- 连接或机器连接码验证失败时保留 Hub 地址并立即清空机器连接码输入，不得保存失败输入。窗口分别显示“地址无法访问”“机器连接码错误”“机器连接码已被重置”等中文原因，并提供“重试”和“关闭”；需要换码时从 Pulse 网页对应资产记录重新复制当前连接码。
- 已连接后从开始菜单打开窗口时，显示“已连接”、当前 Hub 地址和“打开 Pulse 网页”“重新配置连接”“关闭”。重新配置必须使用新的 Hub 地址和对应资产的机器连接码；新连接验证成功并二次确认后才替换旧连接，失败时保留原连接和原凭据，不得产生半配置状态。
- 已连接状态下当前 Hub 地址只读显示，不能直接编辑；点击“重新配置连接”并取得编辑权后，才显示新的 Hub 地址和机器连接码输入区域。取消、验证失败或未完成二次确认时继续使用原连接，不覆盖原地址或凭据。
- 进入“重新配置连接”后必须先显示中文提醒：“验证成功并确认后，旧连接会被替换；验证失败不会影响当前连接。”在新连接验证成功并完成二次确认前，后台继续使用旧地址和旧凭据。
- 用户必须先点击提醒中的“我知道了”，连接配置窗口才显示或启用新的 Hub 地址和机器连接码输入区域；确认前不得提交验证、发送连接请求或修改原连接。
- 新地址和机器连接码填写完成后必须先执行“验证新连接”，验证成功后才显示最终替换确认；验证失败不得覆盖旧地址、旧凭据或通知后台服务切换，并显示真实中文原因。
- 验证成功后的最终确认按钮必须显示“确认替换连接”，旁边再次显示“旧连接将在确认后失效”；用户取消确认时继续使用旧连接，不写入新配置。
- 点击确认后显示“正在切换连接”，暂时禁用关闭、返回和重复点击；只有确认新配置已原子保存且后台服务使用新连接后，才显示“连接已更新”并恢复操作。
- 连接切换失败时必须显示“连接切换失败，仍在使用旧连接”，并提供“重试切换”和“返回”；失败期间旧地址、旧凭据和后台服务继续使用，重试成功前不得覆盖原配置，返回时放弃本次新连接。
- 失败状态点击“返回”时必须先显示“确定放弃本次连接切换吗？”确认提示；取消时保留新地址和机器连接码继续操作，确认后清空新输入并回到旧连接状态，旧连接始终不受影响。
- 机器连接码生成、展示和重置由 Pulse 网页的资产接入记录负责；在“资产监控”页面点击“添加监控”后，先在当前添加页面填写和确认机器信息，不立即生成连接码，也不跳转到其他页面。只有点击“确认添加”并成功创建监控接入记录后，才为没有连接码的资产生成唯一机器连接码并直接显示；重复打开或取消添加不会生成新码，已有连接码的资产继续使用原码。连接码长期有效，添加过程中和添加完成后，网页都向管理员直接显示完整机器连接码，不使用星号遮挡，也不提供额外的查看 / 隐藏入口。管理员可以点击“复制机器连接码”，复制到剪贴板的始终是完整连接码。复制成功提示“机器连接码已复制”，失败提示“复制失败，请手动选择连接码复制”。复制动作写入操作审计，但审计记录不得保存连接码原文。只有管理员可以执行“重置机器连接码”，点击后先显示影响说明：“重置后，旧机器连接码立即失效；已保存的现有连接继续按当前状态运行，之后重新安装或重新配置必须使用新连接码。”确认弹窗只提供“取消”和“确认重置”两个按钮，不要求输入机器名称或固定文字；确认后立即生成并显示新的机器连接码，旧码不再显示，同时短暂提示“机器连接码已重置”，提示几秒后自动消失，并记录操作人和时间。本地重新配置窗口不显示倒计时或提供生成 / 重置按钮，输入已重置旧码只清空新输入并显示“机器连接码已被重置，请到 Pulse 网页查看当前连接码”，不得清除或修改原连接。
- 每台资产同一时间只能有一条有效的监控接入记录。已经存在接入记录的资产不再出现在“添加监控”的可选机器列表中；即使尚未连接成功或机器连接码生成失败，也必须回到原记录继续生成、复制、重置连接码或查看状态，不得重复添加。需要重新接入时复用原记录并重置机器连接码或重新配置连接，不创建第二条记录，避免重复机器、重复数据和重复告警。
- 管理员可以在资产监控记录中主动“删除监控目标”。这是高风险操作，点击后必须进行中文二次确认，弹窗直接提示：“删除后会删除该监控目标的所有历史记录，包括历史指标、历史告警和其他监控数据，且无法恢复。”同时明确不会删除资产资料或删除操作审计；确认按钮为“取消”和“确认删除监控目标”。确认后立即停止接受该 Agent 的新数据，使当前机器连接码和已经发放的连接凭据失效，并把该资产重新放回“添加监控”的可选列表。删除完成后不保留这段监控的历史数据；以后重新添加时创建新的有效接入关系、新机器连接码和全新的数据时间线，不恢复已经失效的旧凭据。
- 取消监控后，如果原 Agent 仍继续上报，Hub 必须直接拒绝本次上报，不保存新监控数据；Agent 收到“当前监控已取消”的结果。拒绝事件写入系统日志和必要的操作记录，但不得反复弹窗或重复通知用户。只有管理员重新添加该资产并生成新的机器连接码后，Agent 才能恢复接入。
- Windows Agent 收到“当前监控已取消”后，本地连接窗口必须明确显示同名状态，不得显示为普通“连接失败”或网络故障。后台服务继续保持已安装和开机自启，但停止正常数据上报，只进行低频连接状态检查，避免反复请求和资源浪费；本地保留原连接配置用于排查，不自动清除。窗口提供“打开 Pulse 网页”“重新配置连接”和“关闭”；管理员重新添加资产并生成新的机器连接码后，通过“重新配置连接”完成验证并恢复接入。
- Pulse 网页首次生成机器连接码失败时只弹出“机器连接码生成失败”，但保留已经创建的监控接入记录；原记录提供“重试生成机器连接码”按钮，管理员可再次点击生成并重试，成功后在原记录和当前页面显示连接码，不重复创建监控记录。“重试生成机器连接码”只用于尚无连接码的失败记录，不得替代已有连接码的“重置机器连接码”。重试失败继续保留记录并允许后续重试。重置失败时只弹出“机器连接码重置失败”。失败时保留原页面状态和原有连接码，不显示技术原因，也不得误作成功或让旧码失效；详细失败原因写入系统日志，供管理员后续查看，日志不得记录连接码原文。
- 已连接但 Hub 暂时不可达时，窗口显示“已连接，当前无法连接”，保留当前 Hub 地址和连接凭据，并提供“重试连接”“打开 Pulse 网页”“重新配置连接”“关闭”。临时离线不清除配置或要求重新输入机器连接码；打开网页失败只显示无法访问。
- 点击“重试连接”只请求后台服务立即连接一次，并显示“正在连接”“连接成功”或“连接失败”。该操作不修改 Hub 地址或连接凭据，不进行无限重试；失败后继续保留原配置。
- 新 Windows 安装包的连接窗口只接收 `HUB_URL` 和机器连接码；连接码验证成功后，由后台按既有安全机制换取并保存受保护的连接凭据到 `DATA_DIR`。原始机器连接码不得作为环境变量、命令行参数或配置文件内容长期保存。`INSTALL_METHOD`、`RUN_MODE`、`AGENT_PROFILE` 等安装信息继续由安装器写入。
- 新安装包不再让程序、数据和日志分散到多个系统路径。程序、服务、连接配置程序、内置组件、配置、连接凭据、缓存、日志、更新包和回退文件统一位于用户选择的“Pulse Agent”根文件夹下，并使用明确子目录；连接凭据目录必须限制 Windows 文件访问权限。
- Windows 服务注册、卸载登记和开始菜单入口仍由 Windows 保存在系统管理位置，这些只是必要登记和入口，卸载时会与所选安装目录一并清理。新安装包不创建桌面快捷方式。旧的一行 PowerShell 安装方式在新安装包完成迁移前仍按现有路径工作，不应被误写成新安装包的最终目录规则。

## Linux / 飞牛 / NAS / Unraid Docker 容器版

适合 Linux、飞牛、NAS 和 Unraid。重点是低负担基础监控、Docker / Podman 容器采集，以及控制同一台机器上的容器和 Compose 堆栈。

容器版可在设置页 Agent 管理中手动更新。Agent 会通过 Docker / Podman socket 拉取目标镜像并重建自身容器；如果当前版本已经是目标版本，只回报“已是最新版”，不会重新拉取或重建。

要求：

- 宿主机需要 Docker 或兼容运行时。
- 如果需要监控并控制同机容器，必须读写挂载 `/var/run/docker.sock`。
- 如果需要 Intel / AMD 核显指标，可按需映射 `/dev/dri`；不再默认依赖宿主机 `video/render` 组名。
- 容器镜像默认从 HTTPS Harbor 拉取：`registry.example.com:443/infra/pulse-agent:1.0.8`。
- Agent 必须使用专用数据目录保存连接凭据和本地状态，不再建议使用当前目录下的临时相对路径。

当前安装入口拆成三类：

- 通用 Linux：Docker Compose，默认数据目录 `/opt/pulse-agent/data`。
- 飞牛 / NAS：Docker Compose，可直接下载 `pulse-agent-flynas.yml`，默认数据目录 `/vol1/1000/docker/pulse-agent/data`。
- Unraid：模板下载命令，可直接把 `pulse-agent-unraid.xml` 写入 `/boot/config/plugins/dockerMan/templates-user`，默认数据目录 `/mnt/user/appdata/pulse-agent`。

默认示例会同时开放宿主机根目录、DMI、/dev/mem 和 GPU 入口，方便安装后直接获得完整采集能力；如果目标机器权限更严格，也可以在设置页里按需关闭单项能力。

示例：

```yaml
services:
  pulse-agent:
    image: registry.example.com:443/infra/pulse-agent:1.0.8
    container_name: pulse-agent
    restart: unless-stopped
    network_mode: host
    privileged: true
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - /opt/pulse-agent/data:/var/lib/pulse-agent
    environment:
      PAIR_CODE: "123456"
      HUB_URL: "http://YOUR_HUB:8090"
      INSTALL_METHOD: docker
      RUN_MODE: docker
      AGENT_PROFILE: linux-container
```

配对安装时，生成的 Compose 预览会把一次性配对逻辑写成 YAML 块标量，并通过 `PAIR_CODE` 环境变量在容器内展开，避免把 shell 单引号直接嵌进 `entrypoint` 后把 YAML 结构弄坏。

全量采集默认补齐以下宿主机能力；如果某台机器不需要某项，后续可在 Pulse 网页中单独关闭：

- `/:/host:ro`
- `/sys/firmware/dmi:/sys/firmware/dmi:ro`
- `/dev/dri:/dev/dri`
- `/dev/mem:/dev/mem`
- `--security-opt systempaths=unconfined`
- `CAP_PERFMON`
- `CAP_SYS_RAWIO`

如果当前 SSH 用户没有 Docker 权限，先用有权限的 root / 管理终端执行，或手动改成 `sudo docker compose ...`。`sudo` 需要交互密码时，命令仍会停在终端里等待输入，这是权限问题，不是镜像问题。

Unraid 模板安装说明：

- Unraid 的主入口是下载命令，命令会把 XML 模板写入 `/boot/config/plugins/dockerMan/templates-user/pulse-agent-unraid.xml`。
- 直接执行时默认按 `root` 权限写入；如果 SSH 已经是 root，就不需要再手动加 `sudo`。
- 写入后的 XML 仍然保留 `Network=host`、`Privileged=true`、`ExtraParams`、`Config`、`PostArgs` 等原有模板语义。
- 一次性配对模板通过 `PostArgs` 执行 `agent pair`，并额外写入 `/var/lib/pulse-agent/paired.code` 作为首次安装标记；如果旧的 `token` / `paired.env` / `pairing.json` 残留，模板会先清理再重新配对，避免重装后检测不到新机器。

## Hub 标准部署

Linux / 飞牛 / NAS 上部署 Hub 时，标准方式是 Hub 和 Hub 同机 Agent 一起安装。这样 Hub 所在机器会自动进入监控范围，也能采集和控制同机容器。

推荐使用：

```text
supplemental/docker/hub/docker-compose.yml
```

首次部署不用先在 Hub 页面添加 Hub 所在机器；标准 Compose 会用 loopback-only Hub 同机 Token 自动注册 Hub 同机 Agent，页面显示真实机器名并带 `Hub` 标签，且这条 Hub 机器记录不能删除：

```bash
export PULSE_AGENT_HUB_URL="http://127.0.0.1:8090"
docker compose pull
docker compose up -d
```

同机 Agent 的 `HUB_URL` 必须保持 `http://127.0.0.1:8090`，用于 loopback-only 本机 Token 和唯一 `Hub` 身份校验；页面身份地址由 Agent 上报的真实物理网卡局域网 IP 提供，不能通过把 `HUB_URL` 改成局域网地址来实现。

## 后续维护

- 发布新版本时，Hub 和 Agent 必须同步升级到同一个显式版本号。即使本次主要修改 Hub，也要重新构建并发布同版本 Agent 镜像和 Windows 安装包，避免 Agent 端采集、更新、容器控制等改动没有跟上。
- Windows 主机版：在设置页 Agent 管理中点击更新；如果版本已最新，只回报“已是最新版”。
- Linux 容器版：在设置页 Agent 管理中点击更新；需要容器挂载 Docker / Podman socket 才能拉取镜像并重建自身容器。
- 两种模式都只依赖 `TOKEN` 和 `HUB_URL` 完成接入。
