# Pulse 1.0.6 开发记录

> `1.0.5` 已于 2026-06-23 固定发布。固定点之后的新改动统一进入 `1.0.6` 开发记录，不再回填到 `1.0.5` 正式记录。

## 1.0.6 开发记录

### Web / Hub

- 模块目录收敛为只读说明页：告警中心、通知模块、Agent 管理和备份日志与审计升级为必需模块，必需模块统一集中显示在列表底部；设置页移除模块启停控件，模块依赖、路由、集合、任务、Agent 能力和健康检查继续可查看。
- 模块说明入口进一步明确为只读目录：页面标题、设置导航和模块阻塞空态统一不再使用“模块管理”操作口径，必需模块仍集中显示在列表底部，用户只能查看职责、依赖和代码边界。
- 前端严格类型门禁完成收口：补齐 Recharts 3 Tooltip 运行时类型、系统图表统计窄化、网站监控选项、资产参数与找图候选类型及测试夹具；新增 `npm run typecheck` 并纳入 Quality CI，前端类型检查不再停留在本地手工命令。
- 前端质量门禁新增模块目录回归与 Node 类型依赖；模块 registry 保留路径字面量类型，避免导航类型被宽泛字符串断言抹除。
- 模块运行态门禁继续收口：关闭模块后，Hub 集合 / 自定义 API 门禁写出 `module_disabled` 响应即停止后续 `Next()`，避免响应已返回仍继续执行；无认证的 Agent 配对接口在解析配对码归属用户后也会检查 `agent-management`，关闭时不会创建系统、指纹或 Token，并新增真实配对回归测试。
- 模块运行态门禁覆盖 realtime 与网站监控后台：PocketBase 集合 / `rt_metrics` realtime 订阅统一按所属模块校验，关闭客户端监控或网站监控后不会建立新的对应订阅；网站监控 cron 按资产所属用户的模块状态跳过已关闭模块，并新增主题映射与模块状态回归测试。
- realtime worker 生命周期继续收口：订阅状态由包级全局变量改为 `SystemManager` 实例状态，读写统一受锁保护并按订阅主题计数；关闭客户端监控时会主动移除用户已有的 `rt_metrics` 和客户端监控集合订阅，避免后台继续拉取或页面继续接收数据。
- 客户端统计聚合任务接入模块状态：`CreateLongerRecords` 通过 Hub 注入系统处理过滤器，用户关闭客户端监控后不再为其系统生成 10m / 20m / 120m / 480m 派生记录；无用户归属的历史系统保持兼容处理，并新增记录管理回归测试。
- 资产中心字段领域继续拆分：资料完整度、保修状态、清单摘要、搜索文本和展示格式迁入 `asset-profile-summary.ts`，`asset-schema.ts` 只保留资产类型与表单字段目录；新增直接契约测试，页面导入路径和显示行为保持不变。
- 资产详情数据加载边界继续收口：首屏主档查询、后台维护 / 附件 / 图片 / AI 任务 / 变更 / 补全查询，以及编辑目录和状态合并规则迁入独立的 `asset-detail-data.ts`；查询过滤器统一转义资产 ID，过期资产的后台响应仍由页面加载世代拦截，并新增直接 Node 契约测试，详情页可见行为保持不变。
- 资产详情关系编辑规则迁入独立领域模块：接口 / 关系类型选项、引导目标筛选、关系表单转换、端点映射和 metadata 序列化不再堆在详情页路由中，并新增直接 Node 契约测试；详情页加载、保存和展示行为保持不变。
- 模块开关补齐 Hub API 门禁：资产中心、客户端监控、网站监控、告警、通知、Agent 管理和维护相关自定义接口及 PocketBase 记录 API 会按当前用户的 `module_settings` 检查启用状态；关闭或依赖被阻塞时返回结构化 `module_disabled` / `blocked_by` 响应，默认启用和必需模块行为保持不变，并新增端到端门禁回归。
- 资料补全 Agent 来源发现改为补充模式：即使资产已有厂家支持页 / 产品页，只要可追溯来源未达到配置上限，仍会继续让 Agent 查找官方来源，并与手填来源合并去重、按可信度排序后再交给字段提取；不再因为已有一条资料而提前停止联网补全。
- 资产补全报告规则继续模块化：焦点归一化、官方配色字段过滤、资产类型策略、冲突统计和建议去重迁入独立领域文件，并新增直接契约测试；报告生成与 AI / 数据库编排行为保持不变。
- 资料补全 Agent 的 Agnes 请求接入请求上下文：用户离开页面、请求超时或上层取消后，模型请求会立即停止，重试等待也支持取消；既有限流重试和非临时错误不重试行为保持不变，并新增 Hub 传输层回归测试。
- 资产主档校验规则按领域拆分：IP / MAC 归一化、metadata 数值读取、接口地址去重和 JSON 解析迁入独立规则文件，并新增 Go 纯规则回归；主档、接口、关系和位置请求校验行为保持不变。
- 用户模块边界收口：用户与用户设置的默认值钩子由 `internal/users.UserManager` 自己注册，Hub 不再直接持有用户初始化细节；首建用户、角色默认值和用户设置默认值行为保持不变。
- 资产详情三列查看工作区迁入独立组件：设备全貌图、资产信息和硬件参数的固定布局与身份字段构造集中到资产中心展示组件，详情页进一步只保留数据加载与页面编排。
- 资产详情参数领域模块补齐直接契约测试：手机的处理器 / 内存 / 存储 / 屏幕 / 电池分组和主机的 CPU / 内存专项分组、单位格式都由 Node 定向回归锁定；模块收敛为可直接执行的 `.ts`，不再依赖 JSX 编译链路才能测试。
- 资产详情硬件参数构造迁入独立领域模块：归档设备语义分组、主机专项硬件档案、单位显示和字段过滤不再与详情页的加载 / 对话框逻辑混在一起，三列参数展示保持不变。
- 资产详情顶部标签展示迁入独立组件：位置、用途、归属、颜色和用户标签继续沿用既有去重与优先级规则，详情页不再维护该展示层细节。
- 资产详情编辑工作台迁入资产中心组件目录：详情页只保留数据读取、保存和 Agent 操作编排，编辑表单、参数替换、找图预览与子档案数量改由独立组件渲染；现有字段、校验和操作入口保持不变，后续可独立维护。
- Web 回归测试新增统一 `npm test` 入口：资产中心、网络拓扑和网站监控三组既有定向回归会顺序执行；GitHub Actions `Quality` 同步改为调用该入口，避免 CI 只覆盖资产中心而遗漏其他已维护模块。
- 资产编辑字段继续按模块边界收口：必填字段规则、完整编辑分组与字段控件迁入资产中心领域模块和组件目录；手机内存 / 存储规格、资产编号、两级位置和采集标签保持原有行为，并新增分组去重回归。
- AI 与识别设置页读取收口：Agnes 配置和两类 Agent 的最近任务改为并行加载，并接入最新请求保护；连续刷新或保存后回读时，旧响应不会覆盖当前配置、任务状态、加载提示或错误反馈。
- 资产清单与网络拓扑加载增加最新请求保护：连续刷新、保存后回读或拓扑布局切换时，较慢的旧请求不能再覆盖最新的资产 / 拓扑状态，也不会提前收起当前加载状态或弹出过期错误；共享请求世代工具已由资产中心和网络拓扑定向回归覆盖。
- 告警中心读取增加最新请求保护：初始加载、实时订阅防抖刷新与确认 / 静默后的回读并发时，只允许最后一次结果更新当前告警和规则状态，旧失败也不会干扰最新加载反馈。
- 网站监控只查询网页端点资产：端点筛选下沉到 Hub，并只读取监控建档需要的名称、位置、用途、说明和 URL metadata；查询迁入网站监控模块并新增契约回归，空态、从资产建档和已有监控去重行为保持不变。
- 系统详情硬件档案读取支持取消过期请求：快速切换机器或离开详情页时，旧机器的 `system_details` 请求会被直接中止，慢响应不能覆盖新机器的 CPU、内存、网卡和运行时详情。
- 容器详情抽屉的日志与 Inspect 读取增加独立最新请求保护：快速切换容器或手动刷新日志时，旧容器的日志 / Inspect 结果不会写入当前抽屉；日志和 Inspect 也不再互相等待，任一先返回即可展示。
- 网络拓扑首屏查询改为模块化字段投影：资产、接口、关系、布局和机器网络详情只读取构图需要的字段，避免拓扑刷新下载无关主档 payload；查询契约迁入 `modules/network-topology` 并由定向测试锁定，画布、连接、保存布局和真实接口数据展示保持不变。
- 修复设备图片 Agent 候选图上限未生效：找图处理器不再把保存的 `max_images` 强制覆盖为固定值，设置页“候选筛选上限”会真实限制官方图片的收集和候选集数量；新增端到端 Hub 回归覆盖管理员配置为 2 时只保存 2 张候选图。
- Hub 设备图片 Agent 清理无调用方的旧统一生图残留：删除 `ai_turntable` 成品写入、旧主图降级包装、图片模型限制常量和图像统一化提示词；当前运行入口仍只收集官方 / 可追溯候选图，用户选择后才写入唯一主图，官方来源过滤与颜色校验保持不变。
- 网站监控页面继续按模块边界收口：网页端点资产转监控表单的 URL 规范化、内外网 / IPv4 / IPv6 目标推导、图标来源和默认字段迁入独立领域模块，并新增定向回归脚本；监控保存、资产回写、归属关系同步与即时检测链路保持不变。
- 网络拓扑工作区继续按模块边界收口：资产候选、未接入机器过滤、端口类型映射、端口速率和宽带标签格式化迁入独立领域模块，并新增定向回归脚本；页面仍负责真实集合读取、拓扑保存和操作反馈，画布、连接和资产接口写入行为保持不变。
- 资产中心导出工作区继续按模块边界收口：导出格式选择、当前筛选资产数量和导出中禁用状态迁入独立组件；页面继续保留 CSV / JSON 实际生成、下载、集合读取和结果提示，导出内容与权限边界保持不变。
- Hub 资产主档校验测试夹具完成第二轮收敛：跨用户资产、重复主档、手机规格、接口主标记、网络标识、资产关系和位置循环等 9 个场景改为同一隔离 Hub 下顺序子测试；各场景使用独立用户与资产数据，完整 Hub 测试通过，定向执行约从 75 秒降至 1.9 秒，完整 Hub 包耗时从约 185 秒降至约 163 秒。
- 资产中心导入工作区继续按模块边界收口：JSON / CSV 输入、文件选择、模板入口、预览行、警告 / 错误状态和导入统计迁入独立组件；页面继续保留真实解析、重复预检、批量写入、接口同步与失败回滚，导入语义保持不变。
- 资产中心编号设置继续按模块边界收口：编号前缀、位数、下一个序号和预览迁入独立设置组件；页面只保留本地规则读取、持久化和提示反馈，新增资产自动编号与手动自定义编号行为保持不变。
- 资产中心位置设置继续按模块边界收口：位置预设总览、新增预设表单和待归档位置提示迁入独立工作区组件；页面只保留位置集合写入、资产目录刷新和反馈编排。新增纯选择规则回归，家 / 公司预设、自定义一级 / 二级位置与“只新增一级位置”的语义保持不变。
- 资产中心新增资产表单继续按模块边界收口：快速建档字段区迁入 `modules/asset-center/components/asset-quick-create-fields.tsx`，页面只保留表单状态、保存校验和展开编排；类型专属必填字段、两级位置、编号预设和手机内存 / 存储选择行为保持不变。
- 移动端网络拓扑首屏收紧：六项概览指标在小屏改为三列两行，桌面继续保持六列；拓扑画布重新进入首屏可视区域，避免统计卡单列堆叠挤压图谱。
- 客户端监控单设备布局收紧：仅有一台机器时客户端卡片会占满列表可用宽度，状态与指标按同一张横向卡片展开；多设备继续使用原有响应式卡片网格，避免家庭场景首屏出现大面积无意义留白。
- 设备图片 Agent 移除已废弃的图片模型统一生成链路：Hub 仅保留官方 / 可追溯候选图收集、颜色分类、用户选择主图和审计记录；不再保留后台生图、图片模型请求、参考图预处理和生成结果校验代码，避免与“AI 找图而非 AI 生图”的产品规则冲突。
- 设备图片 Agent 测试基线同步收口：移除只断言已废弃统一生图、模型格式降级、模型输入与失败诊断的回归场景，保留并继续扩展官方来源发现、候选图收集、颜色规则、低可信来源过滤和用户选图验证。
- 设备图片 Agent 测试继续去除历史生图噪音：删除 16 段已永久跳过的图片生成测试及其专属 Base64 / 像素处理 helper；官方页面解析、可信来源过滤、颜色校验、模型找图发现、候选数量和人工选图回归保持覆盖，测试配置统一以文本发现 `/chat/completions` 语义表达。
- 设备图片 Agent 可信来源校验继续加固：在“仅官方来源”模式下，模型返回的 `official_image` 类型不再自行获得信任，Hub 必须按图片 URL 的实际域名重新分类为厂家官网 / 官方 CDN；伪装官方类型的第三方外链会被拒绝，已补齐对应回归测试。
- 设备图片 Agent 增加厂商品牌约束：已识别厂商的资产只接受本品牌官网或官方 CDN 图片，避免不同品牌的官网图片被模型误标后进入候选；厂商尚未识别的历史资产保持既有官方域名兼容策略。
- 设备图片候选图回归契约修正：选定官方颜色后，Hub 可保留同一配色的多角度官方候选图；只有用户明确选择其中一张时才写为唯一详情主图，测试不再错误限制候选集只能有一张图片。
- Hub API 测试夹具首轮收敛：自动登录和受信认证头的顺序场景改为复用同一个隔离 Hub，仍保持每组测试数据独立；减少重复迁移、启动和清理成本，完整 Hub 测试的后续优化继续以此模式为准。
- 资产详情遗留代码继续收口：移除已经没有渲染入口的资产告警配置、告警历史和通知状态卡，以及其专属类型、格式化和组件依赖；告警中心、通知设置、资产编辑和三列浏览行为不受影响。
- 容器监控无数据首屏收紧：当前机器未上报容器时不再渲染“编排”和“独立容器”两层空分区，改为一张说明 Docker / Podman 上报条件的紧凑空态；加载态、容器分组、表格、详情和控制操作保持不变。
- 网站监控无数据工作台收紧：资产目录和监控列表都加载完成但尚未接入监控时，不再保留空的双栏列表 / 详情工作台和重复入口；改为全宽空态，并按是否已有网页端点提供唯一的“接入网页端点”或“前往资产中心”动作。
- 资产详情二级加载继续收敛：移除仅供已退役卡片使用的网站、告警、通知、容器、SMART、系统统计和告警策略请求，浏览态与编辑工作台继续加载维护、附件、主图、任务和资料补全数据；减少打开资产详情后的并发请求与详情包体，不改变当前查看、编辑或 Agent 流程。
- 资产详情历史展示代码清理：移除已无渲染入口的旧版详细参数、计算机硬件档案、资料完整度、资料来源边界、快捷操作、接口、关系、维护、附件、监控、生命周期与变更历史卡片，当前三列工作台继续复用归档参数和主机硬件分组领域逻辑；减少详情页维护面，不改变资产查看、编辑或 Agent 流程。

- 官方颜色补全写回闭环补齐：资料补全 Agent 获取到官方配色后只生成待确认建议，不会直接覆盖资产主档；用户确认 `colors_available` 建议后才写入主档并生成资产变更历史。
- 设备图片 Agent 生成链路继续收紧：生成前会把已筛选的官方 / 可追溯参考图下载并转成 Data URI 传给 Agnes 图片模型，避免模型只收到不可访问 URL 后凭空生成；已确认的 `official_image_url` 会优先进模型参考输入，图片提示词也改为明确的“参考图编辑”任务，要求保留真实设备外观、官方配色、前后视图、统一背景、统一摆放和白天 / 夜晚两张最终图。
- 设备图片 Agent 稳定性继续补强：调用 Agnes 图片模型遇到 429 或 5xx 等临时失败时会有限重试，编辑工作台会显示“正在收集参考图并调用 Agnes”、失败原因或生成完成状态，避免长时间生成时只看到按钮不可用。
- 设备图片 Agent 生成改为前端异步触发：资产编辑工作台点击“生成统一图”后 Hub 会先创建任务和参考图记录并立即返回，后台继续调用 Agnes 生成白天 / 夜晚图；前端按 `ai_tasks` 轮询阶段进度，完成后自动刷新最终图，成功生成仍会写入操作审计，避免图片模型响应慢时页面长时间卡住或后台成功缺少留痕。
- 设备图片 Agent 任务进度可观测性继续补齐：Hub 会把参考图收集、模型输入准备、白天图生成、夜晚图生成、完成或失败等阶段写入 `ai_tasks.output_summary.phase_history`，运行中任务会显示当前阶段和百分比；失败任务会保留已收集参考图数量、模型候选诊断和跳过原因，便于判断是参考图、模型输出还是网络超时问题。
- 设备图片 Agent 超时和旧任务收敛：Agnes 图片模型单次请求默认超时按官方建议调整为 120 秒，并支持 `PULSE_ASSET_VISUAL_AI_REQUEST_TIMEOUT_MS` / `PULSE_ASSET_VISUAL_AI_REQUEST_TIMEOUT_SECONDS` 在最高 360 秒内调整；同一资产重新触发生成时，超过 15 分钟仍处于 running / queued 的旧图片任务会自动标记失败，避免历史卡死任务继续污染最近任务状态。
- 设备图片 Agent 模型输入继续补强：Agnes 图片模型不再只使用详情页展示用的两张参考图，而是会从全部已收集的可追溯候选里按设备外观相关度排序、过滤规格 / 配色示意图，并在高优先级参考图过大或不可读时继续回退到后续可用真实设备图；实际进入 Agnes 的模型输入限制为最可信的 2 张参考图，跳过原因继续写入任务摘要。
- 设备图片 Agent 的 Agnes 图生图调用继续按官方兼容方式收敛：参考图仍由 Hub 下载、校验并转成 Data URI，但模型输出默认要求 `b64_json`，避免临时图片 URL 下载和过期链路增加不确定性；`ai_tasks.output_summary` 会记录端点、超时、输出格式、参考图数量和请求体体积，便于定位是参考图、请求体还是模型响应问题。
- 设备图片 Agent 任务摘要继续补齐模型请求诊断：资产编辑工作台和 AI 设置页最近任务会直接显示模型输入张数、请求体大小、输出格式和超时时间，运行中、失败和成功任务都能看到关键执行参数，避免只看百分比但无法判断是否被大图 payload 或模型超时拖住。
- 设备图片 Agent 参考图输入继续优化：官网 JPEG / PNG / WebP 参考图超过模型输入上限时，Hub 会先按最长边 1024px 以内缩放并重新压缩为 JPEG，再转成 Data URI 传给 Agnes；无法解码或超过可处理上限的图片才会跳过并记录原因，减少真实官网大图被直接丢弃或拖慢生图请求。
- 设备图片 Agent 增加 Agnes 图片输出格式兼容降级：仍优先请求 `b64_json`，如果 Agnes 在该格式下返回传输失败、超时或明确的 `response_format` 不兼容错误，会自动改用 `url` 输出再由 Hub 下载、校验真实图片字节并固化为 Data URI；任务摘要同步显示主输出格式和备用格式，鉴权错误不会触发降级重试。
- 资产详情页最终设备图显示修复：AI 统一图保存为 Data URI 后，前端不再对 Base64 内容套用普通 URL 的 `icon`、`logo`、`share` 等低质量图片关键词过滤，避免后端已成功生成最终图但详情页仍显示占位图标。
- 设备图片 Agent 参考图过滤继续收紧：厂家产品资源包里的营销横幅、首屏海报、宣传图、配色总览、规格色卡和相机样张不再进入 Agnes 图片模型输入；真实外观图存在时优先使用 `sw2-*`、正面、背面、侧面、外观和产品图库这类设备图，降低生成图偏离实际设备外观的概率。
- 设备图片 Agent 参考图按所选官方配色继续收紧：Hub 下载候选参考图后会在中心设备区域按“墨 / 黑、白 / 银、绿、紫、蓝、金”等颜色语义计算匹配分数，优先只把与用户选择配色匹配的 1-2 张参考图送入 Agnes，并在任务摘要记录颜色匹配分数；图片提示词同步要求只生成所选配色的一台完整设备，禁止把其他配色或多台不同颜色设备混入最终图。
- 设备图片 Agent 提示词继续加强官方图保真：Agnes 图片模型现在会明确以官方参考图作为设备外观来源，禁止重绘或改写机身、镜头数量、相机岛、Logo、按键、比例、材质和颜色，只允许统一背景、摆放和画面呈现。
- 设备图片 Agent 对官网横幅型参考图增加模型输入预处理：宽幅官方图进入 Agnes 前会先裁成居中的竖向设备参考图，再统一压缩为模型可用 JPEG；提示词同步要求移除原始海报场景、只补全被前景遮挡的机身边缘，夜晚图禁止白底 / 浅灰底，并避免伪造或写坏品牌文字，降低 Redmi K50 这类官方海报导致手机显示不全、颜色受背景污染或外观跑偏的概率。
- 资产详情页设备全貌图显示比例继续修正：主图区改为固定竖向 `3:4` 展示框，并取消夜晚模式对主图的额外放大，避免手机被正方形容器或暗色沉浸效果裁切，确保完整机身在首屏内显示。
- 设备图片 Agent 保真和展示比例继续收紧：资产详情页主图框和 Agnes 输出目标统一为固定 `3:4` 竖向画布，图片仍完整 `contain` 显示；宽幅官方海报会先按所选官方颜色裁出设备主体，减少海报光效和场景进入模型输入；Agnes 图生图提示词改为“只替换背景和留边，不重新设计设备”，并按所选官方颜色生成禁用其他颜色的约束；Hub 会拒绝手机类横图、主体比例明显异常或主体颜色明显不匹配的模型输出，并在首次质量不合格时带失败原因自动重试一次，避免错误图继续写入资产主图。
- 设备图片 Agent 超时处理继续收紧：Agnes 图片模型单次请求超时后不再继续重复发起第二、第三轮长耗时请求，会立即把任务标记失败并保留错误摘要；429 / 5xx 等明确临时服务错误仍保留有限重试，避免真实生成长时间卡在“生成中”。
- 设备图片 Agent 的生成结果追溯继续修正：最终生成图只记录实际成功下载、识别并转成 Data URI 后送入 Agnes 的参考图 URL，被跳过的超大图、不可读图和非设备图只保留在跳过原因里，避免候选图和真实模型输入混在一起。
- 设备图片 Agent 的模型输出继续加固：Agnes 返回的最终图必须是解码后仍可识别为图片的 Data URI，或由 Hub 下载真实字节并验证为图片的 HTTP URL；即使 URL 后缀是 `.png` / `.jpg`，也会按字节确认内容类型，如果模型误返回产品页、网页、404、普通文本 Base64 或空结果，任务会标记失败且不会写入 `ai_turntable` 主图，避免错误生成结果污染资产浏览页。
- 设备图片 Agent 的模型输出候选选择继续增强：Agnes 返回多个图片候选时，Hub 会按顺序逐项校验并跳过空值、网页 URL 或非图片 Base64，选择第一个真实可用图片作为最终图，避免第一项无效但后续候选可用时整次生成失败。

- 设备图片 Agent 的模型输出诊断继续补齐：Agnes 返回多个图片候选时，Hub 会把候选总数、实际采用数量、跳过数量和跳过原因写入 `ai_tasks.output_summary`，设置页和资产编辑工作台会显示“模型返回的 URL 不是可验证图片”“Base64 不是可识别图片”等具体原因，方便判断是模型输出异常还是参考图不足。
- 设备图片 Agent 任务摘要兼容历史生成字段：AI 设置页和资产编辑工作台现在会同时识别 `generated_images`、旧版 `theme_images` 和模型实际采用数量，避免历史已生成白天 / 夜晚统一图的任务仍被误显示为“未生成统一图”。

- 设备图片 Agent 的模型输出 HTTP 校验继续收紧：Agnes 返回的 HTTP URL 即使响应头声明为图片，也必须由 Hub 下载真实内容并识别为 JPEG / PNG / WebP / AVIF 后才会写入最终主图；HTML、文本或产品页伪装成图片时会直接失败，不会创建 `ai_turntable`。

- 设备图片 Agent 的模型输出落地继续收紧：Agnes 返回临时 HTTP 图片 URL 时，Hub 会完整下载、按真实字节识别 JPEG / PNG / WebP / AVIF 类型并转成 Data URI 保存到 `asset_visuals.frames`，避免远程图片链接过期后资产详情主图失效；同一任务内会复用已物化结果，避免重复下载同一个模型输出图。

## Agent / 部署

- Agent 网络采集收口为真实物理网卡：Linux 仅保留能确认挂到真实设备路径的接口，Windows 仅保留 `HardwareInterface=True` 且 `Virtual=False` 的适配器；虚拟网卡、桥接、容器、隧道和 TAP/TUN 不再进入 `network_interfaces`，避免详情页和带宽汇总把非物理接口算进去。
- Agent 网络采集继续收口为真实物理网卡，过滤入口和平台物理判定不再向外扩散；虚拟网卡、桥接、容器、隧道和 TAP/TUN 继续剔除，`NICS` 只负责显式黑白名单。
- 暂无 Agent 运行时功能改动；本轮补强了 Agent 网络统计测试和 Hub WebSocket 集成测试的测试隔离，发布 `1.0.5` 时仍必须跟随 Web / 移动端使用同一个版本号重新构建 Hub、Linux / NAS Agent 镜像和 Windows Agent 安装包。
- 修复 Windows Agent 安装脚本生成逻辑：移除未定义的旧数据目录变量引用，避免复制安装命令后 PowerShell 因空路径参数中断安装流程，并补充脚本生成回归测试。
- Windows Agent 安装脚本支持一次性配对码：安装时会先执行 `agent pair --url ... --code ...` 保存凭据，再注册并启动 `pulse-agent` 服务。
- 补充 Windows Agent 安装脚本接口回归测试：覆盖空参数拒绝、一次性配对码生成脚本和非法换行参数拒绝，避免安装入口后续回归。
- 收紧 Agent 版本仓库同步策略：本地 manifest 缺失的版本记录改为禁用并保留原因，不再直接删除；启用版本和禁用版本分别保留最新 2 个，避免跳过推送或缺失镜像时把仍可用的目标版本挤掉。
- Agent 运行时新增采集结果和诊断状态上报：基础指标、容器运行时、SMART、GPU、网络详情、Windows WMI / PowerShell 和运行权限都会给出机器可读状态、检查时间和原因，作为 Hub / Web 判断真实性的来源。
- 补齐 Windows Agent 网卡详情回归测试：覆盖 IPv4、IPv6、默认网关、DNS、DHCP / 静态、MAC 和链路速率字段会完整写入 `network_interfaces`，避免后续采集改动把网络来源字段丢失。
- 修复 Windows Agent 网卡详情运行态采集：兼容 PowerShell 在默认网关字段返回空对象、单个字符串或数组的不同 JSON 形态，并把网卡详情采集改为只查询当前有效网卡、放宽超时，避免真实机器上因为解析失败或 5 秒超时降级成只显示网卡名和 MAC。
- 本机开发 Agent 已替换为重新构建的 `1.0.5`，Hub 入库确认 `network_interfaces` 包含 IPv4、IPv6、默认网关、DNS、DHCP、链路速率和 MAC；系统详情网络卡点击后能展示完整来源字段。
- Agent SMART 采集新增设备级失败退避：同一块盘连续采集失败后按 15 分钟、30 分钟、1 小时逐步延后重试，最多 6 小时；成功采集会自动清除退避状态，避免权限不足或虚拟盘反复触发 `smartctl`。
- Agent SMART 采集新增磁盘介质来源字段：SATA / SCSI 只在 `rotation_rate` 明确存在时标记 SSD 或 HDD，NVMe 标记为 NVMe；字段缺失时留空，避免把未知磁盘类型伪装成真实硬件标签。
- Agent GPU 类型上报收紧：未知 GPU 名称不再默认标记为独显，只有 NVIDIA / Intel / Apple / Jetson 或明确命中的 AMD / Windows GPU 类型才写入核显 / 独显；不能确认时前端不显示类型标签。
- Agent 容器采集新增可信 Compose stack 标记：只有同时采集到 Compose project 和 service 才上报为可信编排；读取 Compose 配置时限制文件大小并脱敏 token、password、secret、key 等敏感字段，避免详情页泄露部署密钥。
