# Pulse 1.0.5 固定发布记录

> 版本已于 2026-06-23 固定为 `1.0.5`。这里保留 `1.0.4` 之后的完整开发流水记录，作为正式发布说明和后续排查的明细来源。固定点之后的新改动不要再回填到 `1.0.5`，应进入下一版本记录。

## Web / Hub

- Agent 管理页 Linux 安装方式恢复默认全能力：通用 Linux、飞牛 / NAS 和 Unraid 现在默认同时开放宿主机根目录、DMI、/dev/mem 和 GPU 采集入口，确保复制出的安装命令默认就能正常安装和连接；工作台仍保留单项能力的手动开关。
- 修复 Unraid / Linux 一次性配对安装在重装后“装上了但检测不到”的问题：配对模板改为显式写入 `/var/lib/pulse-agent/paired.code` 作为首次安装标记，并在标记不匹配时清理旧的 `token` / `paired.env` / `pairing.json` 后重新配对，避免旧状态残留把真正的首次配对跳过去。
- 修复 Unraid / Linux 安装模板里的 `/dev/mem` 设备映射语法：`--device` 不再使用卷挂载专用的 `:ro` 模式，避免 Unraid 执行安装命令时报 `docker: bad mode specified: ro`；普通只读卷挂载仍保持 `:ro`。
- Agent 管理页 Linux 安装命令修复 YAML 语法风险：配对安装的 Compose 预览改成 YAML 原生块标量，配对码通过环境变量传入并在容器内展开，避免单引号 shell 字符串把 `entrypoint` 结构拼坏；同时修正 compose 变量在预览阶段被提前展开的问题。

- Agent 管理页 Windows 安装模板补齐可视化编辑：Windows 目标支持在“一行命令”和“完整 PowerShell 脚本”之间切换，并可编辑安装目录、数据目录、日志目录、重装清理旧数据、NSSM 自动安装、安装后启动服务和出站防火墙规则；页面预览、复制命令和后端 `/api/pulse/agent-install/windows.ps1` 下载脚本共用同一组选项，避免预览和真实执行脚本漂移。
- Agent 安装模板做了一轮源头审计：补充 Windows 安装脚本接口选项回归测试，确认安装目录、数据目录、日志目录、NSSM、清理旧数据、启动服务和防火墙选项都能从复制命令传到真实下载脚本；同时清理 Unraid XML 模板里的旧项目支持链接，避免安装模板继续出现旧 Beszel 残留。
- Agent 管理页桌面端重构为安装工作台：不再按 Windows / Linux 两列堆叠展示，改为上方状态摘要、中间安装模板工作台、下方 Agent 更新和版本仓库分区；Linux、飞牛 / NAS 和 Unraid 模板支持在页面中切换 Docker socket、宿主机只读挂载、DMI 和 GPU 采集入口，右侧代码预览会实时增删对应 Compose / Unraid XML 配置，避免只显示静态模板。
- Agent 管理页 Linux 安装方式拆分为通用 Linux、飞牛 / NAS 和 Unraid 三类：通用版使用 `/opt/pulse-agent/data` 专用目录，飞牛版可直接下载 `pulse-agent-flynas.yml` 并使用 `/vol1/1000/docker/pulse-agent/data`，Unraid 版改为 root 直连下载命令，命令会把 XML 写入 `/boot/config/plugins/dockerMan/templates-user`；添加机器向导的 Linux 下拉同步提供飞牛 yml 和 Unraid 模板下载入口。
- Linux / 飞牛 / Unraid 安装模板默认恢复全能力：页面预览和下载脚本默认保留宿主机根目录、DMI、/dev/mem 和 GPU 设备映射；Linux 直接安装命令会在 `docker` 无权限时自动尝试 `sudo docker`，并在文档里继续要求飞牛用户具备 Docker 权限。
- 添加系统复制安装命令入口修复同一命令二次触发手动复制弹窗的问题；关闭手动复制窗口后再次点击 Windows / Linux 安装命令会重新打开复制内容，安装命令生成和配对逻辑保持不变。
- 修复添加系统弹窗和手动复制命令弹窗的嵌套关闭问题：关闭复制命令兜底弹窗时不再连带关闭添加系统弹窗，避免安装会话、目标 IP 和当前接入步骤被误丢失。
- 客户端资产卡片桌面端改为自动填充固定最大列宽，超宽屏下单张机器卡不再被拉得过宽；小屏单列、筛选、排序、点击进入详情和真实指标展示逻辑保持不变。
- 网站监控详情页目标地址区固定展示外网入口：未配置外网地址时显示“未配置”中性状态，不再缺失外网区域或把未配置误显示为待检测；检测状态条、响应趋势和历史统计仍只使用真实配置的检测目标。
- 网站监控桌面端左侧列表分页栏改为固定在列表卡片底部显示，中间监控卡片区域自动占满剩余高度；分页、筛选和检测数据逻辑保持不变。
- 客户端资产卡片和系统详情顶部的 `Uptime` 中文文案从“正常运行时间”简化为“运行时间”，降低卡片字段长度；运行时间数据来源、格式化和排序逻辑保持不变。
- 客户端资产卡片的 CPU 负载改为三段式可视化：用 1 分钟、5 分钟、15 分钟负载条按线程数归一化展示，并沿用现有告警阈值颜色；仍保留当前负载数值和 tooltip，排序与真实 `la` 数据来源不变。

- 客户端资产卡片的 CPU / 内存 / 磁盘 / GPU 指标条继续按 Cal 风格收紧：资源指标改为独立整行对象，数值右对齐，进度条改为真正按卡片宽度自适应的浅色轨道 + 内部填充，不再被图标 / 标签列挤成短条；负载合并到 CPU 指标行右侧，仅在 Agent 真实上报 load average 时显示；真实百分比、阈值颜色和指标缺失状态逻辑保持不变。

## Agent / 部署

- Agent 网络采集收口为真实物理网卡：Linux 仅保留能确认挂到真实设备路径的接口，Windows 仅保留 `HardwareInterface=True` 且 `Virtual=False` 的适配器；虚拟网卡、桥接、容器、隧道和 TAP/TUN 不再进入 `network_interfaces`，避免详情页和带宽汇总把非物理接口算进去。
- Agent 网络采集继续收口为真实物理网卡，过滤入口和平台物理判定不再向外扩散；虚拟网卡、桥接、容器、隧道和 TAP/TUN 继续剔除，`NICS` 只负责显式黑白名单。
- 暂无 Agent 运行时功能改动；本轮补强了 Agent 网络统计测试和 Hub WebSocket 集成测试的测试隔离，发布 `1.0.5` 时仍必须跟随 Web / 移动端使用同一个版本号重新构建 Hub、Linux / NAS Agent 镜像和 Windows Agent 安装包。
- 修复 Windows Agent 安装脚本生成逻辑：移除未定义的旧数据目录变量引用，避免复制安装命令后 PowerShell 因空路径参数中断安装流程，并补充脚本生成回归测试。
- Windows Agent 安装脚本支持一次性配对码：安装时会先执行 `agent pair --url ... --code ...` 保存凭据，再注册并启动 `pulse-agent` 服务。
- 补充 Windows Agent 安装脚本接口回归测试：覆盖空参数拒绝、一次性配对码生成脚本和非法换行参数拒绝，避免安装入口后续回归。
- 收紧 Agent 版本仓库同步策略：本地 manifest 缺失的版本记录改为禁用并保留原因，不再直接删除；启用版本和禁用版本分别保留最新 2 个，避免跳过推送或缺失镜像时把仍可用的目标版本挤掉。
- Agent 运行时新增采集结果和诊断状态上报：基础指标、容器运行时、SMART、GPU、网络详情、Windows WMI / PowerShell 和运行权限都会给出机器可读状态、检查时间和原因，作为 Hub / Web 判断真实性的来源。
- 补齐 Windows Agent 网卡详情回归测试：覆盖 IPv4、IPv6、默认网关、DNS、DHCP / 静态、MAC 和链路速率字段会完整写入 `network_interfaces`，避免后续采集改动把网络来源字段丢失。
