# Pulse 项目待办清单

> 统一记录尚未完成的功能、问题和优化建议。长期方向维护在 `docs/pulse-roadmap.md`，已完成内容维护在版本说明中。

## 使用规则

- 类型：新功能、问题、优化、基础建设、待核实。
- 优先级：紧急、重要、普通、以后再做。
- 状态：待确认、待开发、开发中、待验证、已完成、暂缓。
- 开发前明确范围、影响和验收标准；完成并写入版本记录后再归档。
- 重要功能、跨模块改造、权限或数据结构变化在进入“开发中”前，先完成简短中文设计并取得用户确认；小修复和低风险小改动可直接执行。
- 同步到 GitHub Issues 或其他外部平台前，必须取得用户确认。
- 每个完整开发阶段结束时更新受影响待办的状态和验收结果，并核对相关文档；正式发布前执行一次全面文档检查。
- 完成待办时记录关键验证结果、未覆盖范围和剩余风险；普通任务不附大段原始日志，高风险任务的完整证据必须先脱敏。
- 重要待办和决策记录简短背景：为什么要做、为什么采用当前方案、由什么条件触发重新评估；不要把整段聊天复制进待办。
- 新待办信息不足时先标记为“待确认”并调查现状；只有涉及产品方向、明显取舍或无法可靠推断的信息时，才整理少量中文选项请用户决定。
- 开发中发现的计划外问题，先按是否阻碍当前功能、影响数据或安全、导致验证失真或必须关联修复来判断；需要当前处理的写入本阶段范围，其他问题新增待办并标记优先级，不在未说明时混入当前改动。
- 质量检查问题按风险分批进入待办：功能、安全、数据、权限和构建问题优先，格式与一般规范分批处理；每批必须记录验证结果和剩余问题。
- 升级和迁移类待办必须写清旧数据如何兼容、备份与回退路径、失败停止条件、验证范围和用户配合事项；未完成迁移验证前不得标记为已完成。
- 关键链路待办必须包含自动测试要求；涉及界面时同时写明桌面和手机浏览器验收范围。测试优先覆盖风险与行为，不以测试数量作为完成标准。
- 用户可见待办必须包含普通家庭用户视角的体验验收，检查中文文案、入口、按钮、状态、反馈和错误后的下一步；体验检查不能替代权限、数据和异常测试。
- 重要功能待办必须写明上线后的观察期限、观察项目、异常处理和结束条件；涉及数据、权限、Agent、告警、备份或正式链路的待办，观察稳定前不得关闭。低风险小改动完成验证后无需观察期。
- 观察期默认按风险填写：一般重要功能为 24 小时，高风险正式链路为 3 至 7 天；发生异常时延长观察并更新待办中的稳定起算时间和结束条件。
- 涉及采集、刷新或后台任务频率的待办必须说明实时性收益、CPU、内存、磁盘、网络和数据库增长影响，并给出验证指标；默认选择满足使用目标的最低合理频率。
- 涉及设备状态和采集数据展示的待办必须验证在线、短暂离线、长期离线和恢复四种状态；旧数据要显示采集时间并标记为历史值，不得伪装成实时状态，恢复后应自动续采且不产生重复告警。
- 涉及采集能力的待办必须验证支持、未启用、权限不足、依赖缺失、暂时失败、未知和真实零值等状态；页面要显示明确原因与可行下一步，不能把失败状态伪装成 0 或正常。
- 涉及自动重试的待办必须写明哪些操作可以安全重复、最大次数、等待间隔、停止条件、失败留痕和告警方式；高风险操作默认禁止自动重试，并验证不会重复生效。
- 涉及 Hub 与 Agent 协议或版本的待办必须列出兼容范围、降级行为、受限功能和统一升级路径；验收时覆盖同版本、可兼容版本和不兼容版本，确保基础监控与危险操作按规则分别处理。
- 安全漏洞待办必须记录受影响组件、实际版本、利用条件、严重程度、Pulse 是否受影响的证据、修复方案、测试范围、备份与回退方式和复查条件；确认受影响的高风险漏洞优先级不得低于“重要”。
- 依赖与安全检查按每月一次和发布前一次执行；检查记录要写明日期、范围、实际版本、发现项、影响判断和处理状态。需要联网或新增扫描工具时先取得用户确认。
- 涉及正式环境维护、升级、迁移或回滚的待办必须写明预计中断时长、影响范围、备份与回退方案、验收步骤和用户确认的执行时间；未确认维护时间前不得进入正式执行。
- 正式维护待办必须写明暂停与重新确认条件：中断明显超时、风险变化、方案变化或操作范围扩大时先停在安全状态；同时记录当前现场、可选方案、用户重新确认结果和后续步骤。
- 正式维护待办完成时必须附中文简短结果报告，记录实际操作、实际中断时长、验证结论、异常处理、观察期、剩余风险和用户配合事项；关键证据单独脱敏保存。
- 备份与恢复待办默认以“最多丢失最近 24 小时新数据”为验收目标，并验证重要变更前额外备份；恢复报告要写清实际恢复点和可能缺失的数据时间范围。
- 严重故障处置待办以“尽量在 4 小时内恢复基本使用”为目标，优先级顺序为登录、账号与核心资料、状态查看、告警、必要设置，最后恢复非关键图表和高级功能；外部阻碍和替代方案必须记录。

## 重要

### PBL-015 将 Windows Agent 升级为可安装软件

- 类型：重要功能
- 状态：开发中
- 设计文档：`docs/superpowers/specs/2026-09-01-windows-agent-installer-design.md`（待用户确认）
- 决定：Windows 版提供标准安装包、Windows 后台采集服务和按需打开的中文连接配置窗口，不提供托盘程序；Linux、飞牛、NAS 与 Unraid 继续使用 Docker。
- 当前阶段结果（2026-09-02）：已确认本机 Wails CLI v2.15.0 和 Inno Setup 6.7.3 可用；新增 Inno Setup 安装脚本与本地构建脚本，已成功生成 Windows Agent 1.0.6 / 1.0.7 测试安装包。已在当前开发测试机完成真实安装、服务自动启动、关闭配置窗口后服务继续运行、开始菜单入口、彻底卸载清理、覆盖升级和异常自动恢复验收：`1.0.6` 覆盖到 `1.0.7` 后服务和配置均保留，强制结束服务进程后 Windows 按 5 秒策略自动恢复并回到 Running。当前剩余连接配置与网页更新闭环验收；现有 Inno Setup 未带简体中文语言包，中文安装界面暂列为待确认的工具补充项。
- 当前阶段结果（2026-09-03）：Windows Agent 更新已补齐阶段状态记录和独立回退目录；失败时会尝试恢复旧程序并清理新文件。Hub 会等待新版本重连并核对真实运行版本，且优先识别本次目标版本的失败结果；本机故意校验失败更新实测记录为 `failed / rollback`，旧版 `1.0.9`、服务自动启动、连接配置和 Hub 健康状态均保持正常。网页最终失败状态已修复并完成真实验收；正式发布前仍需在发布包上再做一次完整演练。
- 当前阶段结果（2026-09-03）：完成正常采集状态下的本机资源采样（4 次、每次间隔 10 秒）：服务私有工作集约 `16.4 MB`，峰值 CPU 计数为 `0%`，平均磁盘读取约 `5.84 KB/s`，写入接近 `0`；服务保持自动启动和运行。该结果只代表基础常驻状态，SMART、GPU、磁盘扫描等重采集任务的瞬时峰值仍需在发布包上补测。
- 原因：让技术初学者能够像安装普通软件一样完成安装和配置，同时保证退出界面或未登录桌面时仍可持续采集，并控制常驻资源占用。
- 资源边界：重点保证后台采集服务轻量，开发和验收时测量 Agent 的 CPU、内存、磁盘、网络和后台任务占用；网页端以流畅、稳定、无明显卡顿和无明显资源浪费为标准，不设置苛刻的极限资源上限。
- 初步边界：后台服务负责持续采集、连接 Hub、接收网页指令和执行更新；按需打开的本地窗口只负责 Hub 连接配置。采集数据、能力设置、诊断、日志、更新及其他操作统一由 Pulse 网页管理。
- 安装体验：安装程序不提供桌面快捷方式选项，也不创建桌面图标。安装时在开始菜单创建“Pulse Agent”文件夹，文件夹中必须包含“Pulse Agent”和“卸载 Pulse Agent”两个入口，同时保留 Windows 设置中的标准卸载入口。
- 安装位置：安装页面始终允许选择路径，默认优先使用空间合适的非系统本地固定磁盘并创建“Pulse Agent”根文件夹，不默认装到 C 盘，也不自动选择移动盘或网络盘。只有 C 盘或用户主动选择 C 盘时，显示目标路径、预计占用和可用空间，由用户明确确认后允许继续。
- 文件归属：程序、服务、连接配置程序、内置组件、配置、连接凭据、缓存、日志、更新包和回退文件统一放入所选根文件夹的明确子目录；秘密目录使用 Windows 文件权限保护。服务注册、卸载登记和快捷方式等 Windows 必需登记留在系统管理位置，卸载时一并清理。
- 卸载体验：提供 Windows 标准卸载入口；卸载程序必须停止并删除后台服务和连接配置进程，清理安装目录、快捷方式、服务登记、安装器创建的防火墙规则、临时文件和其他安装器创建项，不遗留失效服务或孤立入口。连接凭据、本地缓存、日志与用户配置必须明确询问保留或彻底删除，彻底删除前二次确认。
- 卸载数据默认值：默认彻底删除连接凭据、配置、缓存和日志，并在中文二次确认中提示重新安装需要重新连接；允许用户主动选择保留配置，但该选项不得默认勾选。
- Hub 记录边界：卸载程序不远程删除 Hub 中的设备记录、历史监控和告警；卸载后设备保留并标记离线，管理员需要时再在 Pulse 中单独二次确认删除。
- 首次配置流程：从资产管理中选择已有的主机资产（资产已有名称和 IP），点击接入监控后由 Pulse 网页为该资产生成并长期保留唯一机器连接码；再完成软件与后台服务安装，首次安装成功后只自动打开一次中文连接配置窗口，填写 Hub 地址并输入网页提供的机器连接码。安装错误与连接码验证错误分开显示，配置失败不回滚安装。关闭后不再自动打开，后续只能从开始菜单重新配置。
- 暂缓配置：首次安装后可以不填写 Hub 并直接关闭窗口，后续从开始菜单继续配置，无需重新安装。未配置时后台服务保持开机自启，但只低频等待配置，不进行高频连接；窗口和网页相关状态必须区分“尚未配置”与“连接失败”。
- 连接完成：连接成功后窗口显示“连接成功”和当前 Hub 地址，并提供“打开 Pulse 网页”和“关闭”两个主要按钮；窗口不自动关闭。打开网页使用系统默认浏览器，关闭窗口后界面进程退出且后台服务继续采集。
- 连接码验证失败：保留已填写的 Hub 地址并立即清空本地连接码输入，不把失败输入写入本机；机器连接码由 Pulse 网页在选定资产的接入记录中生成并长期保留，添加过程中和添加完成后都可由管理员查看和复制，本地窗口不提供生成或重置入口。分别显示“地址无法访问”“机器连接码错误”“机器连接码已被重置”等原因，并提供“重试”和“关闭”。需要换码时由管理员在网页重置后再复制填写。
- 已连接状态：从开始菜单再次打开时显示“已连接”、当前 Hub 地址，以及“打开 Pulse 网页”“重新配置连接”“关闭”。重新配置需要新的 Hub 地址和对应资产的机器连接码，验证成功并二次确认后原子切换；失败时继续使用原连接，不产生重复设备或半配置状态。
- 已连接后当前 Hub 地址只读显示，不能直接改写；点击“重新配置连接”并取得编辑权后，才出现新的 Hub 地址和机器连接码输入区域。取消、失败或未确认时保留旧连接。
- 重新配置提醒：进入重新配置后先显示“验证成功并确认后，旧连接会被替换；验证失败不会影响当前连接。”在新连接完成验证和二次确认前，旧连接继续使用。
- 重新配置提醒需要用户先点击“我知道了”，之后才显示或启用新的 Hub 地址和机器连接码输入区域；确认前不能提交或修改连接。
- 重新配置采用两步确认：先“验证新连接”，验证成功后再确认替换；验证失败只显示原因，旧连接继续使用。
- 验证成功后的最终按钮使用“确认替换连接”，旁边再次显示“旧连接将在确认后失效”；用户取消时保留旧连接。
- 执行替换时显示“正在切换连接”，暂时禁用关闭、返回和重复点击；确认后台服务已使用新连接后显示“连接已更新”，再恢复操作。
- 切换失败时显示“连接切换失败，仍在使用旧连接”，并提供“重试切换”和“返回”；重试不覆盖旧配置，返回放弃本次新连接。
- 点击“返回”放弃切换前先确认“确定放弃本次连接切换吗？”；取消确认则保留新输入继续操作，确认后清空新地址和机器连接码并回到旧连接状态。
- 机器连接码长期有效，不设置自动过期；在“资产监控”页面点击“添加监控”后，先在当前添加页面填写和确认机器信息，不立即生成连接码。只有点击“确认添加”并成功创建监控接入记录后，才为没有连接码的资产生成唯一机器连接码并直接显示；重复打开或取消添加不会生成新码，已有连接码的资产继续使用原码；添加完成后仍在该资产接入记录中持续显示。网页向管理员直接显示完整机器连接码，不使用星号遮挡，也不提供额外的查看 / 隐藏入口。管理员可以点击“复制机器连接码”，复制结果始终是完整连接码。复制成功提示“机器连接码已复制”，失败提示“复制失败，请手动选择连接码复制”；复制动作记录操作人、时间和对应资产，但审计中不保存连接码原文。管理员可重置连接码，点击后先说明旧码立即失效、现有已保存连接继续按当前状态运行、重新安装或重新配置必须使用新码；确认弹窗只提供“取消”和“确认重置”按钮，不要求输入机器名称或固定文字。确认后立即生成并显示新码，旧码不再显示，同时短暂提示“机器连接码已重置”，提示几秒后自动消失，并记录操作审计；本地输入已重置旧码只清空本地输入，旧连接是否继续工作按现有连接状态处理。
- 唯一接入记录：每台资产同一时间只能有一条有效的监控接入记录。已有记录的资产不再出现在“添加监控”的可选列表中；尚未连接成功或连接码生成失败的记录也算已占用，后续操作必须回到原记录完成。重新接入时复用原记录并重置连接码或重新配置连接，不创建第二条记录，避免重复机器、数据和告警。
- 删除监控目标：管理员可在资产监控记录中点击“删除监控目标”，这是高风险操作，确认弹窗直接提示“删除后会删除该监控目标的所有历史记录，包括历史指标、历史告警和其他监控数据，且无法恢复”，同时说明保留资产资料和删除操作审计；按钮为“取消”和“确认删除监控目标”。确认后停止接收新数据，当前机器连接码和已发放连接凭据立即失效，资产重新进入“添加监控”候选。以后重新添加时创建新的接入关系、新连接码和全新数据记录，不恢复旧凭据或旧监控历史。
- 删除后的上报：原 Agent 继续上报时由 Hub 直接拒绝，并返回“当前监控已删除”；不保存新数据，不反复弹窗或重复通知，只在系统日志和删除操作记录中记录拒绝事件。重新添加资产并生成新机器连接码后才恢复接入。
- 本地删除状态：Windows Agent 收到删除结果后，本地窗口明确显示“当前监控已删除”，不显示为普通连接失败。后台服务保持安装和开机自启，停止正常上报并只做低频连接检查；保留原连接配置用于排查，不自动清除。窗口提供“打开 Pulse 网页”“重新配置连接”和“关闭”，重新添加资产后使用新的机器连接码完成重新配置并恢复接入。
- 连接码失败提示：首次生成失败只弹出“机器连接码生成失败”，但保留已经创建的监控接入记录；原记录显示“重试生成机器连接码”按钮，管理员可再次点击生成并重试，成功后显示连接码且不重复创建监控记录。该按钮只用于尚无连接码的失败记录，已有连接码时使用“重置机器连接码”。失败后继续保留记录并允许后续重试。重置失败只弹出“机器连接码重置失败”。失败时保留原页面状态和原有连接码，不显示技术原因、不让旧码失效；详细原因写入系统日志供管理员后续查看，日志不记录连接码原文。
- Hub 暂时离线：已连接设备显示“已连接，当前无法连接”，保留当前 Hub 地址和有效凭据，并提供“重试连接”“打开 Pulse 网页”“重新配置连接”“关闭”。临时离线不要求重新输入机器连接码、不清除配置；网页打不开时只提示无法访问。
- 手动重试：“重试连接”只让后台服务立即尝试连接一次，窗口显示“正在连接”及“连接成功”或“连接失败”。不修改任何配置，不无限重复；失败后保留原连接并允许稍后再次手动重试。
- 本地界面启动：不提供托盘、桌面快捷方式或界面自启动项；用户点击开始菜单中的“Pulse Agent”时只打开连接配置窗口，关闭窗口后界面进程直接退出，后台服务继续运行。
- 窗口单实例：连接配置窗口已经打开时，再次点击开始菜单入口只把原窗口切换到最前面，不创建第二个进程或窗口，不重复提交配对、不覆盖正在编辑的内容，也不改变后台服务状态。
- 标准窗口按钮：连接配置窗口保留普通 Windows 软件的“最小化”“最大化 / 还原”和“关闭”三个标题栏按钮。最小化后进入任务栏，不创建托盘图标；最大化与还原只改变显示尺寸；关闭后界面进程退出并释放资源。三种操作都不影响后台采集服务。
- 未保存关闭提醒：仅当 Hub 地址、机器连接码或其他连接内容已修改但尚未成功保存时，点击标题栏或界面内“关闭”才显示“更改尚未保存，确定关闭吗？”。选择继续编辑时保留输入，确认关闭时丢弃未保存内容；没有修改时直接关闭。未提交的机器连接码不得保存到本机磁盘、日志或后台服务。
- 默认窗口位置：不记忆上次的窗口大小、最大化状态或屏幕位置，每次启动使用产品设定的默认大小和默认位置。显示器被拔掉、分辨率改变或原位置已不在当前可用屏幕范围时，自动恢复默认大小并将窗口放到当前主屏幕中央，避免窗口打开后无法找到。
- 窗口缩放：本次打开期间允许自由拖动调整窗口大小，并支持标准最大化与还原；关闭后不保存调整结果，下次仍恢复默认大小。设置合理的最小宽度和高度，保证中文文案、状态、输入框和主要按钮完整可见且不重叠，到达最小尺寸后不能继续缩小；具体尺寸在实现时按最终内容和 Windows 显示缩放实测确定。
- 管理员权限边界：连接配置窗口默认使用普通用户权限；打开和关闭窗口、查看服务或连接状态、打开 Pulse 网页以及不修改配置的单次重试均不弹出管理员确认。只有首次连接验证成功后保存连接、重新配置 Hub 并替换原连接等需要写入受保护配置的操作，才通过 Windows 标准管理员确认临时授权，不让整个窗口长期以管理员身份运行。用户取消或授权失败时不保存新配置、不替换原凭据、不改变后台服务，并显示“未获得管理员权限，连接设置未保存”。
- Windows 多账号：开始菜单“Pulse Agent”文件夹和配置入口对本机所有登录账号可见。任一账号均可用普通权限查看这台电脑共用的服务状态、当前 Hub 地址和连接状态，但不能读取连接凭据；首次保存或重新配置仍须管理员确认。整台电脑只使用一份生效连接配置，不按账号创建多套连接；配置窗口单实例仅约束当前登录会话，不跨账号桌面抢占窗口。
- 跨账号编辑保护：整台电脑同一时间只允许一个账号编辑首次连接或重新配置；其他账号可以继续查看状态，但连接编辑入口暂时禁用并显示“另一位用户正在修改连接，请稍后再试”。保存、取消、确认关闭或界面异常退出后自动释放编辑权，并能清理崩溃、注销或断电留下的失效占用；未取得编辑权的窗口不能写配置、提交配对码或覆盖在途内容。
- 状态自动刷新：配置窗口打开时自动刷新后台服务、Hub 连接和最近连接结果，不要求用户重新打开窗口；窗口最小化或不可见时降低刷新频率，具体间隔按实现阶段的资源实测确定。状态变化只更新文字、图标、颜色和更新时间，不弹提示框。读取失败时显示“暂时无法获取状态”，上一次结果只能作为带更新时间的历史状态展示，不能冒充当前状态；恢复后自动更新为最新真实状态。
- 手动刷新状态：状态区域右上角提供带中文悬停说明的标准刷新图标按钮。点击后只立即读取一次服务、Hub 连接和最近连接结果，不修改配置、不触发重新连接、不启动或重启服务，也不要求管理员权限；刷新期间禁止重复点击，结束后显示最新刷新时间。读取失败继续显示“暂时无法获取状态”及带时间的历史结果。“刷新状态”与会主动连接 Hub 的“重试连接”必须在名称、位置和反馈上清楚区分。
- 手动启动服务：仅在后台采集服务确认停止且没有处于 Windows 自动恢复过程中时显示“启动服务”。点击后请求 Windows 管理员确认，只启动服务，不修改 Hub 地址或连接凭据；启动期间显示“正在启动服务”并禁止重复点击，成功后自动刷新真实状态。取消授权或启动失败时不自动反复重试，保留原配置并显示中文原因和下一步。自动恢复中只显示“正在恢复服务”，状态无法确认时不显示启动按钮。
- 不提供本地停止：连接配置窗口不提供“停止服务”或其他停止采集入口，只保留故障恢复用的“启动服务”。主动停止 Windows Agent 统一在 Pulse 网页中进行，由管理员选择设备、查看设备离线、监控中断和告警影响后中文二次确认；网页记录执行进度、结果和失败原因，本地窗口不能绕过确认。
- 运行控制统一到网页：停止、重启、暂停采集、恢复采集、进入或退出维护状态，以及后续同类运行控制均不放入本地连接窗口。Pulse 网页在执行前展示目标设备、当前任务或更新状态、预计离线时间、监控与告警影响及恢复方法，并要求管理员中文二次确认；执行中展示进度，结束后记录真实结果。更新、连接切换或其他互斥任务进行中时拒绝冲突操作并说明原因。本地“启动服务”只用于服务意外停止后的故障恢复。
- 本地版本信息：连接配置窗口底部只读显示真实的“Agent 版本”和“配置程序版本”，用于排查版本不一致或更新失败；读取不到时显示“暂时无法获取”，不能使用目标版本或默认值冒充。版本不一致时显示双方实际版本和简短兼容状态；更新按钮、更新说明、版本选择、升级和回退仍全部放在 Pulse 网页中。
- 不显示文件路径：连接配置窗口不显示安装位置、程序、配置、凭据、缓存、日志、更新或回退目录，也不提供打开目录按钮。需要查安装位置时使用 Windows 开始菜单“Pulse Agent”图标的系统右键功能；普通账号不能因此接触连接凭据或秘密目录。详细目录说明保留在安装文档，日志和诊断管理继续放在 Pulse 网页管理员页面。
- 本机名称：连接配置窗口只读显示 Windows 当前真实电脑名，帮助确认正在配置哪台电脑；读取失败时显示“暂时无法获取”，不使用设备显示名称或缓存值冒充。本地不能修改电脑名或 Pulse 设备显示名称，设备显示名称继续在网页中管理，并与 Agent 上报的真实主机名保持区分。
- 复制错误信息：本地错误先显示中文原因和下一步，错误区域提供带中文悬停说明的复制图标。复制内容仅包含错误编号、时间、本机名称、组件版本、服务与连接状态及简短原因，并统一隐藏配对码、凭据、Token、密码和授权信息；不复制完整日志、秘密目录或无关数据。只写入当前用户剪贴板，不自动上传或发送；成功提示“错误信息已复制”，失败提示“复制失败，请稍后重试”。详细日志与诊断继续在 Pulse 网页中管理。
- 机器连接码输入：Pulse 永久统一使用 6 位数字机器连接码，显示时可按 `123-456` 分组，输入时自动忽略空格和短横线；以后不再规划或兼容 `PMC-...` 长码。机器连接码由资产接入记录提供，本地窗口只提供明文输入框，不做隐藏处理，不提供显示 / 隐藏、生成、重置或复制入口。验证成功、失败、放弃修改或关闭窗口后立即清空本地输入；原始连接码不写入本机日志、错误信息或剪贴板，后台只保存受保护的连接凭据。
- 服务启动：后台采集服务随 Windows 开机自动运行，不依赖用户登录或连接窗口。异常退出后由 Windows 按有限次数和合理间隔自动恢复；连续失败时停止反复重启并记录真实原因，供 Pulse 网页和连接窗口显示。
- 服务状态：点击“Pulse Agent”入口不额外启动或重启服务，只读取并显示当前服务和连接状态。恢复失败时显示中文原因和下一步，服务恢复由 Windows 服务机制负责。
- 本地窗口：不使用五标签页，只保留一个按需打开的轻量连接配置窗口，显示服务状态、当前 Hub、连接状态和最近连接结果，并提供 Hub 地址、机器连接码、连接或重试、重新配置和“打开 Pulse 网页”。关闭窗口后释放界面资源，不影响后台采集。
- 连接切换：更换 Hub 必须使用新地址和对应资产的机器连接码，先测试再二次确认，成功后原子切换，失败时保留旧配置。验证旧凭据不跨 Hub 复用、不会产生重复设备或半配置状态。
- 网页管理边界：采集数据、采集能力、增强项、软件与服务、容器、详细日志、诊断、Agent 更新、更新进度和设备操作全部在 Pulse 网页进行；本地连接窗口不得重复实现。
- 采集组件策略：常用轻量组件可随安装包内置，但要逐项核对来源、维护状态、许可证、文件校验、体积、运行资源和实际采集收益，并纳入统一升级与彻底卸载；特殊硬件或大型组件按需安装，安装前必须确认。
- 采集模式：Agent 安装后默认开启全部已实现的采集项目，覆盖基础指标、常见硬件、网络、内存、Windows 服务、手动软件状态、硬盘健康、温度、GPU、Docker / Podman、虚拟机和特殊硬件等。采集失败或能力不存在时必须显示“不可用”及真实原因，不得显示为正常、0 或空白。
- 采集频率：CPU、内存、网络在线状态和基础运行状态默认每 30 秒采集；磁盘使用量、温度、GPU、Docker / Podman、Windows 服务和软件状态默认每 60 秒采集；S.M.A.R.T. 与虚拟机清单默认每 5 分钟采集。窗口最小化、Agent 离线或项目关闭时降低或暂停无效采集；网页按机器提供频率调整和当前资源影响展示。
- 采集开关：所有采集项目分别使用独立开关，安装后默认开启；用户可在网页按机器关闭不需要的项目，关闭后停止对应后台任务并显示“已关闭”，不影响其他采集。依赖缺失或设备不支持时，对应项目显示中文原因与下一步。
- 日志与诊断：统一在 Pulse 网页显示中文摘要、按需技术详情和脱敏诊断导出；本地连接窗口不提供日志和诊断管理。
- 软件更新：只能在 Pulse 网页发起。网页显示中文更新内容、预计影响、更新进度和是否需要重启服务；管理员二次确认后由 Hub 下发任务，失败时保留或恢复旧版本，不能留下半更新状态。
- 更新来源：Windows Agent 仅通过当前已连接并认证的 Pulse Hub 获取可用版本、更新说明、安装包和校验信息，不直接访问 GitHub。Hub 只提供管理员允许的版本；Agent 下载后独立校验版本、完整性和发布可信性，失败时拒绝安装并继续运行当前版本。Hub 不可达时不得影响现有采集。
- 更新入口：Pulse 网页是唯一入口，管理员选择目标 Windows 设备并二次确认后由 Hub 下发任务；网页展示准备、下载、校验、安装、重启、重新连接和成功或失败状态。本地窗口不提供检查更新或“立即更新”。
- 设计前必须确认：安装向导步骤、配置页面、管理员权限边界、秘密信息保存、升级与卸载行为、采集完整度矩阵、安装包技术和资源目标。
- 验收方向：普通用户可通过图形界面完成安装与配对；重启电脑和关闭界面后继续采集；连接窗口状态准确且关闭后无界面进程常驻；权限或依赖不足时显示中文原因；卸载与升级可回退且不泄露凭据。
- 重新评估条件：Windows 后台服务无法满足所需采集或安装包资源目标，或主流安装技术带来不可接受的维护成本时，再讨论替代方案。

### PBL-026 容器模式下本机 Agent 无法连接（专用本地身份在 NAT 后失效）

- 类型：问题 / 待核实
- 优先级：普通
- 状态：待核实（2026-10-24 1.0.7 发布时发现，已初步定位根因）
- 现象：1.0.7 发布用容器模式运行 Hub 期间，本机（Nacht，is_local=true）系统记录持续 down、版本停更在 1.0.11-test；切回源码模式后本机立即上线并上报真实版本 1.0.7（其二进制已提前手动替换）。期间主力机（GuteNacht，192.168.1.5）其实一直在线——当时 ping 不通只是防火墙拦截 ICMP，造成「关机」误判。
- 根因（初步）：本机 Agent 用专用本地 Token 连 `http://127.0.0.1:8090`（见 D:\Pulse Agent\data\paired.env），容器 bridge 端口映射经 NAT 后 Hub 看到的连接来源不再是 127.0.0.1，本地身份识别失败、专用 Token 被拒，连接循环失败；期间也未创建第 5 条系统记录（连接从未成功）。源码模式直连无 NAT，一切正常。
- 影响：容器模式运行 Hub 时本机监控掉线（其余三台正常）；「本机版本显示滞后」是同一问题的表象，不是独立 bug。
- 待办：让容器模式也正确识别本机 Agent（按指纹/Token 而非来源 IP 判定本地，或本机容器改用等价于 host 的网络方案），修复后在本机容器模式验证本机上线与版本刷新；在此期间若用容器模式日常浏览，需知晓本机监控会掉线。
