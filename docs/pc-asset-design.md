# 计算设备资产方案（品牌整机 / 自组装）

> 2026-10-07 定稿。适用范围：PC 大类全部类型（物理主机 / 迷你主机 / NAS / 服务器）。
> 本文档是计算设备参数结构、获取方式、维护模型与页面布局的定稿方案，后续实施以此为准。

## 一、核心原则

1. **装机方式由用户在添加时必选**（品牌整机 / 自组装），系统不做判断；选择结果写入字段 `build_mode`（brand / diy），全程跟随资产，资产卡与详情页头部带可见标签。
2. **两种模式的档案级别完全一致**：固定 12 组参数分组相同，唯一区别是**填写与获取方式**——品牌机可"整机型号一次获取整包"，也可任意组单独填写/单独获取；自组装逐配件填写、逐配件获取。
3. **所有获取的参数都必须人工确认后才写入**（获取 → 候选 → 勾选 → 写入）；手动填写的字段视为已确认。
4. **系统名 ≠ 硬件品牌**：UNRAID / 飞牛 fnOS / PVE / Windows 是操作系统，归「系统与负载」组；硬件档案只写真实硬件。
5. **维护按对象分层**：品牌机默认关联整机，自组装关联到具体硬件组/配件；两种模式都支持"整机级"与"组级"维护记录。

## 二、固定参数分组（12 组 + 购买与保修）

| # | 分组 | 典型内容 | 获取方式 |
|---|------|---------|---------|
| 1 | 设备档案 | 编号、设备名称、厂商、型号、IPv4、官方网站、位置、用途、状态、加入监控（标签） | 手动（编号自动；品牌机可按型号获取部分） |
| 2 | 外观 | 形态、颜色、尺寸、净重、安装方式。品牌机：随整机型号直接获取；自组装：按机箱/外观填写与获取 | 品牌机随整机；自组装按机箱 |
| 3 | CPU | 厂商、型号、核心/线程 | 品牌机：整机获取；自组装/单独组：按型号获取 |
| 4 | 内存 | 容量、类型、频率、通道、最大支持；自组装可多条 | 同上（可多条） |
| 5 | 存储 | 盘位 / 硬盘位、已装盘（型号/容量/接口）；可多块 | 同上（可多块） |
| 6 | 显卡 | 厂商、型号、显存（核显/独显） | 同上 |
| 7 | 主板与固件 | 主板品牌/型号、BIOS/UEFI 厂商/版本/日期 | 品牌机随整机；自组装单独获取 |
| 8 | 网络 | 有线网（网口数量/速率）、无线网（Wi-Fi 规格）、MAC、管理 URL | 品牌机随整机；自组装按网卡型号获取+手动补 |
| 9 | 接口与扩展 | USB 数量与版本、视频输出、音频输出、蓝牙、PCIe 槽 | 品牌机随整机；自组装从主板/机箱推导+手动补 |
| 10 | 电源与散热 | 供电方式、输入电源、适配器功率、散热系统 | 同上 |
| 11 | 系统 | 操作系统（UNRAID/fnOS/PVE/Windows…）与版本 | 系统手动选 |
| 12 | 外部连接 | 由「网络」与「接口与扩展」推导的连接表：网络对端连接（上联/下联设备）、蓝牙设备、音频设备、USB 外设、电源连接 | 品牌机随整机；自组装按外设型号获取+手动补 |

附加：**购买与保修**（价格、渠道、购买日期、保修到期）——与现有购买信息打通。

**显示固化（2026-10-17 用户定稿，2026-10-18 收敛为 11 类）**：计算设备（台式机 / NAS / 服务器 / 迷你主机）固定以下 **11 类**常驻显示——**物理规格 / 处理器(CPU) / 图形核心(GPU/核显) / 内存 / 存储支持 / 网络连接 / 显示输出 / 接口与扩展 / 电源与功耗 / 散热设计 / 系统与软件**；即使某分类参数被全部删除，分组卡片也不消失（保留「编辑」入口补参数，卡片内显示「暂无参数」），确保结构稳定、入口不丢。映射规则：「基本信息」为左侧独立卡片；「主板与固件」并入系统与软件；「显示输出」从接口与扩展拆出；散热设计独立成组（不再并入电源）；其余分类（显示 / 影像 / 音频 / 传感器等）仍仅在有参数时显示；「特色功能」分组已按用户要求移除。Agent 粘贴格式固定为**一行一个参数（参数名 + Tab + 值）**。

**品牌机整包获取**：填厂商+机器型号 → AI 获取整包规格 → 候选确认层 → 逐条勾选写入对应组。拿不到的组保持空白，后续按组单独填写/获取（准系统后装内存硬盘等场景）。

## 三、参数写入规则（所有获取统一）

- 获取结果 → **候选展示**（每组内：候选值与当前值对照、逐条勾选）→ **勾选确认才写入**
- 手动直接填写 = 已确认，直接生效
- 与添加资产流程的"逐条勾选、勾选即所见"同一原则，扩展到编辑页全部参数组

## 四、自组装配件清单

- 配件**不是独立资产**，是整机资产下的清单（`asset_components`：分类、品牌、型号、规格、序列号、购买信息、备注）
- 分类固定：CPU / 主板 / 内存（多条）/ 存储（多块）/ 显卡 / 电源 / 机箱 / 散热器 / 网卡 / 其他
- 配件参数获取：按"品牌+型号"逐件获取；二期支持**粘贴配置单文本**自动拆件
- Agent 实机数据（监控侧）与配件清单对照（清单 32G vs 实机识别 32G ✓）——实机运行数据在监控模块展示，不进资产参数

## 五、图片

- 品牌整机：按机器型号获取官方整机图，封面默认官方图
- 自组装：按**机箱/外观关键词**获取机箱图；全部图片支持手动上传
- 图库增加**相册分组**（整机 / CPU / 主板 / 内存 / 存储…），配件图自动归组

## 六、维护模型（按对象分层）

- 维护记录新增**关联对象**：整机 或 某硬件组/配件
- 品牌整机：默认整机级（送修、整机保养）；也可挂到组（如"硬盘更换"）
- 自组装：默认组级（内存条更换、CPU 散热器清灰、加装盘位）
- 维护列表支持按对象过滤/分组显示；每个硬件组的卡片头部可直达"本组维护记录"

## 七、页面布局（统一骨架内）

- **详情页**：骨架不变（左：图片/档案/维护与附件；中：网络详情卡 + 硬件参数卡）。
- **连接展示**：网络连接（连接了什么网络设备）与其他连接（蓝牙/音频/USB/电源等外设）**各自成表**，样式与网口状态表同款；编辑页同构，两组都有「编辑连接」入口。
  - 品牌整机：硬件参数卡 = 9 组分节（横向格子 + 编辑）
  - 自组装：硬件参数卡 = 配件清单表（分类|品牌|型号|规格）+ 组级摘要格子
- **编辑页**：档案弹窗按 build_mode 出字段；自组装多一张配件清单卡（配件编辑弹窗，规格字段按配件分类动态出）；每组「获取」「编辑」入口如前述
- 网络详情卡（网口状态/其他连接）与参数卡的既有结构不变

## 八、实施顺序

1. `build_mode` 字段 + 添加流程必选分流 + 资产标签
2. 9 组固定分组重构（替换现有混合分组，字段从头梳理入 registry）
3. 获取候选确认层（获取 → 勾选 → 写入组件，添加流程与编辑页共用）
4. 自组装配件清单（数据 collection + 编辑页卡 + 详情页表 + 配件编辑弹窗）
5. 维护关联对象（维护记录加对象字段 + 列表分组过滤）
6. 图片相册分组（自组装配件图归组）

## 九、迁移

现有计算设备资产默认 `build_mode=brand`，数据不动；单台转自组装时一键将现有 CPU/内存/存储等字段迁为清单条目。
